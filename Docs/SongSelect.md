# Penpot 곡 선택 화면

수정 진입점: `Client/GameScene/MusicSelectScene/Submodules`.
배치는 SongSelectLayout/패널은 SongSelectPanels/카드는 SongSelectCards,
선택 정책은 SongSelectionState, 미리듣기는 SongPreviewController를 읽습니다.
MusicSelectScene은 View와 상태·오디오를 조립하고 View의 전환 의도를 처리합니다.

`MusicSelectScene`은 Penpot `Music Select · Sky` 페이지의
`곡 선택 화면 · Song List Focus · 1920×1080` 보드를 기준으로 구성한다.
1920×1080 좌표에 `2/3`을 적용한 1280×720 `FixedHeight` Canvas를 사용한다.
Canvas의 논리 높이는 720으로 유지하되 창 화면비에 따라 논리 폭과 보드 폭을
갱신하므로, 세로 해상도가 달라져도 UI 비율이 유지되고 가로 여백은 실제 창 폭을
모두 사용한다.

배경·주요 패널·버튼·가상 곡 카드의 이미지는 선택 스킨의 `[MusicSelect]`에서 지정할 수 있습니다.
INI가 비어 있으면 기존 색상 디자인을 사용합니다. 문구·곡 정보·선택/입력·배치는 유지합니다.
폴더와 상태별 이미지 계약은 [skin.ini](BuiltInAssets.md#skinini와-씬별-이미지)에 있습니다.

## 배치

- 화면은 기록·곡 정보·곡 목록의 3열이며 폭 비율은 약 2:3:2다.
- 별도 헤더는 없다. `ALL` 카테고리 바가 왼쪽과 가운데 열 위를 덮는다.
- 왼쪽은 `PERSONAL RECORD` 선택기와 실제 기록이 없을 때의
  `NO RECORDS`만 표시한다.
- 가운데는 정사각형 배경 미리보기, 곡명·아티스트와 선택한 패턴의
  이름·제작자·BPM·노트 수·모드·JudgeLevel·BPM 범위·곡 길이를 표시한다.
  BPM 범위는 유효한 타이밍 구간에서 계산해 목록 캐시에 보관한다. 곡 길이는
  선택 곡의 비동기 미리듣기 음원이 준비되면 표시하며 읽을 수 없으면 `—`다.
  선택한 YMP의 `BG:`를 현재
  Songs/BG에서 읽고 원본 비율을 유지해 가운데를 잘라 채운다.
  선택 경로가 바뀔 때만 등록하며 엔진의 기존 이미지 경로 캐시를 재사용한다.
  패턴 변경 시 이미지를 교체하며, 미지정·읽기 실패·선택 없음은 `NO IMAGE`다.
  YMP의 `offset:`은 플레이 화면 배치에 적용하며 이 정사각형 미리보기는 이미지 중앙을 보여준다.
  LEVEL은 현재 YMP 필드가 없어 `—`로 표시한다.
- 오른쪽 검색창과 정렬 선택기는 곡 목록 viewport와 같은 폭이고 패널에서
  14px 안쪽에 놓인다. 목록은 부모 clip rect로 실제 표시 영역 밖의 카드와
  글자를 자르고 scrollbar로 현재 위치를 표시한다.
- 곡명과 선택 곡의 아티스트가 실제 측정 폭으로 영역을 넘으면 1초 정지 후 픽셀 단위로
  이동한다. 원본 Unicode 문자열/배치를 유지하고 같은 배치의 두 번째 사본과 고정 clip으로
  순환하므로 문자열을 잘라 레이아웃을 계속 만들거나 이모지 surrogate를 분리하지 않는다.
  영역에 들어오는 문구는 정지하며 resize 후 측정된 폭을 다시 사용한다.
- 하단에는 `BACK`, `OPTION SELECT`, `GO`를 둔다. `BACK`과 `GO`는 Penpot처럼
  화면 좌우 및 아래쪽 경계에 일부가 걸친다.

## 화면비 대응

- 기록 패널과 상단 카테고리는 좌측 여백을 기준으로, 곡 목록 패널은 우측
  여백을 기준으로 정렬한다.
- 가운데 곡 정보 패널은 좌우 패널 사이의 남은 폭을 사용한다. 16:9보다 넓은
  화면에서는 좌우 패널 폭을 유지하고 이 영역만 늘어난다.
- 좁은 화면에서는 세 열과 간격을 함께 축소해 겹치거나 화면 밖으로 나가지
  않게 한다. 곡 정보 폭이 부족하면 배경 미리보기만 숨기고 실제 곡·난이도
  정보 영역을 우선한다.
- `OPTION SELECT`는 화면 하단 중앙을 유지한다. `BACK`과 `GO`는 각각 좌우
  가장자리를 기준으로 배치하며, 좁은 화면에서는 세 버튼이 겹치지 않도록
  가로 폭만 줄인다.
- 패널 내부의 선택기, 검색창, 곡 viewport, scrollbar, 카드와 정보 열도 새
  패널 폭에 맞춰 다시 계산한다. resize 뒤 hit-test와 목록 scroll 위치도 함께
  갱신한다.

## 곡과 난이도 포커스

곡과 패턴을 별도 패널로 나누지 않는다. 포커스된 곡 카드 하나만 높이가
늘어나고 그 안에 해당 YMP 패턴 목록이 펼쳐진다. 다른 곡 카드는 실제 곡명과
아티스트만 표시한다.

- `←` / `→`: 이전·다음 곡으로 이동하고 그 곡의 첫 난이도에 포커스를 둔다.
- `↑` / `↓`: 펼쳐진 카드의 난이도 포커스를 이동한다.
- 마지막 난이도에서 `↓`: 다음 곡을 펼치고 첫 난이도에 포커스를 둔다.
- 첫 난이도에서 `↑`: 이전 곡을 펼치고 첫 난이도에 포커스를 둔다.
- `Enter` / `Space` 또는 `GO`: 곡과 난이도가 모두 유효할 때만 gameplay로 간다.
- 펼쳐진 난이도 상자 클릭: 해당 난이도를 선택하고 같은 검증/진입 경로로 바로 실행한다.
  곡 카드 클릭은 포커스만 바꾸며, 옵션 패널이 열려 있으면 뒤쪽 클릭은 차단한다.
- `Escape` 또는 `BACK`: Logo Scene으로 돌아간다.
- `OPTION SELECT` 또는 `Ctrl+O`: 왼쪽 옵션 패널을 열고 닫는다. 패널이 보이는
  동안 뒤쪽 곡·난이도·검색 입력은 멈춘다.

카드가 펼쳐지거나 접힌 뒤에는 scroll offset을 자동 보정해 포커스된 카드 전체가
viewport에 들어오게 한다. 패턴이 없는 음악도 실제 catalog 항목으로 표시하지만
`NO DIFFICULTIES` 상태에서는 `GO`가 동작하지 않는다.

## 검색과 정렬

검색창을 클릭하거나 `Ctrl+F`를 누르면 영문·숫자 검색을 입력할 수 있다.
곡명과 아티스트를 대소문자 구분 없이 필터링하며 Backspace로 지운다.

정렬 선택기는 `난이도순`, `곡 이름순`, `아티스트 이름순`을 제공한다. 현재
YMM/YMP에는 chart LEVEL이 없으므로 `난이도순`은 catalog 순서를 보존한다.
노트 수나 판정 범위를 난이도로 오인해 가짜 순위를 만들지 않는다.

옵션 패널의 한국어/영어 선택은 곡 목록의 고정 문구와 현재 표시 중인 오류
접두사를 즉시 갱신한다. 패널 크기·애니메이션·스크롤과 텍스트 표 구조는
[문구·언어·글꼴 관리](TextManagement.md)에 있다.

## 실행 데이터

행에는 `SongCatalog`가 읽은 실제 제목과 아티스트만 사용한다. `GO`는 선택한
`SongCatalogPattern`의 YMP/YME 경로, YMM이 가리키는 음악 경로와 mode를 기존
`GameplayLaunchStore::SetValidated`에 기록한 뒤 `DestroyOnExit` gameplay Scene으로 전환한다.
진입한 Scene은 `Snapshot()`으로 독립적인 `GameplayLaunchRequest` 사본을 받는다.
Catalog 탐색은 파일별 오류를 격리하므로 손상된 YMM/YMP/YME 또는 누락된 음원은
진단을 남기고 해당 항목만 제외한다. `GO` 직전에도 선택 패턴을 한 번 검증하며,
실패하면 Scene을 전환하지 않고 상세 영역에 오류를 표시한다. 성공하면 검증한
PlaySession의 소유권을 gameplay controller로 한 번 넘겨 같은 파일을 다시 읽지 않는다.
첫 진입의 Initialize에서 카탈로그 worker를 시작하고 재진입에서도 외부 편집을 반영한다.
SongCatalogLoader는 복사한 경로와 파서 캐시만 worker에 넘기며 Scene/엔진 pointer를
참조하지 않는다. Scene은 완료 결과만 적용하고 첫 로딩 중에는 로딩 문구를 표시한다.
런타임은 `SongCatalog::MetadataIndex`로 목록용 문서와 노트 수·진단만 보관하며,
수정 시각/크기가 같은 문서는 사용자 캐시 폴더의 디스크 인덱스에서도 재사용한다.
추가/삭제 파일과 음원·YME 의존성은 매 갱신에서 확인한다. 포맷 변경 시 캐시 무효화
규칙과 소유권은 [자원 로딩](ResourceLoading.md)에 있다.
GO의 검증·세션 생성도 `PlaySessionLoader` worker에서 실행하고 완료 결과만 게시한다.
대기 중 다른 패턴으로 이동하거나 화면에서 나가면 이전 진입 결과는 적용하지 않는다.
MusicSelectView는 행 배치 metadata와 실제 카드를 구분하여 viewport 인근 행만 만든다.
포커스/검색/정렬/스크롤/resize는 기존 조작 규칙을 유지한다.
미리듣기는 엔진의 StreamAsync로 열고 준비가 끝난 다음 기존 200ms fade로 재생한다.
선택이 바뀌면 이전 로딩의 완료를 확인해 폐기하고 최신 선택을 시작한다. 로딩/정지 직후의
clip은 안전한 release 상태가 될 때까지 보관한다. 실패 파일은 매 Update 재시도하지 않고
다른 선택이나 Scene 재진입에서 다시 시도한다.
