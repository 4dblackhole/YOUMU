# Penpot 곡 선택 화면

수정 진입점: `Client/GameScene/MusicSelectScene/Submodules`.
배치는 SongSelectLayout/패널은 SongSelectPanels/카드는 SongSelectCards,
선택 정책은 SongSelectionState, 미리듣기는 SongPreviewController를 읽습니다.
MusicSelectScene은 View와 상태·오디오를 조립하고 View의 전환 의도를 처리합니다.

노트 종류 비율 그래프와 NPS(초당 노트 수) 그래프는 사용자 지시로 폐기했습니다.
두 그래프 및 이를 위한 분석 버튼/패널은 선곡 화면의 구현 범위에서 제외합니다.

`MusicSelectScene`은 Penpot `Music Select · Sky` 페이지의
`곡 선택 화면 · Song List Focus · 1920×1080` 보드를 기준으로 구성한다.
1920×1080 좌표에 `2/3`을 적용한 1280×720 `FixedHeight` Canvas를 사용한다.
Canvas의 논리 높이는 720으로 유지하되 창 화면비에 따라 논리 폭과 보드 폭을
갱신하므로, 세로 해상도가 달라져도 UI 비율이 유지되고 가로 여백은 실제 창 폭을
모두 사용한다.

배경·주요 패널·버튼·가상 곡 카드의 이미지는 선택 스킨의 `[MusicSelect]`에서 지정할 수 있습니다.
INI가 비어 있으면 기존 색상 디자인을 사용합니다. 문구·곡 정보·선택/입력·배치는 유지합니다.
폴더와 상태별 이미지 계약은 [skin.ini](BuiltInAssets.md#skinini와-씬별-이미지)에 있습니다.

## 배치

- 화면은 기록·곡 정보·곡 목록의 3열이며 폭 비율은 약 2:3:2다.
- 별도 헤더는 없다. `ALL` 카테고리 바가 왼쪽과 가운데 열 위를 덮는다.
- 왼쪽 기존 기록 영역에 선택 패턴의 실제 로컬 기록을 최신순 여섯 개씩 표시한다.
  `PERSONAL RECORD` 선택기와 이전/다음 페이지를 유지하고 기록이 없으면 `NO RECORDS`를 표시한다.
  `Filter records`는 별도 기록 필터 패널을 열며 기록 영역 자체를 옮기거나 넓은 열람 창으로 바꾸지 않는다.
  선택형/직접 조건식의 결합과 적용·취소 계약은 [기록 필터](Gameplay/PlayOptions.md#조건식)를 따른다.
- 가운데는 정사각형 배경 미리보기, 곡명·아티스트와 선택한 패턴의
  이름·제작자·BPM·노트 수·모드·JudgeLevel·HP 난이도·BPM 범위·곡 길이를 표시한다.
  노트 수는 실제 기본 플레이 세션의 논리 노트 객체 수다. 롱노트의 머리·꼬리는 하나의
  논리 노트이며 틱/입력 개수와 구분한다. 집계할 수 없으면 `—`로 표시한다.
  노트 수 범위 필터에도 같은 값을 쓰며, 범위를 지정했을 때 집계 미상 패턴은 제외한다.
  HP 난이도는 JudgeLevel 바로 아래에서 선택한 패턴의 값을 소수 둘째 자리까지 표시한다.
  HP 미지정 채보는 기존 파서/모델의 기본값 `9.00`이며 패턴이 없으면 HP 정보를 비운다.
  네 정보 행이 들어가도록 패턴 정보 패널 높이를 조정하며 resize·언어 전환에도 함께 갱신한다.
  BPM 범위는 유효한 타이밍 구간에서 계산해 목록 캐시에 보관한다. 곡 길이는
  선택 곡의 비동기 미리듣기 음원이 준비되면 표시하며 읽을 수 없으면 `—`다.
  선택한 YMP의 `BG:`를 현재
  Songs/BG에서 읽고 원본 비율을 유지해 가운데를 잘라 채운다.
  같은 이미지를 선곡 화면 전체의 UI 뒤 배경에도 표시한다. 전체 배경은 화면비에 맞춰 채우고
  채보의 720 기준 `offset:`을 적용한다. 정사각형 미리보기와 전체 배경은 같은 캐시 이미지
  handle을 사용한다. 같은 BG에서 offset만 바뀌어도 배치를 갱신하고 화면 크기 변경에 대응한다.
  선택 경로가 바뀔 때만 등록하며 엔진의 기존 이미지 경로 캐시를 재사용한다.
  패턴 변경 시 이미지를 교체하며, 미지정·읽기 실패·선택 없음은 미리보기에 `NO IMAGE`를
  표시하고 전체 화면은 기존 스킨 배경으로 돌아간다. 이전 채보의 배경을 남기지 않는다.
  YMP의 `offset:`은 전체 배경에 적용하며 정사각형 미리보기는 이미지 중앙을 보여준다.
  LEVEL은 현재 YMP 필드가 없어 `—`로 표시한다.
- 오른쪽은 폴더 탭, 검색창, 정렬/필터 행, 곡 목록 순서이며 각 행은 패널에서
  14px 안쪽에 놓인다. 목록은 부모 clip rect로 실제 표시 영역 밖의 카드와
  글자를 자르고 scrollbar로 현재 위치를 표시한다.
- 사용자 지시에 따라 곡 목록 카드에는 BG 썸네일을 표시하지 않는다. 곡명·아티스트는 기존 카드
  폭을 사용하며 에디터의 추가 버튼 공간은 유지한다. 선택 채보의 전체 배경과 상세 미리보기는
  같은 기존 BG 참조/캐시를 사용한다. 곡 복귀 시 첫 표시 채보를 선택하는 기존 동작도 유지한다.
- 기록·곡 정보·곡 목록의 세 주요 패널 바탕은 불투명도 90%다. 에디터 선곡에서는 존재하는
  곡 정보·곡 목록 두 패널에 적용한다. 글자·버튼·카드·내부 정보 영역의 불투명도는 유지한다.
  부모 전체를 흐리게 하지 않고 패널 Sprite에만 적용하며, 내부가 빈 테두리 도형으로 BG를
  실제 10% 비춘다. 내부를 채우던 불투명한 테두리 사각형을 밑에 겹치지 않는다.
  스킨 패널 PNG도 기존 알파에 90%를 곱하며, 해당 스킨 이미지가 있으면 기본 테두리를 숨긴다.
  기본 바탕은 내장 `MusicSelect/PanelFill.png`의 흰 픽셀을 색상으로 곱해 기존 알파 블렌딩 이미지
  재질로 그린다. 일반 화면 사각형의 불투명 재질을 사용하지 않으며 새 스킨 키는 추가하지 않는다.
  resize와 스킨 변경/복귀에 같은 규칙을 적용하고 별도 불투명도 설정은 추가하지 않는다.
- 곡 목록과 상세의 곡명·아티스트, 상세의 제작자는 등록된 값을 파일 순서대로 한 줄씩 표시한다.
  빈 항목은 건너뛰고 값이 모두 없으면 기존 파일명/`—` 대체 표시를 사용한다.
  여러 줄을 볼 수 있도록 해당 칸과 곡 카드의 높이를 늘리며 각 칸 안에서만 내용을 자른다.
  내용이 넘치면 세로/가로 스크롤바를 표시한다. 휠은 세로, Shift+휠은 가로로 이동하며
  세로 넘침이 없는 긴 한 줄에서는 일반 휠도 가로로 이동한다. 스크롤바 드래그도 지원한다.
  넘치는 칸 위의 휠은 끝에 도달해도 바깥 곡 목록을 움직이지 않는다. 일반 글자 클릭은 기존
  곡 카드 선택을 유지하고 스크롤바 조작은 곡 선택을 실행하지 않는다.
  문자열을 자르지 않고 전체 Unicode 배치의 픽셀 위치를 이동하므로 서로게이트 쌍을 보존한다.
  내용 변경 시 처음으로 돌아가며 resize 후 실제 측정값으로 범위와 위치를 다시 제한한다.
  정렬과 플레이 진입용 대표 표기, 검색 범위, YMM/YMP 저장 형식은 유지한다.
- 하단에는 `BACK`, `OPTION SELECT`, `GO`를 둔다. `BACK`과 `GO`는 Penpot처럼
  화면 좌우 및 아래쪽 경계에 일부가 걸친다.

## 화면비 대응

- 기록 패널과 상단 카테고리는 좌측 여백을 기준으로, 곡 목록 패널은 우측
  여백을 기준으로 정렬한다.
- 가운데 곡 정보 패널은 좌우 패널 사이의 남은 폭을 사용한다. 16:9보다 넓은
  화면에서는 좌우 패널 폭을 유지하고 이 영역만 늘어난다.
- 좁은 화면에서는 세 열과 간격을 함께 축소해 겹치거나 화면 밖으로 나가지
  않게 한다. 곡 정보 폭이 부족하면 배경 미리보기만 숨기고 실제 곡·난이도
  정보 영역을 우선한다.
- `OPTION SELECT`는 화면 하단 중앙을 유지한다. `BACK`과 `GO`는 각각 좌우
  가장자리를 기준으로 배치하며, 좁은 화면에서는 세 버튼이 겹치지 않도록
  가로 폭만 줄인다.
- 패널 내부의 선택기, 검색창, 곡 viewport, scrollbar, 카드와 정보 열도 새
  패널 폭에 맞춰 다시 계산한다. resize 뒤 hit-test와 목록 scroll 위치도 함께
  갱신한다.

## 곡과 난이도 포커스

곡과 패턴을 별도 패널로 나누지 않는다. 포커스된 곡 카드 하나만 높이가
늘어나고 그 안에 해당 YMP 패턴 목록이 펼쳐진다. 다른 곡 카드는 실제 곡명과
아티스트만 표시한다.

- `←` / `→`: 이전·다음 곡으로 이동하고 그 곡의 첫 난이도에 포커스를 둔다.
- `↑` / `↓`: 펼쳐진 카드의 난이도 포커스를 이동한다.
- 마지막 난이도에서 `↓`: 다음 곡을 펼치고 첫 난이도에 포커스를 둔다.
- 첫 난이도에서 `↑`: 이전 곡을 펼치고 첫 난이도에 포커스를 둔다.
- `Enter` / `Space` 또는 `GO`: 곡과 난이도가 모두 유효할 때만 gameplay로 간다.
- 펼쳐진 난이도 상자 클릭: 해당 난이도를 선택하고 같은 검증/진입 경로로 바로 실행한다.
  곡 카드 클릭은 포커스만 바꾸며, 옵션 패널이 열려 있으면 뒤쪽 클릭은 차단한다.
- `Escape` 또는 `BACK`: Logo Scene으로 돌아간다.
- `OPTION SELECT` 또는 `Ctrl+O`: 왼쪽 옵션 패널을 열고 닫는다. 패널이 보이는
  동안 뒤쪽 곡·난이도·검색 입력은 멈춘다.

카드가 펼쳐지거나 접힌 뒤에는 scroll offset을 자동 보정해 포커스된 카드 전체가
viewport에 들어오게 한다. 패턴이 없는 음악도 실제 catalog 항목으로 표시하지만
`NO DIFFICULTIES` 상태에서는 `GO`가 동작하지 않는다.

## 검색과 정렬

검색창을 클릭하거나 `Ctrl+F`를 누르면 일반 텍스트를 입력할 수 있다. `Ctrl+F`는 기존 검색어를
전체 선택한다. Windows Unicode 편집기를 검색창 안에 배치하며 한글·일본어 IME 조합/후보창,
커서 이동·마우스 선택·Backspace/Delete·잘라내기/복사/붙여넣기를 표준 편집 동작으로 처리한다.
확정 문자열이 바뀌면 검색 결과를 갱신한다. 조합 중 Enter/Escape는 IME에 전달하고, 조합 밖에서는
검색 편집만 끝낸다. 검색창에 포커스가 있으면 방향키·공백·Enter/Escape로 곡 이동/플레이/뒤로 가기를
실행하지 않는다. Scene/옵션/추가 메뉴에 가려질 때 native 편집기도 숨기고 포커스를 해제한다.
편집기의 수명은 MusicSelectView가 소유하고 shutdown에서 창보다 먼저 해제한다.
창이 없는 표시 테스트에서는 Canvas 문구만 사용한다.
곡명의 모든 표기, 모든 아티스트 표기, YMM 곡 태그와 YMP 패턴 태그를 검색한다.
검색어는 공백으로 나누고 대소문자를 구분하지 않는 부분 일치를 AND로 결합한다.
`angel`만 입력해도 `Angel Dream`이 결과에 나온다. `angel dream`처럼 두 단어를 입력한 경우에는
`angel`과 `dream`이 모두 있어야 하며 순서는 상관없다. 두 단어가 제목과
아티스트 등 서로 다른 필드에 있어도 일치한다. 연속·앞뒤 공백은 무시하고 빈 검색어는 전체 목록이다.
IME의 전각 공백도 단어 구분으로 처리하며 Unicode 대소문자는 invariant lowercase로 비교한다.
텍스트 검색 결과의 단위는 곡이다. 패턴 태그로 곡이 일치해도 텍스트 검색 자체는 패턴 목록을 자르지 않는다.
검색 때는 로드된 목록 메타데이터만 사용하고 YMM/YMP 파일을 다시 읽지 않는다.

SceneStateTests는 단일 단어/부분 일치·AND·외국어/Unicode 대소문자 비교를 검사한다.
RunMusicSelectViewTests는 숨김 D3D12 창의 실제 편집기에 Unicode를 삽입하고 결과 갱신,
편집 키 차단·조합 명령 분리·옵션 숨김·handle 해제를 자동 검사한다.
자동 검사는 실제 키보드 IME 후보 선택이나 사용자 클립보드를 조작하는 수동 검증을 포함하지 않는다.

정렬 선택기는 `난이도순`, `곡 이름순`, `아티스트 이름순`, `Base BPM순`을 제공한다. 현재
클라이언트 계산 난이도가 미계산 상태이므로 `난이도순`은 catalog 순서를 보존한다.
노트 수나 판정 범위를 난이도로 오인해 가짜 순위를 만들지 않는다.
`Base BPM순`은 목록에 로드된 각 곡의 첫 패턴 `baseBpm`을 기준으로 숫자 오름차순 정렬한다.
다른 패턴의 BPM이나 변속 범위는 정렬 키로 사용하지 않는다. 같은 BPM은 기존 catalog 순서를
유지하며 패턴이 없거나 유효한 기본 BPM이 없으면 뒤에 둔다. 검색 결과에도 동일한 정렬을
적용하고 정렬/언어 변경 후에도 선택한 곡과 정렬 항목을 유지한다. YMP에서 BPM을 생략한 경우는
기존 파서 기본값을 따르며 정렬을 위한 파일 재읽기나 포맷 변경은 없다.
SceneStateTests와 RunMusicSelectViewTests가 숫자 순서·동률·첫 패턴 기준·검색 결합,
드롭다운의 실제 선택과 언어 전환을 검사한다.

정렬 옆 `필터` 버튼은 별도 모달 패널을 연다. 모드는 실제 catalog에 등록된 값 중 하나 또는
전체를 선택하고 노트 수·기본 BPM·JudgeLevel의 최소/최대 범위를 입력한다. BPM은 변속 범위가
아닌 패턴의 `baseBpm`이다. 빈 경계는 제한 없음이며 경곗값을 포함한다. 노트 수는 0 이상의
정수, BPM은 0 이상의 유한한 수, JudgeLevel 경계는 1–100이다. 최소가 최대보다 크거나 입력이
유효하지 않으면 오류를 표시하고 기존 적용 조건을 보존한다. 모든 조건은 같은 패턴에서 AND로
결합하며, 일치하는 패턴만 곡 카드에 표시하고 그런 패턴이 없는 곡은 제외한다. 텍스트 검색·정렬과
함께 적용하고 원본 catalog 및 플레이 진입용 패턴 인덱스는 유지한다.

`적용`/조합 밖 Enter는 조건을 확정한다. `초기화`는 편집 중인 조건만 비우며 적용해야 반영된다.
`닫기`/조합 밖 Escape/Scene 숨김은 편집을 취소한다. 패널이 열린 동안 뒤쪽 검색·목록·플레이·
옵션 단축키는 차단한다. 숫자 입력은 기존 Unicode 편집기를 사용하며 모드 드롭다운을 펼치면
겹치는 native 입력창을 숨긴다. 조건은 선곡 상태에만 보관하고 새 설정 파일은 만들지 않는다.

`SongCatalogPattern::calculatedDifficulty`는 향후 클라이언트 계산용 `optional<double>`이며
초기값은 미계산이다. YMP/YMM와 디스크 인덱스에는 저장하지 않고 난이도 알고리즘도 추가하지
않는다. 미계산은 0과 구별하고 현재 난이도 범위 입력은 비운 채 비활성화한다. 계산값이 제공되면
난이도 범위를 사용할 수 있고 해당 범위에서 미계산/비유한 값은 제외한다. 계산값의 척도는 미정이다.
SceneStateTests와 RunMusicSelectViewTests는 같은 패턴 AND, 실제 인덱스의 클릭/방향키 탐색,
범위 검증과 원자적 적용/취소, 실 native 입력의 IME 명령 분리·모달 격리·숨김/해제를 검사한다.

옵션 패널의 한국어/영어 선택은 곡 목록의 고정 문구와 현재 표시 중인 오류
접두사를 즉시 갱신한다. 패널 크기·애니메이션·스크롤과 텍스트 표 구조는
[문구·언어·글꼴 관리](TextManagement.md)에 있다.

## 패턴별 즐겨찾기 폴더

게임·에디터 선곡 화면의 곡 목록 맨 위에 `전체`와 사용자 폴더 탭을 표시한다. 탭이 넘치면
그 영역의 휠이나 아래 가로 스크롤바로 이동한다. 폴더를 선택하면 그 폴더에 등록된 패턴과
해당 곡만 보이며, 기존 텍스트 검색·숫자 필터와 AND로 결합한다. 빈 폴더는 빈 결과를 표시한다.
같은 패턴을 여러 폴더에 등록할 수 있고 원본 catalog 인덱스로 클릭·키보드 탐색·플레이를 유지한다.
즐겨찾기를 해제해도 다른 폴더의 소속에는 영향을 주지 않는다.

탭 옆 `즐겨찾기` 버튼은 선택한 곡/패턴과 폴더 목록이 있는 관리 패널을 연다. 왼쪽 체크 칸은
현재 패턴의 소속을 편집하고 폴더 이름 행은 이름 변경/삭제 대상을 선택한다. 생성·이름 변경은
기존 Unicode 이름 입력 대화상자를 사용한다. 이름의 앞뒤 공백을 정리하고 빈 이름·제어문자는
허용하지 않는다(제어문자는 ASCII C0 범위). 여러 폴더는 목록의 휠·위/아래 버튼으로 탐색한다. 선택 패턴이 없으면 소속
편집만 비활성화하고 폴더 관리는 계속 제공한다.

생성·이름 변경·삭제·소속 변경은 모두 편집 중인 사본에 적용한다. `적용`/Enter로 함께 저장하고
`닫기`/Escape/Scene 숨김으로 전체 편집을 취소한다. 이름 대화상자의 확인/취소 키는 바깥 패널의
적용/닫기나 플레이 명령으로 재해석하지 않는다. 폴더 삭제는 그 폴더와 소속 정보만 제거한다.
활성 폴더가 삭제되면 `전체`로 돌아간다. 관리 패널은 배경 탐색·플레이·옵션 단축키를 차단하고
native 검색 입력도 숨긴다.

설정은 `Option.ini` 옆의 별도 UTF-8 `favorites.json`에 저장한다. 두 선곡 Scene은 진입할 때
다시 읽어 같은 사용자 설정을 공유하며, 탭 선택 자체는 각 Scene 상태에 둔다. 파일이 없으면
빈 설정으로 시작하고 적용 시 처음 저장한다. 읽기에 실패하면 마지막 정상 메모리 값을 보존하고
관리 패널에 오류를 표시하며 원본 파일을 덮어쓰지 않는다. 파일을 수정한 뒤 선곡 화면에 재진입하면
다시 읽는다. 저장 실패도 기존 파일과 적용 중인 메모리 상태를 보존한다.

파일의 `version`은 1, `nextId`는 다음 폴더 ID, `folders`는 생성 순서의 폴더 배열이다. 각 폴더는
양의 고유 `id`, Unicode `name`, 패턴 경로 키의 배열 `patterns`를 갖는다. 이름 변경과 삭제로
다른 폴더의 ID가 바뀌지 않으며 삭제한 ID는 재사용하지 않는다. 경로 키는 파일을 읽지 않고
절대 경로를 어휘적으로 정리한 뒤 Windows invariant lowercase와 `/` 구분자로 UTF-8 변환한다.
차트의 실제 파일 경로가 소속의 기준이므로 파일을 옮기면 새 경로로 등록해야 한다. 일시적으로
없어진 패턴의 소속은 자동으로 지우지 않는다. YMP/YMM와 목록 디스크 인덱스는 변경하지 않는다.

`SongFavorites`는 사용자 설정과 원자적 파일 교체, `SongFavoritesValues`는 편집 사본,
`SongFavoritesJson`은 고정 스키마 JSON 경계를 소유한다. `SongFavoriteTabs`는 가로 탭과 스크롤,
`SongFavoritesPanel`은 관리 편집을 소유하고 `SongSelectionState`는 기존 필터에 폴더 소속을 결합한다.
회귀는 TestSongFavoritesPersistence/Selection과 RunMusicSelectViewTests가 저장·복원·손상 파일·
저장 실패·원본 보존, 복수 소속·원본 인덱스, 실제 이름 입력과 관리/탭/모달 동작을 검사한다.

## 실행 데이터

행에는 `SongCatalog`가 읽은 실제 제목과 아티스트만 사용한다. `GO`는 선택한
`SongCatalogPattern`의 YMP/YME 경로, YMM이 가리키는 음악 경로와 mode를 기존
`GameplayLaunchStore::SetValidated`에 기록한 뒤 `DestroyOnExit` gameplay Scene으로 전환한다.
진입한 Scene은 `Snapshot()`으로 독립적인 `GameplayLaunchRequest` 사본을 받는다.
Catalog 탐색은 파일별 오류를 격리하므로 손상된 YMM/YMP/YME 또는 누락된 음원은
진단을 남기고 해당 항목만 제외한다. `GO` 직전에도 선택 패턴을 한 번 검증하며,
실패하면 Scene을 전환하지 않고 상세 영역에 오류를 표시한다. 성공하면 검증한
PlaySession의 소유권을 gameplay controller로 한 번 넘겨 같은 파일을 다시 읽지 않는다.
첫 진입의 Initialize에서 카탈로그 worker를 시작하고 재진입에서도 외부 편집을 반영한다.
SongCatalogLoader는 복사한 경로와 파서 캐시만 worker에 넘기며 Scene/엔진 pointer를
참조하지 않는다. 검증이 끝난 곡 메타데이터와 패턴을 탐색 중 바로 추가하고 첫 로딩 전용 문구를
두지 않는다(LOAD-01). 첫 탐색 중 곡이 아직 없거나 패턴이 추가되지 않은 곡은 `NO DIFFICULTIES`로
표시한다. 읽힌 패턴은 전체 탐색 중에도 선택하고 플레이/편집기에 진입할 수 있다. 카탈로그
탐색은 KeepAlive Scene에서 계속되며 같은 루트의 진행 중 작업은 재진입 때 유지한다.
새 난이도 생성·가져오기는 전체 탐색 완료 후에 허용한다. 부분/최종 목록이 바뀌어도 선택한
곡·패턴의 경로와 검색·필터를 유지하며 루트가 바뀌면 이전 세대의 결과를 버린다.
런타임은 `SongCatalog::MetadataIndex`로 목록용 문서와 노트 수·진단만 보관하며,
수정 시각/크기가 같은 문서는 사용자 캐시 폴더의 디스크 인덱스에서도 재사용한다.
추가/삭제 파일과 음원·YME 의존성은 매 갱신에서 확인한다. 포맷 변경 시 캐시 무효화
규칙과 소유권은 [자원 로딩](ResourceLoading.md)에 있다.
GO의 검증·세션 생성도 `PlaySessionLoader` worker에서 실행하고 완료 결과만 게시한다.
대기 중 다른 패턴으로 이동하거나 화면에서 나가면 이전 진입 결과는 적용하지 않는다.
MusicSelectView는 행 배치 metadata와 실제 카드를 구분하여 viewport 인근 행만 만든다.
포커스/검색/정렬/스크롤/resize는 기존 조작 규칙을 유지한다.
미리듣기는 엔진의 StreamAsync로 열고 준비가 끝난 다음 기존 200ms fade로 재생한다.
선택이 바뀌면 이전 로딩의 완료를 확인해 폐기하고 최신 선택을 시작한다. 로딩/정지 직후의
clip은 안전한 release 상태가 될 때까지 보관한다. 실패 파일은 매 Update 재시도하지 않고
다른 선택이나 Scene 재진입에서 다시 시도한다.
