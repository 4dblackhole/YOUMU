# 차트 에디터

## 선택·복사·붙여넣기·편집 기록

- Q 선택 도구에서 악보/실시간 뷰의 박자 구간을 드래그합니다. 선택 구간의 빈 앞뒤 간격도
  보관하며, 롱노트가 걸치면 시작·끝을 함께 선택하고 복사합니다. 우측 속성 편집은 기존 단일
  노트 선택을 유지합니다. 다중 선택은 노트 종류를 강제로 하나로 바꾸지 않습니다.
- 박자표·이펙트 탭은 클릭으로 한 행, Ctrl+클릭으로 개별 추가/해제, Shift+클릭으로 연속 행을
  선택합니다. Ctrl+C로 현재 탭의 선택을 복사합니다. 다른 탭 종류로 붙여넣지는 않습니다.
- Ctrl+V/붙여넣기는 실제로 겹치는 항목만 교체하고 복사본의 빈 구간에 있는 기존 노트는
  보존합니다. Ctrl+Shift+V/공백 포함 붙여넣기는 복사 구간 전체를 지운 뒤 붙여넣습니다.
  목적지는 현재 재생 위치의 가장 가까운 디바이더 눈금입니다. 전체 묶음은 한 번에 적용됩니다.
  겹친 롱노트·영역 효과는 하나의 연결된 객체로 교체하며 Undo로 전체가 복원됩니다.
- 음악적 간격은 `MusicalTimeline::WholeNotesBetween`/`AddWholeNotes`의 정확한 유리수와
  마디 prefix sum으로 계산합니다. BPM/delay는 최종 us 변환에만 적용하며 복사 당시의
  상대 박자 간격은 이후 원본 타이밍 수정에도 유지합니다. 마디 길이 변경은 마디 시작에만
  붙여넣을 수 있고, 형식 검증 실패는 묶음 전체와 기록을 보존하며 오류로 표시합니다.
- Delete는 현재 탭의 선택 항목을 묶어서 지웁니다. Ctrl+Z는 Undo,
  Ctrl+Y/Ctrl+Shift+Z는 Redo입니다. 편집 메뉴에서도 같은 명령을 실행합니다.
  노트·BPM·마디 길이·효과·메타데이터의 최근 32동작을 기록합니다. Undo 후 새 편집은
  Redo 분기를 버리며 저장 시점으로 돌아오면 Dirty가 해제됩니다. 선택/재생/스크롤은 기록하지 않습니다.
  첫 저장이 자동 확정한 YME 참조도 이력에 반영하므로 메타데이터 Undo/Redo로 이 경로가
  사라지지 않습니다. 저장 실패 시에는 문서와 이력을 그대로 보존합니다.
  저장 전에 YMP·YME·각 `.editor.tmp`/`.editor.bak`의 여섯 경로가 모두 다른지
  검사합니다. Windows 대소문자·상대경로 정규화·기존 hardlink 별칭도 거부하며,
  이 검사를 통과하기 전에는 디렉터리 생성이나 원본/복구 파일 변경을 하지 않습니다.

Workspace는 선택·읽기 전용 복사본·공통 명령 연결을, 모드는 화면 좌표→박자/드래그를 소유합니다.
`IEditorDocument`의 Undo/Redo 계약을 현재 `ChartEditor`가 구현합니다. 원본 트리는 유지하고
기록에는 변경된 노트와 바뀐 타이밍/효과/메타데이터만 보관합니다. 노트만 되돌릴 때는 해당
트리/구간 인덱스만 갱신하고, 시간·자동화가 바뀐 동작은 관련 컴파일 결과도 다시 만듭니다.

메타데이터 탭에서 BG 경로와 `offset: x, y`를 수정할 수 있습니다. BG는 진입 시 복사한 Songs
루트의 BG 폴더를 사용하며 YMM 음악 경로와 함께 다른 폴더 설정으로 중간에 바뀌지 않습니다.

타이틀 → Editor → 곡/난이도 선택으로 진입합니다. 새 난이도는 [곡 카드의 +](EditorSongSelect.md#새-난이도-생성)로 만듭니다. Penpot `Editor UI`의 Pattern,
Realtime View, Time Signature, Metadata, Effects 보드를 기준으로 구성했습니다.
일반 실행은 여전히 로고 화면에서 시작합니다.

진입 시 선택한 글로벌 오프셋(ms)은 플레이와 동일한 MusicalTimeline의 실행용 시간에
적용합니다. 노트·틱·마디선·효과 표시/히트사운드 예측은 같은 좌표를 사용하며,
저장 원본과 문서의 Dirty 상태는 바꾸지 않습니다. 문서 복사·교체·타이밍 수정에도 유지합니다.

수정 시 `Client/EditorScene/EditorScene.*`는 조립 흐름만 확인합니다.
`Submodules/EditorWorkspace`는 문서와 모드의 수명 및 공통 편집 상태를,
`EditorView`와 각 `Editor*View.cpp`는 공통 탭/타임라인/분석 화면을 맡습니다.
`EditorInput`은 공통 입력을 연결하고 모드별 좌표 해석은 모드 객체에 위임합니다.
`EditorMenuBar`는 에디터 전용 Canvas 상단 메뉴와 열림/강조 상태를 맡고,
저장·편집·폴더 열기 의도를 View로 반환합니다. 문서·모드·Scene을 참조하지 않습니다.
`EditorAnalysisController`는 worker와 marker 캐시를 맡습니다.
`EditorMetronome`은 문서 revision/음원 길이별 박자 눈금과 재생 전용 클릭 cue를 캐시합니다.
`EditorPlayback`은 에디터 전용 Voice/Clip과 DSP 기준 재생 시각을 소유합니다.
모드가 제공하는 파일/예상 cue만 소비하며 문서·화면·노트 규칙은 참조하지 않습니다.
PCM/FFT 자체는 `YOUMU.Editor/Audio/EditorAudioAnalysis`만 읽으면 됩니다.
문법 변경이 없으면 다른 형식 문서와 엔진 내부를 읽을 필요가 없습니다.

화면 구간의 롱노트는 ChartEditor의 시간/마디 구간 인덱스로 조회합니다. 양 끝점이
화면 밖이어도 몸체가 보이면 포함합니다. 노트·BPM·delay·효과 원본 트리와 안정 ID는
그대로 유지하고 문서 revision 변경 뒤 첫 조회에서 불변 projection을 갱신합니다.
오디오 탭은 128열 시간 타일의 집계와 FFT geometry를 캐시합니다. 재생/seek에서 기존
타일 위치를 옮기고 새로 보이는 타일만 만들며, 줌·분석·주파수·문서 변경은 캐시를
무효화합니다. ruler/cursor와 waveform min/max는 현재 시간으로 갱신합니다.

## 조작

- 진입 시 Q 선택 도구가 활성화됩니다. 아이콘은 커서와 지우개를 함께 그린
  `Editor/SelectionTool.png`입니다. Q는 미완성 롱노트 배치를 취소하고 선택 도구로 전환합니다.
- 노트 도구는 W 동/캇, E 큰 동/큰 캇/보라, R 롤/큰 롤, T 틱롤/큰 틱롤,
  Y 풍선/뎅뎅, U 동 버즈/캇 버즈의 여섯 묶음입니다. 이미 선택된 버튼이나 단축키를
  다시 누르면 같은 묶음의 다음 노트로 순환합니다. 다른 묶음으로 돌아오면 이전 변형을
  기억합니다. 우클릭 팝업도 해당 묶음의 변형만 표시합니다.
- 서클/overlay와 풍선/뎅뎅은 현재 선택된 스킨의 InGame PNG를 사용하며 누락 파일은
  기존 내장 기본본으로 대체합니다. 악보/실시간 뷰에서 큰 롤·큰 틱롤을 큰 헤드로 그리고,
  롱노트 헤드에 종류와 요구 연타 수 또는 틱 간격을 표시합니다. 스킨 경로는 선택 revision별로 캐시하여 화면 재구축마다 파일을 탐색하지 않습니다.
  틱 간격은 4분음표를
  한 박자로 표시하며, 파일의 TickDivision은 온음표 분할입니다(16 → 1/4박).
- 선택 도구로 노트 헤드·끝점·몸통을 클릭하면 우측 노트 정보 영역에서 종류와 연타 수/틱 분할,
  히트사운드 ID와 시작·끝의 마디/박자를 수정하고 적용/초안 취소를 선택합니다. 끝점 선택도
  같은 시작 노트를 편집합니다. 마디 번호는 1부터, 박자는 YMP와 같은 온음표 기준 N/D입니다.
  컴파일된 ms는 읽기 전용입니다. 종류 변경은 위의 여섯 도구 묶음 안에서만 순환합니다.
  예를 들어 큰 캇은 큰 동/보라로만 바꿀 수 있으며 롱노트의 연결된 끝점 ID도 유지합니다.
  다른 묶음으로 바꾸려는 초안, 범위 밖 위치, 박자값 기준의 역전/동일
  끝점, 다른 노트와의 금지된 겹침은 원본과 revision을 보존하며 거부합니다.
- 악보 또는 실시간 레인 좌클릭으로 추가, 노트 우클릭으로 삭제합니다. 롱노트는 두 번
  클릭합니다. 도구를 바꾸거나 Escape를 누르면 미완성 배치를 취소합니다.
  Taiko에서는 롱노트끼리 겹치거나 일반 노트가 롱노트 안에 들어가는 배치를 거부합니다.
  두 번째 끝점 검증이 실패하면 문서/revision을 보존하고 미완성 시작점을 유지합니다.
  이 제한은 Taiko 모드의 정책이며 공통 문서 adapter에 강제하지 않습니다.
- 선택 도구로 빈 그리드를 클릭하면 선택을 해제하고 현재 시간을 변경합니다. 악보 뷰의 휠은 마디를,
  실시간/오디오 뷰의 휠은 현재 디바이더의 한 눈금씩 재생 위치를 이동합니다.
  Space 재생/일시정지와 휠 입력은 EditorView의 공통 이동 함수가 처리합니다. 좌우키는 1ms 이동합니다.
- 악보 화면의 박자 디바이더는 4분음표를 기준으로 나눕니다. 1/2는 8분음표,
  1/4는 16분음표이며 기본값은 1/4입니다. 슬라이더로 1/1부터 1/16까지
  정수 분모 눈금을 선택하고, 1/17부터 1/1024까지는 직접 입력합니다.
  YMP에 저장되는 노트 위치의 분수는 그대로 온음표 기준입니다.
- 실시간 뷰는 오디오 영역의 현재 시간(ms)을 판정선 위치로 사용합니다. 차트 offset과
  delay를 포함한 노트의 컴파일 시각 차이로 간격을 계산합니다. 이동 속도는
  Base BPM으로 고정하며, Base BPM에서 16분음표 간격은 일반 노트 지름의 85%입니다.
  YME의 Whole 누적 거리와 Separate 노트/head 배율을 플레이와 같은 계산으로 반영합니다.
  노트 조회 범위는 실제 컴파일된 Separate 배율의 최소값을 균형 트리로 관리하며
  추가/삭제·BPM/효과 수정과 함께 갱신합니다. 사용자 식의 끝값만으로 내부 최소값을
  가정하지 않습니다. 이런 식을 쓰는 그리드는 기존 최대 33마디(앞 1마디 포함)/마디당 4096개 범위에서
  실제 화면 X좌표로 검사하므로 느린 노트와 노트가 없는 스냅 위치도 누락하지 않습니다.
  실시간 마디선은 5px, 틱은 2px이며 화면 배율을 반영합니다. 축약된 박자 위치에 따라
  4분 흰색, 8분 빨강, 16분 파랑, 32분 노랑, 64분 회색, 12분 초록, 24분 보라,
  나머지는 주황색입니다. 같은 위치는 더 큰 음표 간격의 색을 우선합니다.
  입력 검사도 그리기와 같은 레인 사각형을 사용하며 레인 밖 클릭은 추가·삭제하지 않습니다.
  실시간 뷰의 −/+ 버튼은 레인 크기와 서클 크기를 유지하고 시간축 배율만
  25/50/100/200/400%로 바꿉니다. 기본은 100%이며 그리드·스냅·노트/마디선에 같은 배율을 씁니다.
- Space는 현재 시간에서 음악과 예상 히트사운드를 재생하거나 일시정지합니다.
  모든 탭에서 동작하며 Ctrl/Alt 조합과 열린 파일 메뉴에서는 실행하지 않습니다.
  재생 중 Seek도 재생 상태를 유지합니다. Z는 첫 노트, 연속으로 다시 누르면 0ms,
  다음 Z는 다시 첫 노트로 이동합니다. X는 마지막 노트(롱노트 테일 포함), 다음 X는
  음원 끝, 그다음 X는 다시 마지막 노트로 이동합니다. Z/X를 바꿔 누르거나 다른 수동
  Seek/Space를 사용하면 두 순서를 초기화합니다. 음원 끝은 현재 파일의 분석 결과를
  사용하며 분석이 준비되지 않았으면 현재 시간을 유지하고 상태 메시지를 표시합니다.
  분석이 끝나면 X를 다시 눌러 음원 끝 이동을 재시도할 수 있습니다.
  음원 끝과 마지막 노트 테일 중 더 늦은 시각까지 재생합니다.
- 패턴 탭의 기존 오디오 분석 영역은 긴 타임라인 슬라이더입니다. 트랙을 클릭하거나
  손잡이를 드래그해 현재 편집 시각을 ms 단위로 바꾸며 실시간 뷰와 공유합니다.
  범위는 음원 전체 길이와 차트 노트 시각을 포함하고 음수 노트 시각도 탐색합니다.
  직접 입력·좌우키·슬라이더·선택 도구의 시간 이동은 같은 `Seek` 검증을 사용합니다.
  리듬 clock의 정수 us 또는 기존 마디 탐색 범위를 벗어나는 입력은 이전 시간을 보존합니다.
  화면 구성 중 오류는 상태 메시지로 표시하며 탭 이동·시간 수정·저장으로 복구할 수 있습니다.
- 오디오 탭은 음악 파형, 음악 FFT 스펙트로그램, 예상 히트사운드 FFT 스펙트로그램의
  세 영역을 같은 시간축으로 표시합니다. 하단 타임라인/현재 시간 입력으로 탐색하며,
  +/− 버튼은 현재 시각을 기준으로 보이는 시간 범위를 확대/축소합니다.
  하단 OFFSET 직접 입력 또는 −1/+1ms로 패턴 offset을 수정합니다. 양수는 음악의 0ms를
  유지하면서 노트·타이밍·효과를 늦추며 문서 변경으로 저장됩니다. 글로벌 옵션 offset과는 별개입니다.
  파형 상단의 파란 눈금은 4분음표 박자(마디 첫 박자 강조), 히트사운드 FFT 상단의 파란
  눈금은 예상 타격 위치입니다. 메트로놈은 기본 꺼짐이며 켜면 Space 재생 시 함께 들립니다.
  BPM·마디 길이·offset·글로벌 offset·delay와 음수 delay의 제거 구간을 같은 MusicalTimeline으로
  컴파일합니다. 메트로놈 토글은 음악을 다시 로드/seek하지 않고 재생 cue만 갱신합니다.
  클릭은 FFT 분석 입력에 넣지 않으며 설정은 편집 세션에만 유지합니다. 기본 클릭 WAV 두 개는
  내장 Default Skin/Editor에 있고 별도 클럭이나 프레임별 템포 적분은 사용하지 않습니다.
- 박자표에서 마디/위치/BPM과 마디 길이를 편집합니다. 마디 밖으로 넘친 노트는 초과분을
  다음 마디로 이월합니다. 마디 밖 BPM/이펙트가 생기는 변경은 데이터 손실 대신 오류를 표시합니다.
  롱노트 시작과 끝이 역전되거나 같은 위치가 되는 변경도 전체 취소하고 원본을 보존합니다.
- 메타데이터에서 YMM 상대경로, 이름, 제작자, 태그, offset, 기본 BPM, Accuracy Difficulty(JudgeLevel 1.00~100.00, 0.01 단위), 히트사운드 표를 편집합니다.
  표의 소유 파일은 YME이며 사운드 상대경로도 YME 폴더 기준입니다.
- 이펙트 목록 선택 후 같은 위치의 값을 수정하거나 삭제할 수 있습니다. 동/캇 변경은 각각
  독립 지시문입니다. 각 입력 필드는 Unicode 입력을 지원하는 Windows 텍스트 창에서 편집합니다.
- 최상단 자체 메뉴바의 파일 → 저장하기, 기존 하단 저장 버튼 또는 Ctrl+S로
  YMP와 `Effect file`이 지정한 YME를 저장합니다. 세 경로 모두 Workspace의 같은 저장 명령입니다.
  메뉴바는 에디터에서만 표시하며 Windows 네이티브 메뉴 API를 사용하지 않습니다.
  파일 메뉴에는 현재 YMM/YMP/YME 각각의 폴더 열기가 있습니다. 편집 메뉴에는
  되돌리기·다시 실행·복사·붙여넣기·공백 포함 붙여넣기를 두고 단축키와 같은 명령을 연결합니다.
  Alt+F/F10은 파일, Alt+E는 편집 메뉴를 열며 방향키로 항목/메뉴를 고르고 Enter로 실행합니다. 메뉴가 열린 동안
  뒤쪽 탭·노트·슬라이더 입력을 차단하며, 바깥 클릭 또는 Escape는 메뉴만 닫습니다.
  메뉴 문구·글꼴은 기존 `Texts/EditorScene` 표와 언어별 글꼴 설정을 사용합니다.
  경로가 없으면 같은 이름의 YME를 생성하고 YMP에 참조를 기록합니다. 미저장 상태에서
  Escape를 누르면 폐기 여부를 확인합니다. 저장 전 파싱 왕복 검증 및 두 파일의 임시/복구본을
  사용합니다. 실패하면 이번 저장이 만든 임시 파일을 정리하고 원본 복구를 시도하여
  재시도할 수 있게 합니다. 시작 전부터 존재한 복구 파일은 보존하고 저장을 거부합니다.
  프로세스 강제 종료 또는 복구 자체의 파일 시스템 오류로 복구 파일이 남은 경우에는
  원본 복구를 확인한 뒤 제거하세요. YMP와 YME를 같은 파일에 저장하는 것도 거부합니다.

이펙트 UI는 기존 볼륨/마디선/Whole/Separate/동·캇 편집을 유지합니다. 볼륨 기본 대상은
HitSound이며 Music/UI 대상은 검증 오류입니다. 보간 버튼은 Linear/Exponential/Harmonic을
선택합니다. 목록의 지점형 효과는 변경값 하나만 표시하고, Area 효과만 시작값 → 끝값으로
표시합니다. Kiai는 내부 숫자 대신 언어파일의 이름으로 표시합니다.
파일에 등록한 식/베지어는 표시·저장하고 해당 효과의 값을 편집할 수 있지만,
식 등록과 Syncopation/Kiai ON/OFF의 전용 편집 UI는 아직 없습니다. 이 명령들은 파일에서
편집하며 다른 수정/저장에서도 보존합니다. 문법은 [YME](Formats/Yme.md)가 기준입니다.

## 내부 구조와 검증 경계

### 모드와 파일 형식의 교체 경계

```text
EditorScene
  EditorWorkspace
    IEditorMode                 도구/배치/그리기/좌표/히트사운드 정책
      Modes/Taiko/TaikoEditorMode
    IEditorDocument             공통 편집용 데이터와 파일 형식별 수정/저장
      ChartEditor               현재 YMP/YME 구현
    EditorAnalysisController    IEditorAudioSource의 파일/marker 비동기 분석
    EditorPlayback              revision별 Clip/cue, DSP 기준 재생/seek/정지
  EditorView                    공통 탭/박자 디바이더/타임라인/FFT 화면
    EditorMenuBar               Canvas 상단 파일/편집 메뉴와 입력 점유 상태
    IEditorModeCanvas           모드에 제공하는 Box/Text/Image/Button 그리기 계약
```

Workspace가 문서/모드/worker/재생 객체를 단독 소유합니다. 모드는 `IEditorContext`의 읽기 전용
문서와 읽기 전용 악보 설정을 받고 Replace/AddNote/DeleteNote/Seek 등의 명령만 전달합니다.
다른 모드·진입 요청·분석 worker·공통 탭의 내부 재구축 플래그를 참조하지 않습니다.
문서 수정 성공 후 Workspace가 분석 갱신과 화면 재구축을 연결합니다. worker는
해석된 파일 목록이 바뀐 경우에만 재시작하고 marker는 문서 identity/revision으로 캐시합니다.
오디오 조회는 `IEditorAudioSource`로 분리되어 분석 코드가 UI 모드 계약에 의존하지 않습니다.
디바이더·표시 모드·첫 마디 변경도 Workspace 명령이 검증/재구축 요청을 함께 처리합니다.

`EditorModeFactory`가 진입 요청의 `mode`에 맞는 객체를 생성합니다. 현재 등록된
모드는 Taiko 하나이며 빈 모드 ID와 미지원 ID는 오류입니다.
Taiko로 열었는데 다른 모드가 기록된 문서는 오류로 거부하며 Taiko 도구로 덮어쓰지 않습니다.
활성 에디터 안에서 모드를 바꾸는 UI는 제공하지 않습니다.

`TaikoEditorNoteInspector`는 선택한 안정 ID와 미적용 초안을 소유합니다. 문서/rule 객체의
포인터를 보관하지 않고 `FindNote`로 원본의 시작/끝 복사본을 조회합니다. 문서 revision이
바뀌면 선택을 다시 확인하고 삭제된 노트는 해제합니다. 미적용 초안은 외부 revision 변경에서
보존합니다. 적용은 공유 Taiko 배치/옵션 검증 → Workspace UpdateNote → 문서 트리 갱신
순서이며, 실패하면 원본 ID/인덱스/revision을 보존합니다. 속성 편집은 타이밍 맵이나
전체 노트 트리를 재생성하지 않고 선택된 시작/끝 항목을 준비한 뒤 교체합니다.
형식별 adapter는 `FindNote`의 끝점 선택 해석과 `UpdateNote`의 직렬화/추가 데이터 보존을
소유합니다. 게임플레이 INote는 별도의 판정 수명/상태가 있으므로 편집 원본을 대신하지 않습니다.

Taiko의 도구 ID/그룹/선택 상태, 미완성 롱노트, 팝업, 노트 색/모양,
악보/실시간 레인, 노트 hit-test/스냅/마디 스크롤, YMP 메타데이터 편집과
오디오 파일 해석은 `Modes/Taiko/`가 소유합니다. 플레이와 공유하는 옵션 해석·기본
사운드 ID·예상 cue 생성은 `YOUMU.Modes/Taiko/Submodules/`에 있습니다.
도구 문구와 동·캇 이펙트
문구는 `Client/Texts/EditorScene/Taiko/`에 있습니다. 공통 화면에는 Taiko
노트 enum/숫자 의미나 도구 개수/그룹을 넣지 않습니다. 이펙트의 공통 자동화
편집 UI는 유지하고 사운드 대상 목록/표시는 모드에서 받습니다.

새 모드를 추가할 때는 `Modes/<Mode>/`의 `IEditorMode` 구현과 문구 표를
만들고 factory에 연결합니다. 도구 개수와 그리기 모양/방향은 모드가 결정하며,
`DrawChart`에서 만든 좌표를 해당 모드의 `EditScore`가 해석합니다.
`OpenDocument`는 파일 형식에 맞는 `IEditorDocument`를 반환합니다.
UI 그리기는 전달받은 Canvas를 해당 호출에서만 사용하고, Button 콜백은
활성 편집 context/모드의 수명 안에서 실행됩니다. 모드가 Scene 전환을 호출하지 않습니다.
`AudioFiles`의 `Music` 키는 음악 파형/FFT용이며 나머지 키는
`AudioMarker.sound`와 대응하는 히트사운드입니다. 파일 목록은 worker에 복사합니다.
조회 과정은 진입 요청을 변경하지 않습니다. Taiko cue ID는 플레이와 동일하며
사용자 표의 사운드는 `Chart.HitSound.<index>`로 구분합니다.

`IEditorDocument`의 Pattern/Effects/Notes/Timeline은 **편집용 공통 표현**입니다.
새 파일 형식은 adapter가 원본의 추가 필드/지시문을 보관하고,
수정·검증·롱노트 연결·저장을 그 형식의 규칙에 따라 구현해야 합니다.
공통 표현으로 변환한 뒤 YMP로 저장하는 계약이 아닙니다.
현재 `ChartEditor`의 동·캇 키 검증과 롱노트 연결 규칙은 현재 YMP 편집 구현에
남아 있으며, 새 형식이 이를 상속하거나 그대로 재사용할 필요는 없습니다.
메타데이터 화면/오디오 파일 해석도 모드가 소유하므로 YMM 경로를 강제하지 않습니다.

BMS 파싱·저장, 7키/스크래치 배치와 전용 도구는 아직 구현하지 않았습니다.
나중에 BMS를 실제로 지원할 때는 위 모드/문서 adapter 외에도 현재 YMM/YMP
중심인 곡 카탈로그의 검색·진입 연결을 추가해야 합니다. 이번 변경은 에디터 내부의
교체 경계를 마련한 것이며 파일 지원이 추가된 것은 아닙니다.

### 공통 처리와 검증

`YOUMU.Chart/Editing/ChartEditor`는 `IEditorDocument`의 현재 구현으로
엔진 비종속 편집 상태와 YMP/YME 저장을 소유합니다.
편집 원본 노트는 `(MusicalPosition, 고유 ID)` 균형 트리, BPM/마디 길이는 위치별
다중 트리, 자동화와 히트사운드 변경도 각각 위치별 다중 트리가 소유합니다.
정렬 키는 Rational 박자 위치이므로 BPM 변경으로 시간이 달라져도 원본 키를 바꾸지 않습니다.
시간순 보조 인덱스는 정수 us와 고유 ID를 사용합니다. 일반 노트 추가/삭제는
해당 항목만 갱신하고 전체 복사·정렬·timeline 재생성을 하지 않습니다. 롱노트 편집은
시작/끝 항목만 순회하여 기존 저장/플레이의 짝짓기 규칙을 유지합니다.
BPM·마디 길이·속도 변경은 영향을 받는 컴파일 결과를 후보 안에서 다시 검증합니다.
Workspace는 `ReplaceTiming`/`ReplaceEffects`로 변경 종류를 전달합니다. 타이밍 변경은
timeline·시간 인덱스·시간에 의존하는 속도 캐시만 재생성하고 원본 노트/ID/연결 트리를 유지합니다.
이펙트 변경은 효과 소유 트리와 조회 인덱스를 함께 교체하고 노트 배율/스크롤 캐시를 갱신합니다.
조회 포인터는 같은 트랜잭션의 소유 트리 노드만 가리킵니다. 마디 길이 변경은 노트 위치를
이월해야 하므로 전체 후보 문서 검증을 유지하며, 전체 metadata 교체도 `Replace`를 사용합니다.
노트 위치·마디 길이는 Rational입니다. 화면 좌표를 위한 부동소수점은 렌더링/마우스 스냅 경계에서만 사용합니다.
`ChartEditor`는 후보 문서의 timeline을 한 번 생성해 검증과 노트 캐시 생성에 공유한 뒤
성공한 후보만 교체합니다. 실패 시 문서·revision·dirty·시간/속도 캐시를 보존합니다.
`sourceOrder`는 편집 중 안정적인 노트 ID이며 vector의 배열 인덱스가 아닙니다.
삭제한 ID는 재사용하지 않습니다. `Pattern/Effects/Notes`의 vector는 파싱·저장·플레이와
연결하는 읽기 전용 snapshot으로 요청할 때만 갱신합니다. 이후 수정 시 참조 내용은
갱신될 수 있으므로 편집 명령을 가로질러 항목 포인터를 보관하지 않습니다.
악보와 실시간 뷰는 `NotesInTimeRange`로 표시 마디/화면의 실제 시간 구간을 조회합니다.
양 끝이 화면 밖인 롱노트도 포함하며, 이 경우 롱노트 짝 목록을 추가 검사합니다.
두 구간 조회와 부분 수정 명령은 `IEditorDocument`의 필수 구현입니다. 범위를 무시하고
전체 노트를 반환하던 기본 구현은 없으며 새 adapter도 자체 연결/조회 정책을 구현해야 합니다.
화면 밖 마디와 같은 픽셀에 겹치는 보조선은 그리기를 줄이되 스냅 위치는 유지합니다.
박자/이펙트 입력은 이름 있는 `EditorTimingForm`/`EditorEffectForm`으로 관리합니다.
이펙트 선택은 자동화 종류 또는 모드의 사운드 키를 저장하므로 사운드 목록의 순서와
개수에 의존하지 않습니다. 지원 자동화의 순환·표시·버스 입력은 한 정의 표를 사용합니다.

`EditorScene`은 ScreenVisual2DManager의 Canvas에 draw packet component를 등록합니다.
박자 디바이더는 같은 Canvas의 엔진 `CreateSlider`와 `Visual2DInputRouter`를 사용합니다.
화면 비율이 좁아져도 Penpot 작업영역이 잘리지 않게 동일 비율로 축소합니다.
`EditorAudioAnalysis`는 실제 음악/히트사운드 PCM을 디코딩하고
2048-point Hann FFT를 계산합니다. 96개 로그 주파수 구간은 20Hz부터 최대
20kHz(파일의 Nyquist 이하)까지이며, 색상은 −90~0dBFS 범위입니다.
스테레오 등 다채널 음원은 채널별 FFT 전력을 평균해 위상 상쇄로 사라지지 않습니다.
