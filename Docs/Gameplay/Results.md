# 플레이 결과와 입력 기록

모든 논리 노트가 완료/MISS로 확정된 뒤 3초가 지나면 Result로 이동합니다.
처리가 끝난 뒤 ESC를 누르면 즉시 정상 종료 결과로 이동합니다. 타겟이 남아 있으면
ESC는 [일시정지 메뉴](Pause.md)를 엽니다. Retire 선택은 남은 노트를 MISS로 확정하고
즉시 중도 종료 결과로 이동합니다. Result의 Back·ESC·Enter는 곡 선택으로 돌아갑니다.
Retry는 방금 플레이한 패턴·효과·음원 경로로 새 세션을 생성합니다.
Replay 버튼은 꺼진 상태로만 표시하며 입력 로그의 재생 기능을 제공하지 않습니다.

## 수집과 소유권

- `PlaySession`은 모드가 만든 `IPlayResultCollector`에 판정 입력과 의미 이벤트를 전달합니다.
- `TaikoSessionBuilder`는 실제 생성된 논리 노트만 `TaikoResultCollector`에 등록합니다.
  롱노트 테일, 음수 delay로 제외된 노트, 무시된 겹침 행은 별도 점수 항목이 아닙니다.
- `TaikoResultCollector`는 판정·오차·완료 점수를 수집하고 종료 시 그룹/분산을 계산합니다.
  `IPlayResult`의 공통 요약과 `TaikoPlayResult`의 모드별 데이터를 반환합니다.
- `RhythmTestScene`이 결과 `unique_ptr`를 루트의 대기 슬롯으로 이동합니다.
  미리 등록된 Result factory가 슬롯을 소비하여 새 `ResultScene`을 생성합니다.
  gameplay와 Result 모두 `DestroyOnExit`이며 다음 update에 전환을 적용합니다.
- `ResultScene`은 결과 데이터를 소유하고 `IResultView`를 조립합니다. 모드 선택은
  `ResultViewFactory`, 현재 Taiko 표시/Canvas는 `TaikoResultView`가 소유합니다.
  결과는 노트·세션·오디오 객체의 포인터를 보관하지 않습니다. View는 Scene 데이터만
  읽으며 View/Canvas가 데이터보다 먼저 정리됩니다.

다른 모드는 자신의 수집기·결과·View를 구현하고 모드/결과 factory에 연결합니다.
공통 Scene에 Taiko 판정 항목이나 그래프 규칙을 추가할 필요가 없습니다.

## 점수와 판정 개수

SCORE는 종료 시점의 `PlaySession::Score()`를 `summary.score`로 전달해 표시합니다.
최대 콤보는 판정 수집기의 `summary.maximumCombo`이며 키 레이아웃의 실시간 콤보와
같은 규칙으로 집계합니다. 계산식과 되감기는 [플레이 HUD](Presentation.md#콤보점수판정-누적-hud)를
따릅니다. 로컬 기록과 랭크는 결과의 정확도 집계를 사용합니다.

점수 정밀도는 [판정 규칙](Rules.md)의 AccuracyScore가 기준입니다.
최종 정확도는 **전체 유효 논리 노트 점수의 합 / 전체 유효 논리 노트 수**입니다.
Retire의 남은 노트와 진행 중 롱노트는 0점·실제 MISS로 집계하여 미처리가 남지 않습니다.
이미 확정된 롱노트의 부분 점수는 기존 규칙대로 보존합니다. 수집기에 별도로 미처리 상태의
종료를 요청한 경우에는 해당 노트를 0점·미처리로 구분하며 가상의 MISS를 만들지 않습니다.
노트가 없는 그룹은 화면에 `— %`를 표시합니다. 전체·그룹 정확도는 소수점 둘째 자리까지
버림해 표시하며(99.999999% → `99.99%`) 랭크와 기록은 원래 값으로 판정·저장합니다.

Taiko는 일반(Don/Kat), 큰(BigDon/BigKat/Purple), 롤 계열의 정확도를 각각 표시합니다.
롤 계열에는 Roll/BigRoll/TickRoll/BigTickRoll/Balloon/DengDeng/Buzz가 포함됩니다.
각 노트의 정확도·종류·목표와 수락된 타격/틱은 결과 데이터에도 남습니다.
그룹 평균끼리 평균내지 않고 각 논리 노트에 같은 가중치를 줍니다.

- MAX/PERFECT/GREAT/GOOD/BAD: 실제 `HitAccepted`의 타이밍 판정 개수입니다.
  큰/보라 노트의 두 입력은 각각 셉니다. Buzz의 `HoldStarted`는 중복 집계하지 않습니다.
- OK: 롤 계열이 요구 타격/틱을 모두 채운 성공 완료입니다.
- MISS: 실패로 확정된 논리 노트입니다. 틱롤의 완료 이벤트에도 실패 틱이 있으면 MISS입니다.
- POOR: Good 이내에서 거부된 **Pressed** 입력과 잘못된 색을 유지해 거부된 Buzz 몸통 틱입니다.
  몸통의 각 `TickRejected`는 POOR 1개와 미처리 틱 1개로 집계하며 헤드 오차 표본을 만들지 않습니다.
  빈 입력과 키 해제(`InputEdge::Released`)는 포함하지 않습니다.
- 유지/틱롤의 성공·실패 틱은 별도 집계합니다. 자유 연타 입력은 타이밍 판정으로 세지 않습니다.

따라서 판정 카운트의 합이 논리 노트 수와 항상 같지는 않습니다.

## HP 곡선과 사용 요약

왼쪽 열 맨 위의 HP 그래프는 기본 게이지의 실제 변화 이력으로 0–100% 곡선을 그립니다. 가로축은
채보 시간이며 시작 대기와 종료 시각을 포함합니다. 세로축에는 100%·클리어 기준·0%만 적고
그래프 안에는 글자를 두지 않습니다. 클리어 기준은 게이지가 보고하는 값(`HpGaugeState::clearPercent`,
기본 게이지 60%)이며 그 자리에 점선을 그립니다. 플레이 HUD의 클리어 표시도 같은 값을 씁니다.
게이지는 HP가 변할 때의 판정 이벤트 시각·값을 기록하고, 결과는 그 값을 복사해 소유합니다.
기록이 없는 이전/미지원 결과와 HP 제외 대상은 축과 클리어선만 두고 `데이터 없음`을 표시하며 값을 만들지 않습니다.
유효하지만 변화가 없는 기록은 초기 HP 0%의 수평선으로 표시합니다.

일시정지 메뉴 또는 Rewind를 사용하면 그 시점부터 HP 처리·이력 추가를 멈추고 이전 값과
곡선을 보존합니다. Resume·Rewind·Retire는 HP를 다시 계산하거나 활성화하지 않으며
Retry만 새 0% 기록으로 시작합니다. 곡선은 최초 비활성화 시각에서 끝나고 그 이후를 가상의
HP 값으로 채우지 않습니다. HP 자격이 없어도 기록된 곡선은 숨기지 않습니다.

사용한 항목만 그래프 제목 줄 오른쪽에 `일시정지 사용`·`Rewind 사용` 요약을 표시합니다.
미사용이면 요약을 표시하지 않으며 곡선은 그대로 유지합니다. 일시정지는 `pauseMenuUsed`,
Rewind는 제어 로그의 실제 `Rewind` 명령으로 판단합니다. Debug 전용 정지·탐색은 기존
예외를 유지합니다. 발생 시점 표식·사용 횟수·정지 지속시간은 추가하지 않습니다.
HP 이력은 현재 결과의 값 데이터이며 DB/YMP 형식과 HP 증감식은 변경하지 않습니다.

정상 종료했고 HP 판정이 가능하며 실제 게이지가 불합격인 경우에만 제목 줄의 `HP` 옆에
`FAILED` 표시를 둡니다. 클리어에는 별도 문구를 표시하지 않습니다. HP 비활성화 완주는 기존
사용 요약만 표시하고 실패로 분류하지 않습니다. HP 상태가 없는 결과도 실패를 만들지 않습니다.
Retire는 기존처럼 남은 논리 노트·미완료 롱노트를 MISS·0점으로 확정하며, 중도 종료 문구는
표시하지 않습니다. 실제 HP 값·곡선은 바꾸지 않고 데이터의 종료 사유는 그대로 보존합니다.

## 오차와 그래프

타이밍 판정 입력마다 노트 ID·타격 인덱스·입력 시각·부호 있는 오차·등급·점수를 남깁니다.
자동 MISS, 미처리, 자유 연타, 판정 없는 틱에 가상의 오차를 만들지 않습니다.
모집단 분산(ms²), 평균/표준편차(ms)를 Welford 방식으로 계산합니다.
타이밍 입력이 없으면 통계/그래프에 명시적인 빈 상태를 표시합니다.

시간별 오차 산점도의 가로축은 세션 시간(s), 세로축은 오차(ms)입니다.
양수는 늦은 입력, 음수는 빠른 입력이며 점 색은 키빔의 등급 색입니다.
히스토그램은 오차를 가까운 정수 ms로 대칭 반올림하여 1ms 구간별 입력 개수를 표시합니다.
같은 구간의 실제 판정들을 산점도와 같은 색상으로 MAX→BAD 순서로 아래부터 쌓습니다.
막대 전체 높이와 최고 빈도는 해당 구간의 총 입력 수이며, 표시 범위를 넓혀도 1ms 간격을 유지합니다.
입력이 있는 구간만 집계하여 오차 범위에 비례하는 배열을 할당하지 않습니다.
축소 화면에서는 집계 간격을 유지하고 막대의 그리기 폭만 최소 한 픽셀로 제한합니다.
범위는 최소 ±100ms이고 실제 입력 오차를 포함하도록 확장합니다.
두 그래프와 HP 곡선은 한 RectangleBatch로 그리고 진입·언어/해상도 변경 시에만 재구성합니다.

## 화면 배치와 책임 경계

결과 화면은 [UI-02](../DesignDecisions.md#ui-02-ui-리디자인)의 배치입니다. 1280×720 논리 화면에 왼쪽 위 원점으로
배치하며 16:9보다 넓으면 논리 폭만 늘어납니다. 왼쪽 열은 폭 340으로 고정하고 가운데·오른쪽 열이
나머지를 반씩 나눕니다. 16:9보다 좁은 화면은 16:9 배치를 그대로 줄여 위아래에 `#04070D` 띠를 두고,
32:9보다 넓으면 좌우에 같은 띠를 둡니다.

- 상단 배너(높이 72): 모드 배지, 곡명·아티스트, 오른쪽에 난이도 이름과 난이도 값 배지, 채보 제작자.
  난이도 값은 계산식이 정해질 때까지 `—`입니다.
- 왼쪽 열: HP 그래프 → 정확도(크게)와 최대 콤보(오른쪽 끝) 한 줄 → 판정 개수 두 열
  (MAX·PERFECT·GREAT·GOOD / BAD·OK·MISS·POOR, 판정 색 표시와 숫자) → Ticks → 노트 그룹별 정확도 → 노트 수 합계.
- 가운데: 랭크 PNG와 SCORE를 원 틀(`Rank.Ring`) 안에 둡니다. 틀의 띠 위에 판정 비율 조각을 12시부터
  시계방향으로 MAX→PERFECT→GREAT→GOOD→BAD→OK→MISS→POOR 순서의 판정 색으로 그리고, 조각에 마우스를 올리면
  `PERFECT 62 · 14.98%`처럼 개수와 비율(둘째 자리 버림)을 보여 줍니다. 판정이 하나도 없으면 조각을 그리지 않습니다.
  원 아래에는 기본과 다른 플레이 옵션만 칩으로 표시합니다.
- 오른쪽 열: `Timing` 제목 아래 평균·표준편차·분산·표본 수, 오차 히스토그램, 시간별 오차 산점도.
- 하단 띠(높이 64): 왼쪽 끝 Back, 그 옆 기록 저장 줄, 오른쪽 끝에 띠 위로 솟은 Retry와 그 왼쪽의 Replay.
  기록 저장 줄은 저장 중 회색, 저장됨 초록, 실패 빨강이며 실패해도 결과 화면은 그대로입니다.
  실패 때의 공용 대화상자는 아직 없습니다([UI 리디자인](../UIRedesign.md#결과)).
- 양옆 열 뒤에는 화면 끝에서 들어오는 흰 막(`Panels.Left`·`Panels.Right`)을 두어 BG 위에서도 읽히게 합니다.
- 글꼴: 영어 문구는 Nunito, 한글·일본어가 들어간 문자열은 Noto Sans KR, 숫자는 Barlow Semi Condensed입니다
  (`Presentation/UiFonts.h`). SCORE·최대 콤보·정확도는 글꼴로 그리며 숫자 PNG를 쓰지 않습니다.

곡명·아티스트·첫 제작자명은 곡 선택의 GameplayLaunchRequest 값 snapshot에 보관합니다.
결과 화면에서 카탈로그/채보 파일을 다시 읽지 않습니다. 패턴명과 통계는 IPlayResult에서 읽습니다.
선택 채보의 BG 경로와 2D 오프셋도 같은 플레이 선택 snapshot에서 `ResultViewContext`로 값 복사합니다.
플레이 Scene이 파기된 뒤에도 BG를 전체 결과 UI 뒤에 표시하며 원본 비율을 유지해 화면을 채웁니다.
720 기준 오프셋을 그대로 적용합니다. 이미지 handle은 공통 관리자 캐시를 사용하고 resize·언어 변경 시
재배치하며, BG 미지정·누락·읽기 실패 시 스킨 Sky 배경을 사용합니다. BG를 위해 게임 세션이나 오디오 객체를 보관하지 않습니다.
시안의 빈 자리를 채우기 위한 임의 점수·기록·HP 데이터는 생성하지 않습니다.

- ResultScene은 결과의 소유권·화면 수명·전환과 기록 저장 줄을 담당합니다. View는 Back/Retry 액션을 반환합니다.
- YOUMUGame은 선택 snapshot을 캡처한 retry callback을 조립합니다. 이전 세션의
  노트·타이머·음성을 재사용하지 않고 DestroyOnExit route에서 새 플레이 객체를 생성합니다.
- TaikoResultView는 Canvas·입력·스킨 이미지와 공통 틀(배경·레터박스·배너·하단 띠·버튼)을 소유합니다.
  Panels는 배너와 왼쪽 열, Hero는 원·랭크·점수·옵션 칩·조각 툴팁, GraphView는 Timing 열의 장식·축 문구,
  Graphs는 실제 입력에서 범위/빈/점 좌표와 HP 곡선을, Ring은 판정 비율 조각의 픽셀 행과 포인터 조회를 도출합니다.
- TaikoResultLayout은 좌표계·열 폭·그래프 위치를 소유하고 모드의 점수/판정 규칙을 변경하지 않습니다.
- 그래프와 원 조각은 각각 RectangleBatch 하나로 그리고 진입·언어/해상도 변경 시에만 재구성합니다.
  노드 수는 입력 수와 무관합니다.

## 입력 로그와 종료 시각

판정에 전달된 매핑된 게임 키의 Pressed/Released를 `RhythmInputEvent` 값으로 기록합니다.
QPC timestamp를 현재 세션의 단일 RhythmTimer로 변환한 **부호 있는 정수 us**를 사용합니다.
물리 키·의미 action·edge를 보존하고 같은 us의 입력은 저장 순서로 구분합니다.
빈 입력/오입력도 로그에 남습니다. 실제 바인딩, 판정 레벨, 패턴 경로와 시작/종료 시각을
공통 결과 요약에 보관합니다. Retry/R/디버그 Reset은 이전 시도의 집계와 입력 로그를 지웁니다.
Resume/Rewind는 전체 입력과 제어 마커를 유지합니다. Rewind가 취소한 판정은 결과 통계에서 제외합니다.
HP/클리어 자격 및 미래 리플레이의 마커 계약은 [Pause](Pause.md)가 기준입니다.

ESC가 포함된 프레임은 ESC의 QPC 시각까지만 판정하고 이후 입력을 제외합니다.
held 상태도 ESC 뒤의 edge를 되돌려 구하므로 뒤늦은 키 해제로 Buzz 틱이 바뀌지 않습니다.
타겟이 남으면 메뉴를 여는 순간의 노트 상태를 유지하며 Retire를 선택할 때 미처리를 MISS로 확정합니다.
타겟이 모두 소진된 상태에서 ESC로 정상 종료하면 일시정지 사용 이력이 추가되지 않습니다.

결과 데이터는 메모리에서 수집하며 결과 화면 진입 시 실제 시도의 요약과 플레이 옵션을
로컬 SQLite에 저장합니다. 곡 선택의 조건식 조회와 옵션 아이콘은
[PlayOptions](PlayOptions.md)을 따릅니다. 리플레이 재생은 구현하지 않았습니다.

리절트 PNG와 버튼 이미지는 스킨 `[Result]`의 요소 키와 폴더 상대 경로를 사용합니다.
파일별 기본본 대체와 버튼 상태 이미지 규칙은 [skin.ini](../BuiltInAssets.md#skinini와-씬별-이미지)를 따릅니다.

## 정확도 랭크

랭크 이름은 최대 3자입니다([UI-02](../DesignDecisions.md#ui-02-ui-리디자인)).
최종 전체 정확도의 고정소수점 정수 값을 비교하며 표시 문자열(둘째 자리 버림)은 사용하지 않습니다.
각 하한을 포함하고 다음 랭크 하한은 포함하지 않습니다. 100.000000%만 Y이며,
99.999999%는 화면에 `99.99%`로 보이는 X입니다. 클리어/일시정지 자격과는 별개인 정확도 표시입니다.

| 정확도 | 랭크 / `[Result]` 이미지 키 | 기본 PNG |
| --- | --- | --- |
| 100% | Y / `Rank.Y` | `Rank/Y.png` |
| 99% 이상 | X / `Rank.X` | `Rank/X.png` |
| 98% 이상 | SS / `Rank.SS` | `Rank/SS.png` |
| 96% 이상 | S / `Rank.S` | `Rank/S.png` |
| 93% 이상 | AA / `Rank.AA` | `Rank/AA.png` |
| 90% 이상 | A / `Rank.A` | `Rank/A.png` |
| 85% 이상 | B / `Rank.B` | `Rank/B.png` |
| 80% 이상 | C / `Rank.C` | `Rank/C.png` |
| 75% 이상 | D / `Rank.D` | `Rank/D.png` |
| 70% 이상 | E / `Rank.E` | `Rank/E.png` |
| 70% 미만 | F / `Rank.F` | `Rank/F.png` |

TaikoResultView의 RankImageKey가 한 표에서 키를 선택하고 LoadAssets에서 해당 이미지 하나를
등록합니다. BuildHero는 원 틀 안의 236×118 자리에 원본 비율로 맞춰 표시합니다.
Scene, 결과 수집기, 정확도 산식과 저장 데이터는 바꾸지 않습니다. 부분 스킨에서 빠진
랭크 이미지는 기존 SkinManifest 규칙에 따라 해당 내장 기본본으로 대체합니다.
예전 키 `Rank.PERFECT`·`Rank.SSS`는 읽지 않으며, 외부 스킨의 `Rank.SS`·`Rank.S`는 새 하한(98%·96%)의 그림입니다.

### 랭크 PNG 자산

`YOUMU.Assets/Assets/Skins/Default Skin/Result/Rank`의 11개 PNG는
708×354 RGBA이며 같은 2:1 투명 캔버스를 사용합니다. 교체 시 문구·비율·여백과
실제 알파를 유지합니다. UI 시안에서 뽑은 코발트(#1F4C99) 글자와 흰 외곽의 굵은 기울임
글자 스타일을 공유하며 날개 장식·다른 배지/배경은 넣지 않습니다.
런타임은 위 랭크 표로 이미지를 선택하고 비율을 유지해 표시합니다.
