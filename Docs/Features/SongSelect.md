# 곡 선택 화면

수정 진입점: `Client/GameScene/MusicSelectScene/Submodules`.
배치는 SongSelectLayout/패널은 SongSelectPanels/곡 목록 카드·스크롤은 SongListView,
선택 정책은 SongSelectionState, 미리듣기는 SongPreviewController를 읽습니다.
목록 로더·선택 상태·미리듣기는 `GameFlow/SongLibrary`로 묶여 있고, MusicSelectScene은 그것을 빌려
View와 조립하고 View의 전환 의도를 처리합니다([미리듣기와 타이틀 플레이어](#미리듣기와-타이틀-플레이어)).

노트 종류 비율 그래프와 NPS(초당 노트 수) 그래프는 사용자 지시로 폐기했습니다.
두 그래프 및 이를 위한 분석 버튼/패널은 선곡 화면의 구현 범위에서 제외합니다.

화면은 [UI-02](../Design/Decisions.md#ui-02-ui-리디자인) 설계([UI 리디자인](../Design/UI.md#곡-선택))를 따른다.
1280×720 논리 화면(좌상단 원점)의 좌표를 그대로 쓰는 `FixedHeight` Canvas이며 논리 높이는 720으로 유지한다.
글자는 Nunito(한글·일본어가 있으면 Noto Sans KR), 숫자는 Barlow Semi Condensed다.

배경·면·버튼·곡 카드·기록 줄 판 등의 그림은 선택 스킨의 `[MusicSelect]`에서 지정한다.
내장 `Default Skin`이 모든 부품의 PNG를 갖고 있고, 스킨이 그림을 주지 않은 부품은 내장 그림을 쓴다.
문구·곡 정보·선택/입력·배치는 스킨과 무관하다.
폴더와 상태별 이미지 계약은 [skin.ini](Assets.md#skinini와-씬별-이미지)에 있다.

## 배치

- 화면은 왼쪽 기록(x 0, 폭 352), 가운데 곡 정보(x 368부터), 오른쪽 곡 목록(폭 400, 화면 오른쪽 끝)의 3열이다.
  세 열 모두 위 24, 높이 608이고 아래 64는 하단 띠다. 감싸는 패널은 없다. 별도 `ALL` 바와 안내 줄은 없다.
- 곡 정보와 곡 목록은 한 면(`Panels.Sheet`) 위에 놓인다. 면은 스킨 바탕색(240,248,255)의 불투명도 0.65이고
  x 362부터 화면 오른쪽 끝까지, 화면 높이 전체다. 왼쪽 가장자리는 완만하게 비스듬하다(높이 720에 26, 위 x 388·아래 x 362).
  가장자리 왼쪽에 폭 10의 코발트 그림자 띠(`Panels.SheetEdge`, (31,76,153) 불투명도 0.22)가 같은 기울기로 붙는다.
  곡 정보와 곡 목록 사이에는 가는 세로줄이 있다. 기록 열 자리에는 면이 없어 곡 BG가 그대로 보인다.
  에디터 곡 선택도 같은 면을 쓴다. 양옆 막, 가운데 빛, 글자의 흰 번짐은 쓰지 않는다.
- 왼쪽 기록 열은 선택 패턴의 실제 로컬 기록을 최신순 여섯 개씩 표시한다. 맨 위에 `PERSONAL RECORD` 선택기와
  기록 필터 아이콘 버튼이 있고(x 48부터), 둘 다 BG 위에서 읽히도록 바탕이 불투명하다.
  기록 줄은 곡 목록 막대를 180° 돌린 모양(오른쪽 끝이 비스듬하고 위쪽이 더 김)의 판(`Records.Row`, 불투명도 0.92)이다.
  모든 줄이 화면 왼쪽 끝(x 0)에서 시작해 x 336에서 끝나는 같은 너비이고, 높이 52·간격 6으로 세로 한 줄로 놓인다.
  줄 끝은 면의 비스듬한 가장자리를 따라가지 않는다. 내용은 x 48부터 308까지다.
  기록 한 줄은 랭크 글자, 큰 줄의 SCORE(천 단위 쉼표, `Presentation/ScoreText.h`), 작은 줄의 정확도(소수 둘째 자리 버림)와
  기본값과 다른 옵션 요약(`97.53% · 1.50x · MIR`), 상태 칩(Cleared·Practice·Failed, 중간에 그만둔 플레이는 Failed로 표시), 날짜(UTC, `2026.11.08`)다.
  기록 줄은 버튼이다. 누르면 worker가 그 기록의 결과 상세를 읽어(`PlayRecordStore::LoadDetail`, `PlayRecord::LoadResult`)
  결과 화면을 다시 연다. 이 결과는 다시 저장하지 않으므로 기록 저장 줄이 없고, Back은 곡 선택으로 돌아가며
  Retry는 선택한 패턴을 그 기록의 플레이 옵션(Random 시드 포함)으로 플레이한다. 상세를 읽지 못하면 공용 경고 대화상자
  (`Record not opened`)가 원인을 보여 주고 기록은 그대로 둔다.
  기록 줄에 포인터를 올려 두면 줄에 없는 정보를 툴팁으로 보여 준다. 첫 줄은 플레이 모드·그 플레이의 JudgeLevel(`JL 70.00`)·
  최대 콤보, 그 아래 개별 판정 수 8개를 두 개씩 네 줄(MAX·PERFECT / GREAT·GOOD / BAD·OK / MISS·POOR, 네 자리 수도 툴팁 폭 300에
  들어가도록), 기본과 다른 옵션 전체, 마지막 줄은 플레이 시각(UTC, `2026.11.21 23:14 UTC`)과 일시정지 메뉴를 썼으면
  `Pause menu used`다. 판정 수는 기록 한 쪽을 읽는 worker가 그 쪽 줄들의 결과 상세를 읽어
  `Records/RecordJudgements`(모드별 판정 수, 지금은 Taiko)로 구한다. 상세가 없거나 읽지 못한 기록은 판정 줄 없이 나머지만 보인다.
  랭크 글자는 결과 화면과 같은 기준(`Presentation/RankName.h`)으로 정확도에서 구한다.
  기록이 없으면 설명 없이 숫자 글꼴 `NO RECORD` 한 줄이고(모든 언어에서 같은 영어 문구) 패턴이 없는 곡은 기록 열을 비운다.
  `NO RECORD`, 불러오는 중, 조회 오류 문구는 첫 기록 줄 자리의 같은 판 위에 놓인다.
  기록이 한 쪽을 넘을 때만 아래에 이전/다음 화살표와 쪽 번호가 나타나며, 이것도 같은 바탕색의 판 위에 놓인다.
  기록 필터 버튼은 별도 기록 필터 패널을 열며 기록 영역 자체를 옮기거나 넓은 열람 창으로 바꾸지 않는다.
  항목별 조건·줄 스위치와 적용·취소 계약은 [기록 필터](Gameplay/PlayOptions.md#기록-필터)를 따른다.
  BEST 칸은 두지 않고 일반 기록만 나열한다(사용자 결정).
- 가운데 곡 정보는 열 가운데를 축으로 위에서부터 정사각 재킷(196), 음표 아이콘과 아티스트, 곡명, 깃펜 아이콘과 채보 제작자,
  난이도 블록(코발트 평행사변형 안의 패턴 이름과 금빛 난이도 값 배지, 이름이 길면 수치 표 너비에서 양쪽 여백 24씩(400)을 뺀 폭까지만 늘고 넘는 글자는 잘린다), 수치 여섯 칸(3×2)을 둔다.
  두 아이콘은 옅은 코발트(`#5B8FE6`) 16px이고 이름 앞 6px에 놓이며, 이름이 없으면 아이콘도 숨긴다.
  수치 칸은 폭 448(칸 폭 149.3)의 표이고 위·아래에 진한 1px 줄, 두 행 사이와 열 사이에 옅은 1px 줄을 둔다.
  패턴이 없어 수치 칸을 비우면 줄도 숨긴다.
  수치는 Base BPM·Length·Notes / JudgeLevel·HP level·Mode다.
  Base BPM은 YMP의 `Base BPM`(Accelerate BPM 지정과 BPM 단위 스크롤 속도가 나누는 값, 곡 필터 BPM·Base BPM 정렬과 같은 값)이며
  올바른 값이 아니면 `—`다. 유효한 타이밍 구간의 BPM 범위는 Base BPM 칸(이름·값)에 포인터를 올리면 툴팁 `BPM 120–180`으로 보인다
  (변속이 없으면 `BPM 150`처럼 한 값, 범위를 모르면 툴팁 없음).
  범위는 목록 캐시에 보관한다. Length는 선택 곡의 비동기 미리듣기 음원이 준비되면 표시하며 읽을 수 없으면 `—`다.
  Notes는 실제 기본 플레이 세션의 논리 노트 객체 수다. 롱노트의 머리·꼬리는 하나의
  논리 노트이며 틱/입력 개수와 구분한다. 집계할 수 없으면 `—`로 표시한다.
  노트 수 범위 필터에도 같은 값을 쓰며, 범위를 지정했을 때 집계 미상 패턴은 제외한다.
  JudgeLevel과 HP level은 선택한 패턴의 값을 소수 둘째 자리까지 표시한다.
  HP 미지정 채보는 기존 파서/모델의 기본값 `9.00`이다.
  난이도 값은 `SongCatalogPattern::calculatedDifficulty`를 소수 둘째 자리로 표시하고 미계산은 `—`다.
- 곡명·아티스트·난이도명·채보 제작자는 이름 하나만 한 줄로 표시한다. 어느 표기를 쓸지는 옵션의 `Song text`가 정한다
  (`First notation`: 첫 번째로 등록된 비어 있지 않은 이름, `Romanized`: 로마자 줄. 규칙은 [YMM](../Formats/Ymm.md#로마자-줄과-표시)).
  곡명이 없으면 YMM 파일명을 쓰고 아티스트·제작자가 없으면 그 줄을 비운다. 긴 이름은 칸에서 잘린다.
  각 줄에 포인터를 올리면 로마자 줄과 등록된 모든 이름을 ` · `로 이은 툴팁이 나온다([툴팁](TextManagement.md#툴팁)).
  검색은 로마자 줄과 모든 이름을 대상으로 한다. 곡명·아티스트 정렬과 플레이·결과·타이틀 재생기에 넘기는 이름도
  표시 중인 표기를 따르며, 옵션을 바꾸면 선택한 곡을 유지한 채 곧바로 다시 정렬한다.
- 재킷은 선택한 YMP의 `BG:`를 그 곡 폴더의 `BG`에서 읽고 원본 비율을 유지해 가운데를 정사각으로 잘라 채운다.
  같은 이미지를 선곡 화면 전체의 UI 뒤 배경에도 표시한다. 전체 배경은 화면비에 맞춰 채우고
  채보의 720 기준 `offset:`을 적용한다. 재킷과 전체 배경은 같은 캐시 이미지
  handle을 사용한다. 같은 BG에서 offset만 바뀌어도 배치를 갱신하고 화면 크기 변경에 대응한다.
  선택 경로가 바뀔 때만 등록하며 엔진의 기존 이미지 경로 캐시를 재사용한다.
  패턴 변경 시 이미지를 교체하며, 미지정·읽기 실패·선택 없음은 빈 재킷 그림(`Detail.JacketEmpty`)을
  표시하고 전체 화면은 스킨 배경으로 돌아간다. 이전 채보의 배경을 남기지 않는다.
- 오른쪽은 폴더 탭 한 줄(All + 컬렉션, 오른쪽 끝 ★는 컬렉션 관리), 검색창(돋보기와 곡 수), 정렬/필터 행,
  곡 목록 순서다. 목록은 부모 clip rect로 실제 표시 영역 밖의 카드와 글자를 자르고, 넘칠 때만
  오른쪽 scrollbar로 현재 위치를 표시한다. 활성 필터가 있으면 필터 버튼이 코발트로 채워진다.
- 곡 카드는 높이 58, 간격 64의 흰 막대(불투명도 0.92)이고 곡명과 아티스트 한 줄씩이다. 사용자 지시에 따라 BG 썸네일은 없다.
  카드는 목록 열 안 x 38에서 시작해 화면 오른쪽 끝까지 닿는다(폭 362, 선택 카드는 20 튀어나와 382). 오른쪽 변은 직각이라 잘리지 않고
  어느 화면 너비에서도 열의 오른쪽 끝을 따른다. 난이도 행도 선택 카드 안 x 34에서 카드 오른쪽 끝까지(폭 348) 닿고,
  난이도 값은 행 오른쪽 끝에서 20 안쪽에 둔다. 스크롤바 띠(폭 12)는 넘칠 때만 화면 오른쪽 끝에 붙어 카드 위에 겹쳐 보이고
  카드 글자는 오른쪽 44를 비운다.
  선택한 곡의 카드는 왼쪽으로 20 튀어나온 코발트 면(금빛 왼쪽 줄)이며 그 안에 난이도 행(높이 32, 간격 36)이
  세로로 펼쳐진다. 고른 난이도는 흰 면에 코발트 글자이고 오른쪽 끝에 난이도 값이 있다.
  곡 복귀 시 첫 표시 채보를 선택하는 기존 동작은 유지한다.
- 하단 띠: 왼쪽 끝 `Back`(남색 모서리 블록, 마우스를 올리거나 눌러도 색이 바뀌지 않는다), 오른쪽 끝 `GO`(띠 위로 20 솟은 코발트 블록), 가운데에 게임 모드 선택,
  `Play options`, 옵션 톱니가 나란히 있다. 진입 오류는 GO 바로 위 말풍선에 표시한다.
  `Play options` 글자 오른쪽에는 기본과 다른 옵션 수의 금빛 배지가 있고 0이면 숨는다([배지](Gameplay/PlayOptions.md#플레이-옵션-패널)).
  패턴이 선택되지 않으면 GO는 꺼진 모양이다. Back·GO·게임 모드·옵션 톱니·기록 필터·컬렉션 관리는 이름과 단축키 툴팁이 있다.
- 기록 선택기·정렬·게임 모드는 공용 [드롭다운](TextManagement.md#드롭다운)이다. 기록 선택기와 정렬은 13px 잉크,
  게임 모드는 16px 굵은 코발트 값을 쓴다. 영어 문구는 첫 글자만 대문자다(`Personal record`, `Difficulty`, `12 songs`, `Filter`, `Back`).
- 선택한 곡의 소리가 재생 중이면 선택 카드 곡명 앞에 금빛 막대 세 개(13×12, 0.8초 주기로 30–100% 높이가 엇갈려 오르내림)를
  두고 곡명은 그만큼(21) 오른쪽으로 밀린다. 일시정지·정지되었거나 아직 다른 곡이 들리면 표시하지 않는다. 에디터 곡 선택도 같다.
- 곡 목록 카드의 곡명·아티스트는 이름이 여러 개이거나 줄에서 잘리면 포인터를 올렸을 때 모든 이름(하나면 그 전체 이름)을
  툴팁으로 보인다. 카드 누르기와 난이도 행은 그대로다([툴팁](TextManagement.md#툴팁)).
- 곡 목록의 스크롤바는 공용 [스크롤바](TextManagement.md#스크롤바)다. 끌거나 레일을 눌러 목록을 옮긴다.
  키보드 포커스 그림은 아직 없다.

## 화면비 대응

- 16:9부터 32:9까지는 논리 폭만 늘어난다. 기록 열은 화면 왼쪽 끝 기준, 곡 목록은 오른쪽 끝 기준이고
  가운데 곡 정보가 남은 폭을 쓰며 내용은 그 가운데에 놓인다. 하단 띠는 전체 폭이고 가운데 묶음은 화면 가운데다.
  면은 늘 x 362에서 시작한다. 면 그림은 16:9 화면의 오른쪽 끝까지이고, 그보다 넓은 화면에서는
  그림의 오른쪽 끝 색으로 화면 끝까지 잇는다(비스듬한 가장자리는 늘어나지 않는다).
- 16:9보다 좁은 화면은 16:9 배치 전체를 같은 비율로 줄여 가운데에 두고 위아래에 `#04070D` 띠를 둔다.
  32:9보다 넓으면 32:9 배치를 유지하고 좌우에 같은 띠를 둔다. 좁은 화면용 축소 배치는 없다.
  검색창의 Windows 편집기도 같은 비율로 위치와 글자 크기를 맞춘다.
- Play options·곡 필터·기록 필터 창은 16:9보다 좁은 화면에서 곡 선택 화면과 같은 비율로 줄어 가운데에 놓인다.
  옵션 서랍·컬렉션 패널은 아직 화면 크기에 직접 맞추는 기존 배치를 쓴다.
- resize 뒤 hit-test와 목록 scroll 위치도 함께 갱신한다.

## 곡과 난이도 포커스

곡과 패턴을 별도 패널로 나누지 않는다. 포커스된 곡 카드 하나만 높이가
늘어나고 그 안에 해당 YMP 패턴 목록이 펼쳐진다. 다른 곡 카드는 실제 곡명과
아티스트만 표시한다.

- `←` / `→`: 이전·다음 곡으로 이동하고 그 곡의 첫 난이도에 포커스를 둔다. 플레이를 마치고 선곡 화면으로 돌아오면 같은 곡의 플레이한 난이도에 포커스가 남는다.
- `↑` / `↓`: 펼쳐진 카드의 난이도 포커스를 이동한다.
- 마지막 난이도에서 `↓`: 다음 곡을 펼치고 첫 난이도에 포커스를 둔다.
- 첫 난이도에서 `↑`: 이전 곡을 펼치고 마지막 난이도에 포커스를 둔다.
- `Enter` / `Space` 또는 `GO`: 곡과 난이도가 모두 유효할 때만 gameplay로 간다.
- 펼쳐진 난이도 행 클릭: 다른 난이도는 선택만 하고, 이미 선택된 난이도를 누르면 같은 검증/진입 경로로 실행한다.
  곡 카드 클릭은 포커스만 바꾸며, 옵션 패널이 열려 있으면 뒤쪽 클릭은 차단한다.
- `Escape` 또는 `BACK`: Logo Scene으로 돌아간다.
- 옵션 톱니 또는 `Ctrl+O`: 왼쪽 옵션 패널을 열고 닫는다. 패널이 보이는
  동안 뒤쪽 곡·난이도·검색 입력은 멈춘다.
- `Play options` 또는 `F1`: 플레이 옵션 패널을 연다(게임 곡 선택에만 있다). 패널이 열려 있으면 `F1`은 닫기(적용),
  `F2`는 패널 항목만 기본값으로 되돌린다(Reset과 같음, 사용자 지시, osu!의 모드 선택 관례).

카드가 펼쳐지거나 접힌 뒤에는 scroll offset을 자동 보정해 포커스된 카드 전체가
viewport에 들어오게 한다. 패턴이 없는 음악도 실제 catalog 항목으로 표시한다. 펼친 카드의 난이도 자리에
숫자 글꼴 `NO DIFFICULTIES`(모든 언어에서 같은 영어 문구)를 두고 상세의 곡명·아티스트·재킷은 유지하되
난이도·수치·기록 칸은 비운다. 이 상태에서는 `GO`가 꺼지고 `↑`/`↓`는 그 곡을 한 칸으로 지나간다.
곡이 하나도 없으면 목록 자리에 `NO DIFFICULTIES` 한 줄만 두고 기록·정보 칸은 비운다.
검색·필터·폴더로 목록이 비면 `NO SONGS AVAILABLE` 문구를 표시한다. 이때 기록·정보 칸도 비는 것은 예전 동작 그대로이며,
설계의 "기록·정보 칸 유지"는 아직 구현하지 않았다.

## 검색과 정렬

검색창을 클릭하거나 `Ctrl+F`를 누르면 일반 텍스트를 입력할 수 있다. `Ctrl+F`는 기존 검색어를
전체 선택한다. Windows Unicode 편집기를 검색창 안에 배치하며 한글·일본어 IME 조합/후보창,
커서 이동·마우스 선택·Backspace/Delete·잘라내기/복사/붙여넣기를 표준 편집 동작으로 처리한다.
확정 문자열이 바뀌면 검색 결과를 갱신한다. 조합 중 Enter/Escape는 IME에 전달하고, 조합 밖에서는
검색 편집만 끝낸다. 검색창에 포커스가 있으면 방향키·공백·Enter/Escape로 곡 이동/플레이/뒤로 가기를
실행하지 않는다. Scene/옵션/추가 메뉴에 가려질 때 native 편집기도 숨기고 포커스를 해제한다.
편집기의 수명은 MusicSelectView가 소유하고 shutdown에서 창보다 먼저 해제한다.
창이 없는 표시 테스트에서는 Canvas 문구만 사용한다.
곡명의 모든 표기, 모든 아티스트 표기, YMM 곡 태그와 YMP 패턴 태그를 검색한다.
검색어는 공백으로 나누고 대소문자를 구분하지 않는 부분 일치를 AND로 결합한다.
`angel`만 입력해도 `Angel Dream`이 결과에 나온다. `angel dream`처럼 두 단어를 입력한 경우에는
`angel`과 `dream`이 모두 있어야 하며 순서는 상관없다. 두 단어가 제목과
아티스트 등 서로 다른 필드에 있어도 일치한다. 연속·앞뒤 공백은 무시하고 빈 검색어는 전체 목록이다.
IME의 전각 공백도 단어 구분으로 처리하며 Unicode 대소문자는 invariant lowercase로 비교한다.
텍스트 검색 결과의 단위는 곡이다. 패턴 태그로 곡이 일치해도 텍스트 검색 자체는 패턴 목록을 자르지 않는다.
검색 때는 로드된 목록 메타데이터만 사용하고 YMM/YMP 파일을 다시 읽지 않는다.

SceneStateTests는 단일 단어/부분 일치·AND·외국어/Unicode 대소문자 비교를 검사한다.
RunMusicSelectViewTests는 숨김 D3D12 창의 실제 편집기에 Unicode를 삽입하고 결과 갱신,
편집 키 차단·조합 명령 분리·옵션 숨김·handle 해제를 자동 검사한다.
자동 검사는 실제 키보드 IME 후보 선택이나 사용자 클립보드를 조작하는 수동 검증을 포함하지 않는다.

정렬 선택기는 `난이도순`, `곡 이름순`, `아티스트 이름순`, `Base BPM순`을 제공한다. 현재
클라이언트 계산 난이도가 미계산 상태이므로 `난이도순`은 catalog 순서를 보존한다.
노트 수나 판정 범위를 난이도로 오인해 가짜 순위를 만들지 않는다.
`Base BPM순`은 목록에 로드된 각 곡의 첫 패턴 `baseBpm`을 기준으로 숫자 오름차순 정렬한다.
다른 패턴의 BPM이나 변속 범위는 정렬 키로 사용하지 않는다. 같은 BPM은 기존 catalog 순서를
유지하며 패턴이 없거나 유효한 기본 BPM이 없으면 뒤에 둔다. 검색 결과에도 동일한 정렬을
적용하고 정렬/언어 변경 후에도 선택한 곡과 정렬 항목을 유지한다. YMP에서 BPM을 생략한 경우는
기존 파서 기본값을 따르며 정렬을 위한 파일 재읽기나 포맷 변경은 없다.
SceneStateTests와 RunMusicSelectViewTests가 숫자 순서·동률·첫 패턴 기준·검색 결합,
드롭다운의 실제 선택과 언어 전환을 검사한다.

정렬 옆 `필터` 버튼은 곡 필터 창(평평한 모달, 폭 560, [UI-02](../Design/Decisions.md#ui-02-ui-리디자인))을 연다.
맨 위 Game mode는 실제 catalog에 등록된 값 중 하나 또는 전체를 고르는 드롭다운이다. 그 아래 줄마다 스위치·이름·Minimum·Maximum이 있다.

| 줄 | 값 | 빈 값·모름 |
| --- | --- | --- |
| Note count | 0 이상의 정수, 실제 기본 플레이 세션의 논리 노트 수 | 집계 미상 패턴은 범위를 지정하면 제외 |
| Base BPM | 0 이상의 유한한 수, 패턴의 `baseBpm`(변속 범위가 아님) | |
| JudgeLevel | 1–100 | |
| Difficulty | 유한한 수, `calculatedDifficulty` | 미계산은 어떤 범위에도 맞지 않음. 계산값이 없으면 줄 전체가 꺼진 모양 |
| HP | 1–100, 패턴의 HP(누락 시 9.00) | |
| Length (s) | 0 이상의 초, 채보 길이(첫 노트부터 마지막 노트 항목까지, 롱노트 끝 포함) | 노트가 없는 패턴은 범위를 지정하면 제외 |
| Tag | 태그 하나(Minimum·Maximum 자리를 한 칸으로 씀) | 곡(YMM)이나 패턴(YMP) 태그 중 하나와 대소문자 없이 같으면 맞음. 일부만 같으면 아님 |

조건식을 직접 쓰는 입력은 사용자 결정으로 두지 않는다. 빈 경계는 제한 없음이며 경곗값을 포함한다. 최소가 최대보다 크거나
입력이 유효하지 않으면 바닥 위 빨간 줄에 오류를 표시하고 기존 적용 조건을 보존한다. 켜진 줄의 조건은 같은 패턴에서 AND로
결합하며, 일치하는 패턴만 곡 카드에 표시하고 그런 패턴이 없는 곡은 제외한다. 텍스트 검색·정렬과 함께 적용하고 원본 catalog 및
플레이 진입용 패턴 인덱스는 유지한다.

값이 있는 줄은 줄 앞 스위치로 켜고 끈다. 빈 줄에 값을 넣으면 스위치가 저절로 켜지고, 스위치를 끈 줄은 값을 남긴 채 조건에서
빠진다. 꺼진 줄의 값을 고쳐도 다시 켜지지 않으며, 값을 모두 지우면 스위치가 처음 상태로 돌아가 다음 값에 다시 저절로 켜진다.
값이 없는 줄의 스위치는 꺼져 있고 누를 수 없다. 꺼진 줄의 값도 적용할 때 검사하고, 창을 다시 열면 값과 스위치 상태가 그대로다.

`Apply`/조합 밖 Enter는 조건을 확정한다. `Reset`은 편집 중인 조건만 비우며 적용해야 반영된다.
`Cancel`·✕/조합 밖 Escape/Scene 숨김은 편집을 취소한다. 창이 열린 동안 뒤쪽 검색·목록·플레이·
옵션 단축키는 차단한다. 숫자 입력은 기존 Unicode 편집기를 사용하며 모드 드롭다운을 펼치면
겹치는 native 입력창을 숨긴다. 조건은 선곡 상태에만 보관하고 새 설정 파일은 만들지 않는다.

`SongCatalogPattern::calculatedDifficulty`는 향후 클라이언트 계산용 `optional<double>`이며
초기값은 미계산이다. YMP/YMM와 디스크 인덱스에는 저장하지 않고 난이도 알고리즘도 추가하지
않는다. 미계산은 0과 구별하고 현재 난이도 줄은 비운 채 비활성화한다. 계산값이 제공되면
난이도 범위를 사용할 수 있고 해당 범위에서 미계산/비유한 값은 제외한다. 계산값의 척도는 미정이다.
SceneStateTests와 RunMusicSelectViewTests는 같은 패턴 AND, 실제 인덱스의 클릭/방향키 탐색,
범위 검증과 원자적 적용/취소, HP·Length·Tag 줄과 줄 스위치(값이 생기면 켜짐·꺼진 줄 편집·다시 열기),
실 native 입력의 IME 명령 분리·모달 격리·숨김/해제를 검사한다. SongCatalogTests는 채보 길이와 목록 캐시 복원을 검사한다.

옵션 패널의 한국어/영어 선택은 곡 목록의 고정 문구와 현재 표시 중인 오류
접두사를 즉시 갱신한다. 패널 크기·애니메이션·스크롤과 텍스트 표 구조는
[문구·언어·글꼴 관리](TextManagement.md)에 있다.

## 우클릭 메뉴

게임·에디터 곡 선택에서 곡 카드나 펼친 카드의 난이도 줄을 우클릭하면 osu!처럼 메뉴가 뜬다(사용자 결정 2026-11-22).
우클릭은 왼쪽 클릭처럼 그 곡(과 난이도)을 고르지만 시작하지는 않는다. 메뉴는 포인터 오른쪽 아래의 남색 판(폭 200, 줄 높이 30)이고
화면 밖으로 나가지 않게 옮긴다. 항목을 누르면 실행하고, 메뉴 밖을 누르거나(왼쪽·오른쪽) Esc를 누르면 아무것도 하지 않고 닫는다.
메뉴가 열려 있는 동안 곡 선택의 키와 툴팁은 쉰다. 목록을 읽는 중에는 열지 않는다.

| 항목 | 난이도 줄 | 곡 카드 | 하는 일 |
| --- | --- | --- | --- |
| New difficulty | ○ | ○ | 에디터 곡 선택의 `+`와 같이 그 곡의 [새 난이도](EditorSongSelect.md#새-난이도-생성)를 연다(게임 곡 선택에서도) |
| Edit | 게임 곡 선택만 | — | 그 난이도를 에디터로 연다. 에디터를 나가면 에디터 곡 선택으로 돌아간다 |
| Delete difficulty… | ○ | — | 그 난이도를 휴지통으로(아래) |
| Delete song… | ○ | ○ | 곡 폴더 전체를 휴지통으로(아래) |
| Open folder | ○ | ○ | Windows 탐색기로 곡 폴더를 연다 |
| Collections… | 패턴이 있을 때 | 패턴이 있을 때 | 고른 패턴의 [컬렉션](#컬렉션즐겨찾기-폴더) 관리 창을 연다 |

삭제는 늘 공용 알림으로 먼저 묻는다. 제목은 `Delete difficulty?`/`Delete song?`, 설명(선택 언어)은 휴지통으로 가며 거기서 되살릴 수 있다는
문장이고, 상세 상자에 곡(과 `[난이도]`) 이름과 지울 경로를 Songs 기준으로 적는다(폴더는 끝에 `/`). 왼쪽 끝의 `Delete`를 눌러야만 지우고,
`Cancel`·Enter·Esc는 아무것도 바꾸지 않는다. 다른 알림이 그 위에 뜨면 묻던 삭제는 버린다.

- 난이도(`GameFlow/SongDeletion`의 `PlanDifficultyDeletion`): 그 YMP와, 같은 곡의 다른 차트가 쓰지 않는 YME. 그 차트 세트 폴더에
  그 둘 말고 남는 것이 없으면 폴더째 보낸다. 다른 파일이 있으면 그 파일과 폴더는 남는다.
- 곡(`PlanSongDeletion`): YMM이 있는 `Music`의 상위 곡 폴더 전체(음원·BG·모든 난이도).
- 지울 경로는 모두 Songs 폴더 안이어야 하며(대소문자 무시), Songs 폴더 자체나 그 밖은 거부하고 오류 알림을 띄운다.
- 확인하면 Scene이 미리듣기 음원을 놓고 `RecyclePaths`(SHFileOperation, 되돌리기 가능)로 휴지통에 보낸 뒤 목록을 다시 읽는다.
  휴지통에 넣을 수 없는 항목(네트워크 드라이브 등)은 Windows가 영구 삭제 전에 한 번 더 묻는다. 실패하면 `Not deleted` 알림이
  원인을 보여 준다. 기록 DB·컬렉션·곡별 오프셋은 그대로 둔다(해시·경로가 없는 항목은 표시되지 않을 뿐).

`SongContextMenu`는 메뉴 판과 항목, `SongSelectMenu.cpp`는 우클릭 판정(`SongListView::ContextTargetAt`)·항목 실행·삭제 확인을,
`MusicSelectScene`은 Edit·휴지통·탐색기 실행을 소유한다. 회귀: TestSongDeletionPlan(공유 YME, 빈 차트 세트, Songs 밖·Songs 자체 거부, 대소문자),
RunMusicSelectViewTests의 TestSongContextMenu(난이도 줄·곡 카드 메뉴 항목, Esc, Open folder·New difficulty 명령, 삭제 확인의 Enter 취소와
Delete 확인, 넘기는 경로). 실제 휴지통 이동과 탐색기 열기는 사용자 파일을 건드리므로 자동 검사하지 않는다.

## 컬렉션(즐겨찾기 폴더)

osu!의 컬렉션과 같은 기능이다. 화면에는 `Collections`(한국어 문구 `컬렉션`)로 보이고, 코드 이름은 예전 그대로
`SongFavorites*`다. 게임·에디터 선곡 화면의 곡 목록 맨 위에 `전체`와 컬렉션 탭을 표시한다. 탭은 밑줄 탭이고 넘치면
그 영역의 휠이나 탭 아래 높이 8의 공용 가로 스크롤바(끌기·레일 누르기)로 이동한다. 컬렉션을 선택하면 거기 들어 있는 패턴과
해당 곡만 보이며, 기존 텍스트 검색·숫자 필터와 AND로 결합한다. 빈 컬렉션은 빈 결과를 표시한다.
같은 패턴을 여러 컬렉션에 넣을 수 있고 원본 catalog 인덱스로 클릭·키보드 탐색·플레이를 유지한다.
한 컬렉션에서 빼도 다른 컬렉션에는 영향을 주지 않는다. 컬렉션은 이름 순서다(대소문자 무시, 숫자는 값 순서라
`Folder 2`가 `Folder 10`보다 앞).

탭 줄 오른쪽 끝의 ★ 버튼은 선택한 곡/패턴과 컬렉션 목록이 있는 관리 패널을 연다. 왼쪽 체크 칸은
현재 패턴을 넣고 빼며 이름 행은 이름 변경·삭제·내보내기 대상을 고른다. 생성·이름 변경은
기존 Unicode 이름 입력 대화상자를 사용한다. 이름의 앞뒤 공백을 정리하고 빈 이름·제어문자(ASCII C0)와
다른 컬렉션과 대소문자만 다른 이름은 허용하지 않는다. 여러 컬렉션은 목록의 휠·위/아래 버튼으로 탐색한다.
선택 패턴이 없으면 넣고 빼기만 비활성화하고 컬렉션 관리는 계속 제공한다.

아래 줄의 `Import`는 Windows 파일 열기 창에서 컬렉션 파일(`*.json`)을 골라 편집 사본에 더한다.
같은 이름(대소문자 무시)의 컬렉션이 있으면 그 파일의 채보를 합치고(라벨은 비어 있던 것만 채움), 없으면 새 컬렉션이 된다.
상태 줄은 `Imported: 이름 (채보 수)` 또는 `Merged into: 이름 (채보 수)`다. `Export`는 고른 컬렉션을
저장 창에서 정한 곳에 바로 쓴다(기본 파일 이름은 컬렉션 파일 이름과 같음). 내보내기는 편집 사본의 내용이며
적용 여부와 무관하다.

생성·이름 변경·삭제·넣고 빼기·가져오기는 모두 편집 중인 사본에 적용한다. `적용`/Enter로 함께 저장하고
`닫기`/Escape/Scene 숨김으로 전체 편집을 취소한다. 이름·파일 대화상자의 확인/취소 키는 바깥 패널의
적용/닫기나 플레이 명령으로 재해석하지 않는다. 컬렉션 삭제는 그 컬렉션 파일만 지운다.
활성 컬렉션이 삭제되면 `전체`로 돌아간다. 관리 패널은 배경 탐색·플레이·옵션 단축키를 차단하고
native 검색 입력도 숨긴다.

### 저장과 공유

컬렉션 하나가 사용자 Asset 폴더(`UserAssetRoot()`, 배포본은 EXE 옆 `Asset`)의 `Collections/<이름>.json` 파일 하나다.
이 파일을 그대로 주고받거나 Import/Export로 나눌 수 있다. 개발 빌드의 `Client/Assets/Collections/`는 git이 무시한다.
두 선곡 Scene은 진입할 때 폴더를 다시 읽어 같은 컬렉션을 공유하며, 탭 선택 자체는 각 Scene 상태에 둔다.
컬렉션 id는 실행 중에만 있고 다시 읽어도 같은 이름이면 같은 id를 유지해 고른 탭이 그대로다.

- 채보는 경로가 아니라 YMP 파일 내용의 SHA-256(`Catalog/ChartHash.h`, 소문자 16진수 64자)으로 찾는다.
  목록 catalog가 채보마다 `SongCatalogPattern::chartHash`로 계산해 디스크 인덱스에 보관한다. 그래서 곡 폴더를 옮기거나
  다른 사람의 Songs 폴더에서도 같은 채보를 찾는다. 채보 파일을 고치면 해시가 바뀌어 컬렉션에서 빠진다(osu!와 같음).
- 파일 이름은 컬렉션 이름에서 Windows가 허용하지 않는 문자(`<>:"/\|?*`, 제어문자)를 `_`로 바꾸고 끝의 점·공백을 지운 것이다.
  장치 이름(`CON`·`NUL`·`COM1` 등)은 앞에 `_`, 100자 넘는 부분은 자르고, 빈 이름은 `Collection`이다. 다른 파일과 겹치면
  ` (2)`처럼 번호를 붙인다. 컬렉션의 진짜 이름은 파일 안의 `name`이다.
- 적용하면 바뀐 컬렉션 파일만 원자적으로 바꿔 쓰고, 그다음 삭제·이름 변경으로 쓰지 않게 된 파일을 지운다.
  쓰다 실패하면 아무 파일도 지우지 않고 오류를 표시하며 디스크에 있는 상태를 다시 읽는다.
- 읽을 수 없는 파일은 건너뛰고 관리 패널에 이름을 알리며 덮어쓰지 않는다. 같은 이름의 파일이 둘 이상이면(받은 파일을 폴더에
  바로 넣은 경우 등) 하나의 컬렉션으로 합치고, 그 컬렉션을 다음에 저장할 때 이름과 맞는 파일 하나로 모은 뒤 나머지를 지운다.
  폴더 자체를 읽지 못하면 저장을 막는다.
- 지금 없는 채보도 컬렉션에서 저절로 지우지 않는다. YMP/YMM은 바꾸지 않는다.

파일은 UTF-8 JSON이다(BOM 허용, 멤버 순서 무관, 중복·모르는 멤버는 거부).

```json
{
  "format": "YOUMU collection",
  "version": 1,
  "name": "練習",
  "charts": [
    {"sha256": "ba7816bf…", "title": "Angel Dream", "artist": "Takahashi yoko", "pattern": "Oni"}
  ]
}
```

`title`·`artist`·`pattern`은 받는 사람이 없는 채보를 알아보도록 넣는 라벨이며 생략할 수 있다. 채보를 넣을 때 곡의 첫 이름·
첫 아티스트·패턴 이름을 적고, 관리 패널을 열 때 라벨이 없는 채보는 목록에 있으면 채운다(적용하면 저장).

### 예전 favorites.json

예전 버전은 `Option.ini` 옆 `favorites.json` 하나에 모든 폴더를 패턴 경로로 저장했다. 처음 읽을 때 한 번 옮긴다.

1. 폴더마다 같은 이름의 컬렉션을 만들거나(이미 있으면 합침) 각 경로의 채보 파일을 읽어 해시로 넣는다.
2. 컬렉션 파일을 다 쓴 뒤 `favorites.json`을 내용 그대로 `favorites.v1.json`(있으면 `favorites.v1 (2).json`…)으로 이름만 바꾼다.

그 경로에 지금 채보 파일이 없는 항목은 해시를 구할 수 없어 컬렉션에 들어가지 않고 `favorites.v1.json`에만 남는다.
`favorites.json`을 읽지 못하거나 쓰다 실패하면 그 파일을 그대로 두고 관리 패널에 알리며, 다음에 다시 시도한다(합치기라 여러 번 해도 같음).

`SongFavorites`는 컬렉션 폴더의 읽기·저장·옮기기, `SongFavoritesValues`는 편집 사본,
`SongFavoritesJson`은 컬렉션 파일과 예전 파일의 고정 스키마 JSON 경계를 소유한다. `SongFavoriteTabs`는 가로 탭과 스크롤,
`SongFavoritesPanel`은 관리 편집과 Import/Export(파일 창은 `CollectionFilePicker`로 바꿀 수 있음)를 소유하고
`SongSelectionState`는 기존 필터에 컬렉션 소속을 결합한다. 회귀:

- TestSongFavoritesPersistence: 파일 이름, 저장·복원, 이름 변경·삭제의 파일 정리, 쓰기 실패, 읽을 수 없는 파일, 같은 이름 파일 합치기,
  내보내기·가져오기·합치기, 손상·미래 버전 파일.
- TestSongFavoritesMigration: favorites.json 옮기기, 없는 채보, 한 번만, 읽을 수 없는 예전 파일.
- TestSongFavoriteSelection: 해시로 필터.
- TestSongCatalogIndex: 채보 해시와 디스크 인덱스.
- RunMusicSelectViewTests: 실제 이름 입력과 관리/탭/모달 동작, 넣은 채보의 라벨, Export·Import(파일 창 대신 테스트 응답).

## 실행 데이터

행에는 `SongCatalog`가 읽은 실제 제목과 아티스트만 사용한다. `GO`는 선택한
`SongCatalogPattern`의 YMP/YME 경로, YMM이 가리키는 음악 경로와 mode를 기존
`GameplayLaunchStore::SetValidated`에 기록한 뒤 `DestroyOnExit` gameplay Scene으로 전환한다.
진입한 Scene은 `Snapshot()`으로 독립적인 `GameplayLaunchRequest` 사본을 받는다.
Catalog 탐색은 파일별 오류를 격리하므로 손상된 YMM/YMP/YME 또는 누락된 음원은
진단을 남기고 해당 항목만 제외한다. `GO` 직전에도 선택 패턴을 한 번 검증하며,
실패하면 Scene을 전환하지 않고 GO 바로 위 말풍선에 오류를 표시한다. 성공하면 검증한
PlaySession의 소유권을 gameplay controller로 한 번 넘겨 같은 파일을 다시 읽지 않는다.
카탈로그 worker는 공유 `SongLibrary`가 처음 초기화될 때(보통 타이틀 첫 진입, smoke처럼 곡 선택에 바로 들어오면
그 Initialize) 시작하고, 곡 선택 재진입에서도 외부 편집을 반영한다. 같은 Songs 폴더를 다시 훑을 때는 지금 목록과
선택을 그대로 둔 채 새 항목으로 갈아 끼우고, 폴더가 바뀌면 빈 목록에서 다시 시작한다.
SongCatalogLoader는 복사한 경로와 파서 캐시만 worker에 넘기며 Scene/엔진 pointer를
참조하지 않는다. 검증이 끝난 곡 메타데이터와 패턴을 탐색 중 바로 추가하고 첫 로딩 전용 문구를
두지 않는다(LOAD-01). 첫 탐색 중 곡이 아직 없으면 목록을 비워 두고, 패턴이 추가되지 않은 곡은 `NO DIFFICULTIES`로
표시한다. 읽힌 패턴은 전체 탐색 중에도 선택하고 플레이/편집기에 진입할 수 있다. 카탈로그
탐색은 KeepAlive Scene에서 계속되며 같은 루트의 진행 중 작업은 재진입 때 유지한다.
새 난이도 생성·가져오기는 전체 탐색 완료 후에 허용한다. 부분/최종 목록이 바뀌어도 선택한
곡·패턴의 경로와 검색·필터를 유지하며 루트가 바뀌면 이전 세대의 결과를 버린다.
런타임은 `SongCatalog::MetadataIndex`로 목록용 문서와 노트 수·진단만 보관하며,
수정 시각/크기가 같은 문서는 사용자 캐시 폴더의 디스크 인덱스에서도 재사용한다.
추가/삭제 파일과 음원·YME 의존성은 매 갱신에서 확인한다. 포맷 변경 시 캐시 무효화
규칙과 소유권은 [자원 로딩](ResourceLoading.md)에 있다.
GO의 검증·세션 생성도 `PlaySessionLoader` worker에서 실행하고 완료 결과만 게시한다.
대기 중 다른 패턴으로 이동하거나 화면에서 나가면 이전 진입 결과는 적용하지 않는다.
MusicSelectView는 행 배치 metadata와 실제 카드를 구분하여 viewport 인근 행만 만든다.
포커스/검색/정렬/스크롤/resize는 기존 조작 규칙을 유지한다.

## 미리듣기와 타이틀 플레이어

`YOUMUGame`이 `SongLibrary`(SongCatalogLoader·SongSelectionState·SongPreviewController·Songs 루트) 하나를 갖고
타이틀(`YOUMULogoScene`)과 게임 곡 선택(`LobbySceneId`)이 함께 쓴다. 에디터 곡 선택은 자기 `SongLibrary`를 따로 가지며
타이틀의 곡을 이어받지 않고 그 화면의 선택 곡을 새로 재생한다. 켜져 있는 화면이 목록 진행분 반영·완료 처리와
재생 갱신을 같은 코드로 돌리므로, 어느 쪽이 먼저 열려도(smoke 경로 포함) 동작한다.

- 재생기는 곡을 catalog 인덱스가 아니라 음원 경로로 식별한다. 목록이 갱신되거나 순서가 바뀌어도 같은 곡이면 소리가
  끊기지 않는다. 포커스한 곡 = 재생할 곡이며, 타이틀의 현재 곡이 곧 곡 선택의 선택 곡이다.
- 미리듣기는 엔진의 StreamAsync로 열고 준비가 끝난 다음 200ms fade로 재생한다. 선택이 바뀌면 이전 로딩의 완료를
  확인해 폐기하고 최신 선택을 시작한다. 로딩/정지 직후의 clip은 안전한 release 상태가 될 때까지 보관하고, 종료 때 남은
  것은 `AudioSystem::RetireClip`에 넘긴다. 실패 파일은 매 Update 재시도하지 않고 다른 선택·재생 버튼·Scene 재진입에서
  다시 시도한다.
- 재생 상태(`MusicPlayerState`): 재생/일시정지, 정지(멈추고 처음으로), 위치 이동, 현재 위치·길이. 위치는 재생 중
  흐른 시간을 누적해 얻고, 이동은 같은 voice를 `startPositionMicroseconds`로 다시 시작해 스트림이 준비된 뒤 이어 재생한다.
- 곡 끝: 곡 선택은 그 곡을 처음부터 반복하고, 타이틀은 다음 곡으로 넘어간다. 화면이 바뀌는 즉시 그 화면의 규칙을 따른다.
- 곡 선택은 들어올 때 일시정지·정지된 곡도 다시 재생한다(포커스한 곡이 없으면 소리를 끈다).
- 화면 간 연결: 타이틀 → 게임 곡 선택(Game Start)과 게임 곡 선택 → 타이틀(Back)은 곡과 소리를 그대로 이어 간다.
  로딩·플레이·결과·에디터 곡 선택·에디터·`.osu` 가져오기·새 난이도로 갈 때는 소리를 멈추되 곡 선택은 남긴다.
  결과에서 곡 선택으로 돌아오면 그 곡을 처음부터 다시 재생한다.
- 곡 목록의 "재생 중" 표시는 선택 카드의 금빛 막대다(위의 카드 절).
