# 플레이 화면·노트 표현

`Client/Presentation/LaneKeyBeam`은 Lane 자식 `Lane.KeyBeam` 스프라이트와
200ms 선형 알파 페이드를 관리합니다. Scene은 등록된 게임 키의 Pressed 입력을
판정한 뒤 `OnKeyPressed(result)`를 전달합니다. 빈 입력/범위 밖 입력 및
정확도 없는 Roll tick은 흰색, 판정 결과는 RPG `AccuracyRange::DefaultAccInfo`의
흰색·하늘색·초록·노랑·보라와 점수 기반 보간, Good 이내 거부된 입력은 적색입니다.
수동 입력 결과만 빔을 시작하므로 자동 Miss나 키 해제는 빔을 생성하지 않습니다.
재입력은 같은 스프라이트의 색상과 알파를 초기화하고 200ms 후 숨깁니다.
페이드는 표시용 deltaSeconds로 진행되며 판정 타이머를 변경하지 않습니다.
옵션 Display 섹션의 키빔 불투명도(0~100%, 기본 100%)는 모든 모드에 공통이며, 시작 요청에 복사된 값을
`GameplayPresenter::ConfigureKeyBeamOpacity`가 `LaneKeyBeam::SetOpacity`로 넘깁니다. 빔의 시작 알파와 페이드 전체에
이 값을 곱하므로 100%는 기존 모습, 0%는 보이지 않습니다. 모드 클래스는 이 값을 다루지 않습니다.
같은 섹션의 배경 밝기(0~100%, 기본 100%)는 시작 요청에 복사되어 `GameplayPresenter::ConfigureBackgroundBrightness`가
배경 그림(그림이 없으면 하늘색)의 RGB에 곱합니다. 0%는 검정, 100%는 그림 그대로이며 알파는 바꾸지 않습니다.
로딩 화면의 배경도 같은 밝기로 그립니다.
`InGame/LaneLight.png`는 Lane 폭에 맞춰 비율을 유지하고 로컬 Y=0에서 시작하며,
Lane 끝에서 clip됩니다. PNG 원본 알파에 1→0의 표시 알파를 곱합니다.
Scene 종료 전에 빔의 observer를 해제하고 Canvas가 노드를 파기합니다.

`RhythmTestScene`은 Lobby가 선택한 YMP/YME를 `TaikoMode`에 전달해 세션을
만듭니다. `DestroyOnExit`이므로 매 플레이마다 새로 생성되고 Escape 또는 패턴
완료 3초 뒤 Result로 이동할 때 Canvas, audio voice, session과 함께 삭제됩니다.
Result로는 값 데이터만 이동합니다. 통계/그래프와 소유권은 [플레이 결과](Results.md)에 있습니다.
`GameplaySessionController::ErrorMessage`는 세션 자동화 오류 또는 오디오 오류를 전달하며,
`GameplayPresenter::PresentErrorMessage`는 공통 HUD에 표시하고 오류가 비면 숨깁니다.
사용자 보간식의 트랙별 정상값 유지/복구 규칙은 [YME](../../Formats/Yme.md)의 보간 절을 따릅니다.

플레이 화면의 기준 시안과 런타임 PNG 자산 원본은 Penpot의
[Gameplay · Sky](https://design.penpot.app/#/workspace?team-id=3be9e5e1-190f-8090-8008-7464803e8b40&file-id=3be9e5e1-190f-8090-8008-7468d9cc1bc8&page-id=618d0170-ff55-8025-8008-80646ceaa9d9)에 있습니다.
세션·이미지·오디오를 준비하는 동안 별도 Canvas에 곡명과 패턴명, 준비된 곡 배경을 표시합니다.
하늘색 준비 막대는 준비된 파일 수만큼 왼쪽부터 채워집니다(사용자 결정 2026-11-25, 파일 수 기준).

- 채보 1개, 플레이 화면 그림(스킨 그림과 곡 배경) 한 장마다 1개, 소리 파일 하나마다 1개로 셉니다. 같은 파일을 쓰는
  여러 소리 id는 한 번만 셉니다. 그림과 소리의 수는 채보를 읽은 뒤에 알 수 있으므로 그전까지 막대는 비어 있습니다.
- 엔진은 그림 준비 요청을 한 번에 하나씩 처리하므로 `GameplayPresenter::PrepareAssets`가 그림을 한 장씩 요청해 셉니다.
  `PrepareImages`가 true를 돌려준 그림만 셉니다.
- 엔진의 준비 자리는 하나이고, 실패는 요청한 쪽이 아니라 다음에 묻는 쪽이 받습니다. 그래서 플레이 화면 그림은 로딩 배경이
  끝난 뒤(또는 배경이 없을 때)에만 요청합니다. 어차피 배경이 먼저 줄을 서므로 로딩이 늦어지지 않습니다.
  - 깨진 스킨 그림은 플레이 화면 전에 장면을 멈추고, 로딩 배경은 제 그림을 지킵니다.
  - 깨진 곡 배경은 오류 줄에 경고만 하고, 로딩 배경은 단색으로 남습니다.
  - 전에는 깨진 곡 배경의 실패를 플레이 화면 그림 요청이 받아 장면이 멈출 수 있었습니다.
  - GameplayPauseTests `--broken-skin-image`·`--broken-chart-background`가 두 경우를 확인합니다.
- 파일 하나 안의 진행(음악 디코드, Accelerate의 BGM 음정 유지 변환)은 세지 않습니다. 큰 음악 파일을 준비하는 동안
  막대는 그 칸 앞에서 멈춰 있습니다.
- 준비가 끝나면 막대는 가득 찬 채로 시작 대기(아래)가 끝날 때까지 남습니다. 남은 시간 표시나 금빛 막대는 없습니다.
- GameplayPauseTests의 cold-start 경로가 확인합니다: 처음 디코드하는 소리를 기다리는 동안 막대는 일부만 차 있고,
  줄어들지 않으며, 준비가 끝나면 가득 찹니다.

로딩 BG 준비는 Scene 초기화에서 전체 플레이 이미지·오디오 준비보다 먼저 시작합니다.
선곡에서 공통 이미지 관리자에 등록한 BG는 초기화 중 동일 handle을 바로 연결하므로 첫
로딩 프레임부터 표시합니다. 미등록 BG는 기존 비동기 준비를 사용하고 준비되는 즉시 연결합니다.
BG 없음·실패 시 기존 기본 바탕을 유지하며 자원 준비·음악 시작 조건을 유지합니다.

로딩 화면 오른쪽에는 **플레이 설정 판**이 있습니다(사용자 지시, rhythmgameUI 시안 `proposals/play-settings` A안 선택,
osu!lazer 플레이어 로더와 같은 방식). `GameplayLoadingSettings`가 자기 Canvas(층 9, 일시정지 메뉴 아래)를 소유합니다.

- 배치(1280×720 논리): 폭 304·높이 182의 남색 판(86%)을 오른쪽 끝에서 40 안쪽, 세로 가운데에 둡니다. 제목 `플레이 설정`,
  `배경 밝기` 슬라이더(금빛 채움·흰 손잡이·값 %), `개별 오프셋` 칸(−·값 ms·+), 키 안내, 금빛 대기 안내 줄 순서입니다.
- 배경 밝기: 끄는 동안 플레이·로딩 배경에 바로 적용하고, 놓을 때 Option.ini의 `BackgroundBrightness`에 저장합니다.
- 개별 오프셋: −/+ 버튼이 5 ms(Alt 1 ms, Shift 20 ms)씩 바꾸며 키보드 `+`/`-`와 같은 규칙입니다([개별 오프셋](Audio.md#개별-오프셋)).
- 시작 대기(사용자 결정, `LoadingStartWait`가 정해 `GameplaySessionController::SetStartHeld`로 넘김): 준비가 끝나도
  아무 동작 없이 3초가 지나야 시작합니다. 동작은 마우스 이동·버튼·휠과 키 누름(오프셋 `+`/`-` 포함)이고, 놓는 것은
  동작이 아닙니다. 마우스를 움직이는 동안, 포인터가 판 위에 있거나 슬라이더를 끄는 동안, 게임 창이 활성 창이 아닌 동안은
  계속 기다리고, 멈추거나 판을 벗어나거나 창으로 돌아오면 3초를 다시 셉니다(포인터가 다른 화면으로 나가 멈춰도 같습니다).
  Enter를 한 번 더 누르면 판 위에서도 바로 시작합니다. 음악은 준비된 채 기다립니다. 남은 시간은 따로 표시하지 않습니다.
  - 3초는 로딩 화면이 뜬 때부터 셉니다. 준비에 3초 넘게 걸리는 동안 아무 동작이 없었으면 준비가 끝나는 즉시 시작합니다.
  - 일시정지 메뉴(Esc)가 열리면 셈을 멈추고, 닫히면 3초를 다시 셉니다.
  - 일시정지 메뉴의 Retry와 재시작 키로 다시 뜬 로딩 화면은 3초를 기다리지 않습니다. 판 위의 포인터와 Enter만 적용합니다.
    결과 화면의 Retry는 플레이 화면을 새로 열므로 처음 들어올 때처럼 3초를 기다립니다.
- 판은 시도의 시계가 처음 흐르기 전까지(Retry 뒤 로딩 포함) 보이고, 일시정지 메뉴가 열리면 숨깁니다. 실제 곡이 아닌
  데모·디버그 진입에는 나타나지 않습니다.
배경은 Gameplay와 동일하게 원본 비율을 유지하면서 화면을 채우고 YMP 오프셋을 적용합니다.
선택 채보의 정적 BG는 선곡·플레이·리절트 화면에서 공통으로 사용합니다. BGA·MP4 등 추가 그래픽
포맷과 영상 재생은 사용자가 아직 지정하지 않았습니다. 배경은 기존 이미지 경로 계약을 사용합니다.
실제 플레이 Canvas는 자원 준비 후 Gameplay 상태에서 표시합니다.
기존 곡 선택 화면의 Sky 색상과 타이포그래피를 유지하면서 짙은 밤하늘색 Lane,
ScrollGear 프레임, 마디선, 입력 키, 키빔, 롱노트 tick과 롤/큰 롤/Balloon/DengDeng 남은
횟수 표시를 한 화면 계층으로 구성합니다.

입력 패널의 네 키는 Penpot 원본 좌표를 2/3로 축소해 배치합니다. 판정원 중심은
입력 패널 오른쪽에서 Lane 높이의 절반만큼 떨어져 있어, 중심에서 입력 패널과
Lane 위·아래까지의 거리가 같습니다. Lane과 ScrollGear 표면은 오른쪽 논리 화면
끝까지 이어지고 마지막 `Lane.png` 타일만 UV로 잘립니다.
기어의 바깥 테두리 하단은 화면 중앙 가로선(Y=0)에 맞춥니다. `ScrollGear` 부모 아래에
테두리·배경·`ScrollGear.Lane`·`InputPresentation`을 두고, 기어 전체의 이동은 이 부모의
Transform 한 곳에서 지정합니다. Lane 아래의 노트·판정원·키빔과 입력 패널 아래의 키
오버레이도 이 변환을 상속합니다. 선택 스킨의 Lane 폭과 입력 패널 높이 중 큰 값에
테두리 여백을 반영해 부모 높이를 계산합니다. 세로 고정 Canvas이므로 16:9의 해상도
변경이나 다른 화면비에서도 같은 중앙선 기준을 유지합니다. 화면 배경·진행바·정확도와
화면 하단 타이밍 인디케이터는 기어 밖의 HUD로 유지합니다.

## 인게임 World 부모·자식 관계

아래는 실제 표시 노드의 Transform 계층입니다. `*`는 여러 개, 괄호는 노트 종류나
표시 상태에 따라 생성되는 요소입니다. Canvas의 비표시 앵커는 생략했습니다.

```text
플레이 Canvas 루트 (화면 중앙 원점, +Y 위쪽)
├─ Background                         화면 배경
├─ ScrollGear                         기어 전체의 위치·회전·배율
│  ├─ ScrollGear.Border               기어 띠(`Gear.Band`, 화면 왼쪽 끝부터 오른쪽 끝까지)
│  ├─ ScrollGear.Lane                 레인 로컬 +Y, Taiko에서 -90° 회전
│  │  ├─ Lane.SurfaceTile *           레인 배경 타일
│  │  ├─ Lane.KeyBeam                 입력 키빔
│  │  ├─ Lane.Highlight                    레인 크기로 잘린 Highlight 빛의 부모
│  │  │  └─ Lane.Highlight.Glow            판정원 뒤 호박색 빛
│  │  ├─ Lane.JudgementCircle         판정원
│  │  │  ├─ Lane.JudgementCircle.Highlight 같은 판정원 그림의 옅은 금빛 덧그림
│  │  │  ├─ Lane.JudgementCircle.HighlightRing 바깥 금빛 고리
│  │  │  └─ Lane.Judgement.{등급}      MAX/PERFECT/GREAT/GOOD/BAD/MISS/POOR와 Recovery.MAX~GOOD 판정 글자(판정원 바로 위)
│  │  ├─ Lane.MeasureLine *           마디선
│  │  └─ Lane.Notes                   노트 사이의 앞뒤 순서를 격리하는 레이어
│  │     └─ Lane.Note.{id} *          노트별 표시 루트
│  │        ├─ AmbientHead           헤드 (풍선·뎅뎅은 화면에 바로 서도록 반대로 회전)
│  │        ├─ UntintedOverlay        헤드 무채색 덧그림 (일반 이미지)
│  │        ├─ AmbientBody / BodyOverlay 롱노트 몸통 (해당 종류)
│  │        ├─ AmbientTail / TailOverlay 롱노트 테일 (해당 종류)
│  │        └─ LongNote.Tick *        현재 보이는 미처리 틱 (해당 종류)
│  └─ InputPresentation
│     └─ Input.Panel                  키 오버레이 바탕
│        ├─ Input.Key.Glow ×4         강/약 키 점등
│        ├─ Input.Key.Face ×4         키 이미지
│        └─ Input.Key.PressFlash ×4   첫 번째 할당 키를 누를 때 흰 섬광
├─ Hud.GameProgress                   하단 진행바 바탕
│  ├─ Progress.Track / Progress.Fill / Progress.Marker
│  └─ Progress.CurrentTime / Progress.TotalTime
├─ Hud.Accuracy                       정확도 텍스트
├─ Hud.JudgementGuide                 화면 하단 타이밍 인디케이터
│  ├─ Judgement.Panel.0~4             반투명 판(Hud.TimingPanel을 날개·띠·가운데·띠·날개로 잘라 붙임)
│  ├─ Judgement.Margin / Judgement.Band.0~4
│  ├─ Judgement.Caption.0~1           EARLY / LATE
│  ├─ Judgement.Zero                  0 기준선
│  ├─ Judgement.HitLine.0~63          타격 막대(판정 색, 반투명)
│  └─ Judgement.Average / Judgement.AverageUnit   평균 오차와 단위
├─ Hud.NoteProcessing.{id} *          중앙 풍선/뎅뎅 처리 그림(완료 연출 포함)
├─ Hud.NoteCounter.{id} *             롤·큰 롤·풍선·뎅뎅의 남은 타격 수 배지
│  └─ RemainingHits                   남은 타격 수 텍스트
└─ Debug.NoteState                    Debug 구성의 상태 텍스트

└─ Center 앵커 → Hud.ErrorLine
   └─ Hud.Error                       흰 막
      ├─ Hud.Error.Mark / Hud.Error.Icon 왼쪽 빨간 표지와 경고 아이콘
      ├─ Hud.Error.Kind               종류(영어 캡션)
      ├─ Hud.Error.LocationChip       파일 경로와 행(고정폭 글자, 없으면 숨김)
      │  └─ Hud.Error.Location
      └─ Hud.Error.Cause              원인

└─ Center 앵커 → Pause.Root
   ├─ Pause.Dim                       화면 어둡게 덮기
   └─ Pause.Panel                     메뉴 컨테이너
      ├─ Pause.SkinPanel              사용자 스킨의 전체 패널 (지정 시)
      └─ Pause.Row.0~3                각 행의 테두리 또는 사용자 스킨
         ├─ Pause.RowFill             선택/일반 상태 바탕
         ├─ Pause.0~3                 Resume / Rewind / Retry / Retire 실행 영역
         │  └─ Pause.Label            액션 이름
         └─ Pause.Selector            Resume/Rewind 값 선택기
            ├─ Pause.SelectorFill
            ├─ Pause.{0/1}.Previous/Next
            │  └─ Pause.Arrow → Pause.ArrowStroke ×2
            └─ Pause.Label            현재 값
```

`ScrollGear`의 Transform을 바꾸면 그 아래의 모든 표시 요소가 함께 이동합니다.
레인의 회전은 레인 하위에만 적용되므로 입력 키 이미지는 같은 기어 아래에서도 바로 서 있습니다.
판정 글자와 레인 위 풍선·뎅뎅 헤드는 판정원·노트를 따라가되 Taiko의 레인 회전을 반대로 보정하여 세웁니다.
중앙 풍선/뎅뎅 처리 그림과 남은 타격 배지, 하단 타이밍 인디케이터, 일시정지 메뉴, 화면 오류 줄은 화면 기준 UI입니다.

Canvas가 표시 노드를 소유하고 `GameplayPresenter`는 비소유 포인터만 보관합니다.
`Shutdown`은 포인터를 해제한 뒤 소유 Canvas handle을 반납합니다. 판정용 노트·타이밍·점수는
`PlaySession` 데이터이며 World 계층에는 해당 노트의 표시 노드만 들어갑니다.

타격 막대 노드 64개(`Judgement.HitLine.0~63`)는 초기화 때 한 번 만들고 재사용합니다. 수명·개수는
[판정 인디케이터](#판정-인디케이터와-판정-글자)에 있습니다. 자동 MISS·빈 입력·타이밍 없는 연타는 막대를 만들지 않습니다.
resize에서 살아 있는 막대 모두 같은 시간→좌표 변환으로 갱신합니다.
키 오버레이의 누름 섬광은 Ambient 색을 곱하지 않은 흰빛이며, 키 점등만 동 적색·캇 청색 Ambient를 사용합니다.
레인 판정 키빔의 판정별 색상 정책은 유지합니다.

YMP의 BG/offset은 그 YMP가 속한 곡 폴더의 `BG` 이미지와 화면 중심의 +Y 위쪽 좌표입니다.
기존 Background 노드에 이미지를 연결하고 비율을 유지한 cover 크기로 표시합니다.
오프셋을 반영한 상태에서도 화면 밖까지 덮도록 resize 때 배율을 갱신합니다.
상세 문법과 선택 필드의 실패 처리는 [YMP](../../Formats/Ymp.md)를 참고합니다.

## 노트 스크롤과 자산

노트가 처음 표시되는 위치는 고정 픽셀 거리가 아니라 현재 Canvas 논리 폭으로
정해지는 Lane 길이와 가장 큰 노트 head의 반지름에서 계산합니다. Taiko의 회전된
Lane에서는 head 전체가 화면 오른쪽 경계 밖에 있을 때부터 왼쪽 판정점으로
이동합니다. Base BPM에서 16분음표 중심 간격은 기본 노트 이미지 지름의 85%입니다.
별도 스크롤 배율 효과가 없으면 이동 속도는 Base BPM을 기준으로 곡 전체에서
일정하며, BPM 변경이나 delay가 반영된 노트 시각 차이에 따라 화면상 간격이
달라집니다. YME `Separate`는 노트/head의 시각으로 정한 고정 배율이며,
`Whole`은 현재 시각의 공통 속도 배율을 적분한 거리로 표시합니다. 둘을 함께 반영하고
Whole 변경 시 노트가 순간적으로 이동하지 않습니다. 에디터 실시간 뷰도 같은 계산입니다.
플레이 마디선도 시각과 Separate 배율을 가진 스크롤 오브젝트입니다.
TaikoSessionBuilder가 표시 마디 시작 위치에서 배율을 고정하고, GameplayPresenter의
`LaneObjectPosition`이 노트 헤드·마디선·틱의 레인 좌표를 같은 거리 계산으로 구합니다.
마디선과 노트는 동일한 Lane 부모와 중심 pivot을 사용하며 Whole/Separate를 함께 반영합니다.
음수 delay로 잘린 마디는 살아남은 시작 위치를 사용합니다. 느린 마디선도 표시 시간 범위에
포함하므로 화면에 진입한 뒤 늦게 생성되지 않습니다. 마디선에는 노트 판정/오디오 책임을 부여하지 않습니다.
판정과 오디오 예약은 기존의 정수 마이크로초 시각을 계속 사용합니다. 창 크기가 바뀌어도
노트와 롱노트 tick 간격은 유지되며, 출현 위치와 표시 범위만 새 Lane 길이에 맞춥니다.
시작 대기 시간은 최소 2초이고, 낮은 BPM이나 넓은 화면에서 첫 노트가 화면 밖에서
들어올 시간이 더 필요하면 그만큼 늘어납니다.

노트와 플레이 HUD의 배포 기본본은
`YOUMU.Assets/Assets/Skins/Default Skin/InGame`의 PNG입니다. 실행 파일 옆
스킨에서 누락된 파일만 이 내장 기본본으로 대체합니다.
`note.png`, `bignote.png`, `LNBody.png`, `LNTail.png`에는 Don/Kat/Roll Ambient
색상을 곱하고 대응하는 `*Overlay.png`는 흰색 원본으로 위에 그립니다. 일반/큰
롱노트는 서로 다른 body와 tail을 사용하고 Buzz tick은 마름모 자산을 사용합니다.
tail과 tail overlay는 별도로 회전하지 않고, 둥근 면이 위를 향하는 원본 방향
그대로 Lane 부모의 회전만 상속합니다.
기본 히트사운드는 `don.wav`, `kat.wav`, `bigdon.wav`, `bigkat.wav`이며 풍선 완료음은
같은 `HitSounds/TaikoMode` 폴더의 `pop.wav`입니다.
음악은 StreamAsync로 준비한 뒤 하나의 `RhythmTimer`가 가리키는 DSP 시각 0에 예약합니다.
Raw Input으로 발생한 히트사운드는 입력 timestamp를 판정에만 사용하고 즉시
재생합니다. 따라서 QPC와 장치 DSP clock의 장시간 미세 드리프트가 실시간 입력음을
미래 시각으로 예약해 지연을 누적시키지 않습니다.
오디오 초기화·파일 등록·재생 요청이 실패하면 가능한 나머지 파일 등록은 계속하고,
게임플레이 화면 상단에 첫 오류를 표시합니다. 오류는 무음으로 삼키지 않으며 노트
판정 시간축은 오디오 오류와 독립적으로 유지됩니다.

`GameplayPresenter`는 누적 Whole 거리에서 객체별 가시 구간을 한 번 인덱싱합니다.
Separate가 느린 미래 노트 하나가 다른 화면 밖 노트들의 표시 범위를 확대하지 않습니다.
노트/마디선/틱은 같은 거리 계산으로 조회하고, 노트 수명 정리는 표시 세대 번호를 사용합니다.
창 크기나 세션 presentation revision 변경 시 인덱스를 재구성합니다. Scene의 Render가 표시를
갱신하며 Update는 입력·세션·피드백을 처리합니다. 초기 대기 시각은 첫 실제 가시 구간의
진입 거리를 역산하되 최소 2초를 유지합니다.

Scene 진입에서 `PrepareImages`로 선택 스킨과 fallback PNG를 비동기 디코드합니다.
오디오 준비와 병행하고 Canvas를 구성하되 실제 Gameplay 진입까지 플레이 화면을 숨깁니다.
소유권과 준비 순서는 [자원 로딩](../ResourceLoading.md)을 따릅니다.

Lane 표시는 RPG `PlayScene`의 Transform 계층도 유지합니다. 기본 Lane은 로컬
`+Y` 방향으로 아래에서 위로 진행하는 세로 노드이며, Taiko 화면에서는 이 부모
노드 하나만 Z축 `-90°` 회전합니다. 어두운 단색 Lane, 마디선, key beam,
`JudgeLine`, 노트 head/overlay와 롱노트 body/tail/tick은 모두 Lane의 자식이므로
회전을 함께 상속합니다. 업데이트는 화면 X가 아니라 Lane 로컬 Y만 변경합니다.

`InGame` PNG는 1920×1080 제작 크기이므로 1280×720 논리 Canvas에서는 2/3
배율로 표시합니다. `Lane.png`는 원본 비율을 유지한 채 로컬 Y 방향으로 반복하고
마지막 조각만 UV로 잘라 창 폭을 채웁니다. Canvas의 `FixedHeight` 규칙에 따라
실제 1080p 출력에서는 PNG 원본 픽셀 크기로 표시됩니다.

현재 플레이 화면의 노트와 롱노트 파츠 크기는 PNG 메타데이터에서 계산합니다.
Canvas는 `FixedHeight`이므로 창 높이에 비례해 이미지와 글자도
함께 확대·축소되고, 넓은 창에서는 배경과 ScrollGear가 늘어나며 헤더·시간 표시는
각각 좌·우 기준으로 배치됩니다.

현재 플레이 화면은 마디선, key beam, 노트 head,
롱노트 body/tail/tick을 모두 회전된 Lane 부모 아래 둡니다. 마디선은 레인 폭 전체의 2px·50%(`#C7D9E6`) 선으로
노트보다 약한 보조 정보입니다. Balloon과 DengDeng은
일반 롱노트 body/tail 없이 전용 PNG만 사용합니다([UI-02](../../Design/Decisions.md#ui-02-ui-리디자인)): 일반 노트와 같은 원판 × RollGold와 흰 테두리에
풍선은 매듭과 끈, 뎅뎅은 손잡이와 옅은 북면 원만 더한 그림이며, 원판이 그림 위쪽 정사각형이고 매듭·손잡이가 그 아래에 매달립니다
(기본 128×160). 원판 중심이 노트 위치이고 레인 회전과 관계없이 화면에 바로 섭니다. 시작 시각부터 종료 시각까지
입력이 없으면 판정원에 멈추고, 첫 유효 입력부터 화면 가운데 처리 그림(`BalloonProcessing`·`DengDengProcessing`,
같은 모양을 크게 그린 240×300, 논리 160×200)으로 전환합니다. 처리 그림의 원판 중심은 기어 아래 끝에서 144 아래입니다.
Balloon은 `accepted/required` 진행률만큼 0.72→1.10배로 커지고 완료하면 같은 그림이 1.40배까지 커지며
200ms 동안 사라집니다(터짐). DengDeng은 0.6초에 한 바퀴 시계 방향으로 돌고
완료하면 같은 처리 그림을 200ms 동안 페이드아웃합니다. 제한 시간 안에
완료하지 못한 노트는 종료 시각부터 원래 Lane 속도로 판정원을 지나갑니다.
남은 횟수는 남색 블록·금빛 표지·흰 기울인 숫자의 배지(`Hud.HitCountBadge`, 숫자는 게임이 Barlow Semi Condensed로 그림)
하나로 표시합니다. 풍선·뎅뎅은 처리 그림 아래(그림과 14 겹침, 높이 60, 숫자 48px), 롤은 판정원 중심 오른쪽 52·레인 위 끝 2 아래
(높이 38, 숫자 30px)이며 블록 폭은 자릿수만큼 넓어집니다.

입력 패널(`InputPanel`)은 판의 결·나사 명암을 유지한 채 기어 바탕색 `#BAD1ED` 색조로 구운 그림이고, 콤보 라벨은 진한 잉크입니다.
기어 띠(`Gear.Band`)는 사선 결이 있는 코발트 띠로, 화면 왼쪽 끝부터 오른쪽 끝까지 기어 위아래 4px 테두리와 입력 패널 왼쪽을 채웁니다.
입력 패널은 키를 누르는 동안 점등 그림 하나(`KeyLight`)를 표시합니다.
점등 이미지는 흰색 알파 마스크에 노트와 같은 Ambient 색상을 곱하므로 Kat은
청색, Don은 적색으로 표시됩니다. 나머지 할당 키의 약한 불빛은 Ambient 색조와 45% tint 알파를
사용하고, 첫 번째 할당 키의 강한 불빛은 같은 색조의 채도를 높여 100% tint 알파로 표시해
같은 그림에서 tint만으로 강·약 상태를 구분합니다. 키 얼굴은 첫 번째 할당 키를 누르면
약한 색을 1.38배로 밝힌 선명한 색(회색 72% 키 그림에 곱하면 원래 색에 가까움), 나머지 할당 키면 약한 색, 평소에는 기본 색입니다.
첫 번째 할당 키를 누를 때마다 `KeyLight`와 함께 Ambient 색을 곱하지 않은 흰색 `KeyPressFlash` 십자광이
최대 불투명도로 다시 켜지고 0.1초 동안 선형으로 투명해진 뒤 사라집니다. 나머지 할당 키는 섬광 없이 `KeyLight`만 표시합니다.
우측 정확도 표시는 같은 HUD 영역의 동적 텍스트로 노트별 평균을 소수점 둘째 자리까지 표시하고
그 아래는 반올림하지 않고 버립니다(99.999999% → `99.99%`, `100.00%`는 정확히 100%일 때만).
아직 확정된 노트가 없으면 `--.--%`입니다. 플레이·결과·기록·노트 그룹이 같은
`Presentation/AccuracyText.h`의 형식을 쓰며 언어 파일에는 정확도 서식 키가 없습니다.
계산·저장·랭크 판정은 0.000001% 단위 값을 그대로 씁니다([UI-02](../../Design/Decisions.md#ui-02-ui-리디자인)).
정확도는 오른쪽 위 판(`Hud.ScorePanel`, 300×80) 안에서 점수 바로 아래 줄에 라벨 없이 숫자만 두고(osu!와 같은 배치) 점수와 같은 오른쪽
안쪽 여백(31)으로 오른쪽 정렬합니다. 글자 크기는 점수 30, 정확도 20이며, 정확도 줄은 판 안쪽 폭 전체를 잡아 `100.00%`가 들어가므로 판 크기가 흔들리지 않습니다.

HP 게이지는 스킨 부품 다섯 개입니다([UI-02](../../Design/Decisions.md#ui-02-ui-리디자인)). 틀(`Hud.HpGauge.Frame`, 490×24)은 화면 왼쪽 끝에서
시작해 기어 위 16에 놓입니다. 왼쪽 32는 자물쇠 받침이고 그 오른쪽 454×18 칸에 채움을 HP만큼 왼쪽부터 잘라 보입니다(늘이지 않음).
HP가 게이지의 클리어 기준(`HpGaugeState::clearPercent`, 기본 60%) 이상이면 `FillClear`, 미만이면 `FillLow`입니다. 클리어 표시(`ClearMarker`)는
그 기준 자리에 두고, 일시정지 메뉴나 Rewind로 그 시도의 HP가 꺼지면 받침 위에 자물쇠(`Lock`)를 표시하고 채움은 그 자리에 멈춥니다.
숫자는 표시하지 않습니다.

타이밍 인디케이터는 화면 가로 중앙에 두고 0점을 화면 중앙 x에 맞춥니다. 색 띠 가운데는 기어 아래 72이며, 반투명 판
(`Hud.TimingPanel`)이 색 띠·타격 막대·EARLY/LATE·평균 오차를 감쌉니다([UI-02](../../Design/Decisions.md#ui-02-ui-리디자인),
사용자 지시로 판정원 아래 배치를 대체하고, 이후 사용자 지시로 막대 높이 두 배·판·평균 오차를 추가).
하단 진행 막대는 화면 아래 끝 전체 폭의 띠입니다.

Highlight 구간(YME `#Highlight`, `PlaySession::IsHighlightActive`)에서는 판정원을 강화합니다. 같은 판정원 그림을 옅은 금빛(`#FFCF6E` 곱)으로 덧그리고,
뒤에 호박색 빛(`Highlight.Glow`), 바깥에 금빛 고리 한 겹(`Highlight.Ring`)을 둡니다. 빛의 불투명도(0.40+0.25×맥동)와 고리 크기(반지름 51에서 +3)는
박마다 커졌다 줄어듭니다(맥동 = (1 − 박 안의 위치)², 박은 4분음표). 켜고 꺼질 때는 곡 시간 250ms에 걸쳐 페이드하며, 일시정지 중에는
그대로이고 뒤로 이동하면 페이드 없이 새 상태입니다. 빛은 레인 크기로 잘려 입력 패널 위로 번지지 않습니다. `GameplayHighlightView`가 소유합니다.

화면 오류 줄(`UiErrorLine`)은 플레이·로딩 공용입니다. 화면 위 끝에서 20 아래 가운데에 높이 37의 흰 막(96%)과 왼쪽 빨간 4px 표지·경고 아이콘,
종류(영어 캡션: `Effect file`·`Audio`·`Background image`), 파일 경로와 행(Consolas 칩), 원인을 한 줄로 둡니다. 폭은 글자만큼이고 최대
720(좁은 화면은 양옆 32 여백)이며 넘치는 원인은 오른쪽에서 잘립니다. 자기 Canvas(레이어 11)를 가져 일시정지 덮개 위에 뜹니다.
효과 파일 평가 오류는 YME 경로와 행·`[대상] 원인`, 오디오 초기화와 음악·히트사운드 준비 오류는 원인만, 채보 BG를 못 연 경우는 BG 경로와 원인입니다.
효과 오류는 세션 Reset까지 유지되고 판정은 계속됩니다.

## 콤보·점수·판정 누적 HUD

`GameplayStatisticsView`는 키 레이아웃(`Input.Panel`) 하단의 콤보, 오른쪽 위 판 안에서 윗줄의 점수(정확도는
그 아래 줄), 오른쪽 아래 판(`Hud.JudgeCountsPanel`)의 판정별 누적 횟수를 표시합니다. 콤보는 키 레이아웃의
자식이며 키 그림 아래의 빈 공간에 숫자와 `Combo` 문구를 둡니다. 판정 카운터는 4열×2행(MAX·PERFECT·GREAT·GOOD /
BAD·MISS·OK·POOR)이며 이름 앞에 판정 색 점을 둡니다. 화면 가운데의 풍선·뎅뎅 처리 영역은 비워 둡니다.
별도 일시정지 진입 버튼은 추가하지 않습니다.

숫자는 내장 Barlow Semi Condensed 글꼴의 글자이며 값이 바뀔 때만 다시 씁니다. 숫자 PNG atlas는 쓰지 않습니다.

실시간 점수는 **현재 정확도(0–1) × 100,000,000 × 처리한 논리 노트 비율**입니다.
`PlaySession::Score()`는 확정 노트의 정확도 정수 단위 합을 전체 유효 논리 노트 수로
나눠 버림합니다. 100개 중 50개를 MAX로 처리하면 정확도는 100%, 점수는 50,000,000점입니다.
완료나 MISS로 확정된 논리 노트를 처리 비율에 포함하며, 확정 전 또는 빈 채보는 0점입니다.
종료 시점의 이 점수를 리절트 화면에 전달합니다.

콤보·최대 콤보·MAX/PERFECT/GREAT/GOOD/BAD/MISS/OK/POOR 누적은 세션의 결과 수집기가
소유하며 UI는 `PlaySession::Statistics()`의 값만 읽습니다. 콤보는 노트 처리가 완전히 끝났을 때 계산합니다(사용자 결정).
일반·큰·보라 노트는 BAD·early BAD·POOR·[BAD 복귀](Rules.md#bad-복귀-판정) 없이 GOOD 이상으로 완료하면 논리 노트당 1,
롤 계열은 OK(타격·틱을 하나라도 처리한 완료) 시 1을 더합니다. Buzz는 헤드가 깨끗하고 몸통 틱을 하나 이상 처리해야 OK입니다.
큰 노트의 첫 입력과 롱노트의 개별 타격/틱은 별도 콤보가 아닙니다. 그 밖의 완료·MISS는 콤보를 0으로 만듭니다.
POOR나 early BAD는 그 순간 콤보를 바꾸지 않고, 그 노트가 끝날 때 0이 됩니다.

누적 판정의 정의는 [리절트 집계](Results.md#점수와-판정-개수)와 같습니다. Retry/Reset은
현재·최대 콤보와 판정 횟수를 초기화하고, Rewind/뒤로 탐색은 남은 판정 이력으로 다시
계산합니다. Resume은 유지합니다. 최종 점수와 최대 콤보도 같은 결과 데이터를 사용합니다.

## 하단 플레이 진행바

`GameplayProgressView`는 세션 진입 시 실제 생성된 노트의 마지막 head/tail 시각을 한 번
계산합니다. BPM·delay·offset이 이미 적용된 정수 us 시각을 사용하며, 플레이 중에는
`GameplayPresenter::UpdatePresentation`이 전달한 같은 `RhythmTimer` 시각으로 채움과 마커를
갱신합니다. 판정 유예/음원 길이/Result 전환 대기 3초는 100% 기준에 포함하지 않습니다.
0ms가 시작이고 마지막 노트(롱노트는 tail)가 100%입니다. 음수 시작 대기에는 0%,
마지막 시각 이후에는 100%를 유지합니다. 일시정지·재개·Reset·디버그 탐색은 기존 타이머를
따르므로 별도 진행 시계가 없습니다. 노트가 없으면 0%; 마지막 시각이 0ms 이하인 채보는
그 시각에 100%로 전환합니다. 이 경우 시간 문구는 음수 대신 `0:00`입니다.

기본 스킨 `InGame/Progress`의 `Background.png`(1920×54), `Track.png`(1670×9),
`Fill.png`(1670×9), `Marker.png`(21×21)를 독립 Sprite로 조합합니다. 원본은 RGBA PNG이며
바깥 여백은 투명합니다. 채움은 진행률만큼 bounds와 UV를 잘라 표시하고 마커 중심을
같은 끝점에 둡니다. 현재/전체 시간은 별도 `m:ss` 텍스트로 표시하고 현재 시간의
정수 초가 달라질 때만 문자열을 갱신합니다. 전체 시간 문구는 마지막 노트 시각입니다.
기존 문구가 포함된 단일 `GameProgressBar.png`는 제거했습니다.

Canvas는 노드를 소유하며 View는 observer만 보관하고 종료 시 해제합니다.
PNG는 진입 때 등록하고 프레임 갱신에서 파일 읽기/노트 전체 검색/노드 생성을 하지 않습니다.
띠는 `FixedHeight` 논리 화면 폭 전체를 쓰고 화면 아래 끝에 붙습니다(높이 36). 시간 문구는 좌우 32 안쪽에 두고
마커 크기는 이미지의 2/3 기준 배율을 유지합니다. 창 크기가 바뀌어도 아래 끝에 붙어 있습니다.
선택 스킨 INI의 `Progress.*` 이미지 매핑이 우선하며
없는 요소만 내장 기본본을 사용합니다. 부품 크기와 교체 규칙은 [진행 막대 그림](../Assets.md#진행-막대-그림)에 있습니다.
입력/탐색 동작이 없는 표시 전용 진행바이며 판정·오디오·Result 전환 조건은 바꾸지 않습니다.

## 판정 인디케이터와 판정 글자

`GameplayJudgementView`가 화면 하단 인디케이터와 판정원 위 판정 글자의 상태를 소유합니다.
인디케이터는 화면 가로 중앙에 있고 0 기준선이 화면 중앙 x입니다. 색 띠 아래 끝을 기어 아래 78(가운데 72)에 둡니다.
Canvas가 노드를 소유하고 Presenter는 초기화·입력 피드백·표시 시간 갱신·종료만 연결합니다.
기존 NoteEvent의 판정 등급/오차를 읽으며 점수·노트 처리·오디오 동작을 바꾸지 않습니다.

판(`InGame/Hud/TimingPanel.png`)은 그림 그대로 그립니다. 반투명도는 PNG 픽셀의 알파이며 게임은 색이나 불투명도를
곱하지 않습니다. 그림은 판정레벨 50 배치(논리 524×112)입니다. 양쪽 날개에 EARLY/LATE, 가운데 홈 아래로 색 띠
(판 양쪽 안쪽 52, 위에서 44~56)와 타격 막대, 아래 탭(가운데 128×30)에 평균 오차가 들어갑니다. 게임은 그림을 다섯 조각
(왼쪽 128 · 늘이는 띠 · 가운데 140 · 늘이는 띠 · 오른쪽 128)으로 잘라 붙여 날개와 탭의 크기는 그대로 두고 그 사이만
늘이거나 줄입니다. 판 안쪽 폭은 색 띠 폭을 따르되 300보다 좁아지지 않습니다(판정레벨 74 이상에서는 판이 색 띠보다
조금 넓음). EARLY/LATE는 판 안쪽 끝에 맞춥니다. 0 문구는 없으며 0 기준선(굵기 1)이 타격 막대보다 위아래로 2씩 깁니다.

인디케이터는 MAX/PERFECT/GREAT/GOOD/BAD를 각각 독립적인 색 사각형으로 조합합니다.
넓은 BAD부터 작은 MAX까지 중심에 겹쳐 구성하며 색은 LaneKeyBeam의 공통 GradeColor와
같습니다. 0 기준선과 빠름/늦음 문구는 별도 요소입니다.
판정레벨 50에서 BAD 전체 폭은 논리 378px(±90ms)이고 양쪽에 10ms씩 회색 여유를 두어
전체 표시 범위는 ±100ms, 폭 420px입니다. 다른 판정레벨의 기본 범위에 비례해 길이가 바뀌되,
세션 진입 때 정한 범위를 플레이 중 유지합니다. 싱코페이션의 노트별 추가 범위로
길이나 색 구간을 바꾸지 않습니다. 좁은 창/매우 넓은 범위에서는 판 전체가 좌우 20px 여백 안에
들어오도록 배율만 줄입니다.

실제 입력마다 signedError 위치(왼쪽 빠름·오른쪽 늦음)에 세로 타격 막대를 하나 찍고, 범위를 넘으면
끝점에 제한합니다. 막대는 osu! bar hit error meter의 기본값을 따르되 높이를 두 배로 합니다. 굵기 4·높이 48(색 띠 12의 위아래로 18씩 더 김)이고,
색은 그 입력의 판정 색(색 띠와 같은 `LaneKeyBeam::GradeColor`), POOR는 적색 키빔과 같은 `WrongInputColor`입니다.
100ms 동안 불투명도 0→0.6, 굵기 0→4로 나타나고(OutQuint) 이어서 5초 동안 불투명도가 선형으로 0이 되며
굵기도 InQuint로 줄어든 뒤 사라집니다. 막대는 겹쳐 쌓이고 새 막대가 위에 그려집니다. 살아 있는 막대가 50개인데
새 타격이 오면 가장 오래된 막대를 100ms에 걸쳐 지웁니다. 시간은 플레이 중 표시 시간이므로 일시정지 중에는 멈추고,
Retry·Rewind·일시정지 메뉴의 재개 이동처럼 표시를 다시 시작할 때(`GameplayFeedback::reset`)는 모두 지웁니다.

판 아래 탭의 평균 오차는 **지금 인디케이터에 그려진 타격 막대**의 signedError 산술 평균입니다(사용자 지시).
막대를 만드는 입력(판정을 받은 타격과 POOR 막대)이 모두 들어가고, 5초에 걸쳐 다 사라진 막대와 50개 제한으로 밀려나 지워지는 막대는 빠집니다.
막대가 추가되거나 사라질 때 다시 계산하므로, 막대가 모두 사라지면 값도 비고 Retry·Rewind 등으로 막대를 지우면 값도 비웁니다.
결과 화면 Mean(시도 전체의 판정 타격 평균)과는 표본이 다릅니다.
값은 0.1ms 단위로 반올림한 숫자(늦음 `+`, 빠름 `−`(U+2212), 0은 부호 없음)와 작은 단위(`Gameplay.averageErrorUnit`)이고,
그려진 막대가 없으면 `Gameplay.averageErrorEmpty`(`—`)입니다. 글자는 값이 바뀔 때만 다시 씁니다.
범위 밖 입력은 백색 키빔만 생성하고 막대/문구를 시작하지 않습니다.
정확도 없는 Roll/count tick과 키 해제도 타격 막대/일반 판정 문구를 시작하지 않습니다.
자동 MISS는 MISS 글자만 표시하며 입력 시각이 없으므로 막대를 만들지 않습니다.
빠름/늦음 문구는 판의 날개 안, 색 띠 아래 끝보다 37~53 위에 둡니다.

MAX/PERFECT/GREAT/GOOD/BAD/MISS/POOR는 판정 글자만 담은 투명 PNG 7종입니다(사용자 지시로 판정원을
둘러싸던 링을 없앰). 다른 게임 내 부품처럼 1080p 기준 크기로 그리며(픽셀 ÷ 1.5), 글자 아래 끝을 판정원 위
끝보다 6 위에 두고 판정원 중심과 가로 가운데를 맞춥니다(Highlight 고리의 최대 반지름 54보다 바깥).
`InGame/Judgements/<판정명>.png`를 세션 진입 때 등록하고 같은 노드를 재사용합니다.
입력마다 파일을 읽거나 노드를 만들지 않습니다. 판정원 자식이므로 위치·배율을 따르고
Taiko Lane의 -90° 회전을 되돌려 글자를 똑바로 표시합니다.
최근 판정 하나를 200ms 선형 페이드로 표시합니다. POOR 조건은 적색 키빔과 동일한
Good 이내 InputRejected이며 BAD는 기존 조기/늦은 Bad 입력을 표시합니다.
[BAD 복귀](Rules.md#bad-복귀-판정)의 GOOD~MAX 타격은 같은 글자의 아래가 보라로 물든 `Judgements.Recovery.<등급>`
글자(4종)를 보이고, early BAD 상태로 놓친 노트는 MISS 글자를 새로 띄우지 않습니다(이미 BAD를 보였음).
Buzz 몸통에서 반대 색을 눌러 처리하지 못한 틱은 POOR 글자·적색 키빔을 보이지 않습니다.
한 입력에서 이전 노트의 MISS와 다음 노트의 성공이 함께 오면 실제 입력 응답을 우선합니다.
reset/되감기/종료 시 타격 막대와 판정 글자를 숨깁니다.

롤·큰 롤·틱롤·큰 틱롤·풍선·뎅뎅·버즈는 끝날 때 **처리 비율에 맞는 판정 글자**를 같은 200ms 수명으로 표시합니다(사용자 지시).
처리 비율은 그 노트의 정확도(`NoteAccuracy::ScoreRate`: 친 횟수/목표, 성공 틱/전체, Buzz는 헤드 점수 1/2 + 몸통 1/2)이고,
글자는 일반 타이밍 판정의 점수 경계를 그대로 씁니다: 100% MAX, 99% 이상 PERFECT, 90% 이상 GREAT, 그 밖은 GOOD.
타격·틱을 하나도 처리하지 못했을 때와, 헤드는 쳤지만 몸통 틱을 하나도 처리하지 못한 Buzz가 MISS입니다
(`NoteAccuracy::CompletionGrade`). 노트 종류별 분기는 없고
표시 쪽은 확정된 노트 정확도만 읽습니다. 점수/노트 상태/오디오 규칙은 바꾸지 않습니다.
예전의 OK 글자 그림은 쓰지 않아 지웠습니다. 결과 화면의 OK 수는 [Results](Results.md)를 따릅니다.
다른 노트의 실제 입력 판정이 동시에 있으면 기존 입력 우선순위를 유지합니다.
틱 마커는 규칙의 ProcessedTickCount를 ScrollGear snapshot으로 전달받아 처리된 prefix를
그리지 않습니다. 수용/실패된 틱 모두 숨기며, 조기 입력으로 처리된 미래 틱도 즉시 숨깁니다.
시각만으로 처리 여부를 추정하지 않습니다. 표시 틱은 규칙과 같은 시간순으로 정렬하여
음수 delay로 작성 순서와 시각이 다르거나 같은 시각의 틱이 둘 있어도 처리 인덱스가 일치합니다.
헤드 기준 틱 간격에 맞는 유효한 테일도 같은 마커로 표시하고 처리 뒤 숨깁니다.
Reset은 처리 개수를 0으로 되돌립니다.


11종 PNG(7종과 복귀용 4종)는 내장 기본 스킨 팩에 포함됩니다. 선택 스킨 INI의 `Judgements.*` 매핑이 우선하고
누락된 판정 이미지만 내장본으로 대체합니다. 그림 크기·색·교체 규칙은
[판정 글자 그림](../Assets.md#판정-글자-그림)에 있습니다.

코드 진입점은 `Client/GameScene/RhythmTestScene/Submodules`입니다.
`GameplayPresenter`가 Canvas를 소유하고 판정 표시는 `GameplayJudgementView`, 진행바는
`GameplayProgressView`에 위임합니다. 키 표시 노드의 관찰자·이미지·점멸 타이머와
생성/입력 갱신/정리는 `GameplayInputView`가 소유합니다. 노드는 같은 Canvas 아래에
같은 순서·좌표·Z로 생성되며, Presenter는 초기화와 갱신을 위임합니다.
배치는 `GameplayLayout`, 판정 문구·정확도·오류 표시는 `GameplayFeedbackVisuals`에 둡니다.
노트·롱노트 몸통과 tick·마디선·풍선/뎅뎅 처리 연출과 남은 타수 표시는 `GameplayNoteView`가
상태와 노드를 소유합니다. Presenter는 레인 루트를 만든 뒤 노트 뷰를 붙이고 레인 폭·판정
위치를 전달합니다. 노트 뷰는 레인 로컬 +Y를 미래 방향으로 쓰므로 모드는 레인 루트만
회전합니다. `GameplaySessionController`는 `Client/GameFlow`에서 시간·입력과 모드 공통
상태머신을 소유하고 오디오는 `GameplayAudioSession`에 맡기며
`GameplayFeedback`으로 표시할 이벤트만 전달합니다.
UI 수정 시 해당 표시 파일과 `GameplaySupport.h`의 관련 상수만 읽으면 됩니다.

## 표시 객체의 생성과 재사용

세션 진입 때 스킨 이미지를 등록하고 노트 모델의 비소유 ID 인덱스를 만듭니다.
노트의 head/body/HUD 표시 노드는 화면 snapshot에 처음 포함될 때 생성합니다.
롱노트 tick은 현재 보이는 시각 구간만 이진 검색하고 표시 객체를 재사용하며,
원래 tick 시각 배열과 판정 규칙은 유지합니다. 마디선도 보이는 구간의 pool만 갱신합니다.
화면에서 겹치는 틱은 `ScreenMarkThinning`으로 솎습니다. 노트 시각으로부터의 레인 거리를
Canvas 배율로 화면 픽셀로 바꾸어 2px 띠로 나누고, 띠마다 처음 보이는 틱 하나만 노드에 배치합니다.
띠의 기준이 노트에 고정되어 스크롤 중에도 같은 틱이 선택되고, 처리된 틱을 숨기는 규칙은 그대로입니다.
기준은 화면 거리뿐이며 노트 종류·모드를 보지 않습니다([PERF-01](../../Design/Decisions.md#perf-01-밀집-틱의-표시와-소리)).
화면 구간과 완료 연출을 벗어난 노드 subtree는 제거하여 지나간 노트가 누적되지 않습니다.
되돌아 탐색하면 같은 모델 ID와 등록된 이미지로 표시를 다시 생성합니다.
이미지 경로를 노트 출현 때 다시 조회하거나 파일을 다시 읽지 않습니다.
표시가 관찰하는 PlaySession은 Presenter보다 오래 살아야 하며 Shutdown에서 관찰을 해제합니다.

`Lane.Notes` 안에서는 시각이 빠른 노트가 앞에 그려집니다. 같은 시각이면 ID가 작은
노트를 앞에 두며, 헤드·몸통·테일·틱을 노트 루트와 함께 정렬합니다. 화면에 보이는
목록만 정렬하므로 Separate 속도 차이·되감기·표시 재생성에도 생성 순서에 의존하지 않습니다.
노트 레이어는 판정원 위에 두고 키빔 → 판정원 → 노트 순서로 그립니다.
판정원의 자식인 판정 글자도 같은 부모 순서를 상속합니다.

일반 롤·큰 롤(단무지)도 `DrumRollInputRule::Progress`의 실제 타격 수/요구 타격 수로
남은 타격 배지를 판정원 오른쪽 위에 표시합니다. 첫 유효 타격 후 나타나며 요구 횟수를 넘겨도
남은 수는 0으로 유지하고, 종료/실패/초기화 시 숨깁니다. 풍선·뎅뎅과 같은 카운터를
재사용하지만 롤의 헤드·몸통 이동과 판정·점수·종료 시각은 바꾸지 않습니다.

이미지 파일명은 기본본의 예시이며 실제 경로는 스킨 `[InGame]`과 씬 폴더 설정에서 해석합니다.
에디터도 같은 노트 이미지 키를 사용합니다. 자세한 계약은 [skin.ini](../Assets.md#skinini와-씬별-이미지)에 있습니다.
