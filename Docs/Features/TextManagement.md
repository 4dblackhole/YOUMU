# 문구·언어·글꼴 관리

게임의 고정 UI 문구는 UTF-8 INI로 관리하며 화면별 문구 계약과 글꼴은 `Client/Texts`가 소유합니다.
`YOUMUGame`이 하나의 `TextCatalog`를 소유하고 각 View/Presenter에 빌려주므로,
선택한 설명 언어가 곡 선택·플레이·에디터에도 이어집니다. 항목명·버튼·단위·값 형식은 영어이며,
설명·도움말·오류 안내만 영어/한국어/일본어로 변경합니다. 최초 설정은 Windows 사용자 UI 언어를
따르고 한국어/일본어 이외의 언어와 확인 불가는 영어로 시작합니다. 저장된 언어는 우선합니다.

```text
Client/Texts/
  TextCatalog.*                         언어 목록, 현재 언어, 언어별 글꼴
  Languages/en.ini, ko.ini, ja.ini      영어 UI와 세 언어 안내문의 원본
  Submodules/ExplanationKeys.h          설명·도움말·오류 안내 키의 역할 분류
  Submodules/LanguageFile.*             UTF-8 INI 파싱·자리표시자 검증
  GameIdentity.h                        언어와 무관한 제품 표시 이름
  Options/OptionTexts.*                 공통 옵션 패널
  GameScene/YOUMULogoScene/        로고 화면
  GameScene/MusicSelectScene/           플레이/에디터 곡 선택
  GameScene/RhythmTestScene/            플레이 화면
  GameScene/ResultScene/                리절트 문구·통계 축·액션
  EditorScene/                          공통 에디터 화면
    Taiko/TaikoEditorTexts.*            Taiko 도구/동·캇 이펙트 문구
```

물리 폴더와 `YOUMU.Client.vcxproj.filters`의 `Texts` 트리는 같습니다.
화면별 `*TextSet`은 INI 키를 해당 화면의 이름 있는 필드로 묶습니다.
문자열 값이나 언어 선택 분기는 이 C++ 표에 복제하지 않습니다.

## 언어파일 교체

실제로 읽는 파일은 `<자산 루트>/Languages/ko.ini`, `en.ini`, `ja.ini`입니다.
개발 실행은 `Client/Assets/Languages`, 배포는 EXE 옆 `Asset/Languages`를 사용합니다.
기존 `General/Language=ko` 또는 `en`을 보존하고 `ja`도 지원합니다. 새 필드를 만들지 않으며
이 값은 설명 언어를 선택합니다. 기본 `Get(key)`는 ExplanationKeys의 안내 키만 선택 언어로,
나머지는 영어로 읽습니다. `Get(language,key)`는 특정 원본 팩을 조회하는 명시적 API입니다.
사용자 곡/제작자/폴더/장치 이름 같은 데이터는 번역하지 않습니다. 기존 사용자 언어 파일은
덮어쓰지 않으며 해당 영어 팩과 내장 영어를 순서대로 fallback으로 사용합니다.
파일은 TextCatalog 생성 시 한 번 읽으므로 수정/교체 후 게임을 다시 실행합니다.
언어 선택 전환과 화면 그리기 중에는 파일을 다시 읽거나 디렉터리를 탐색하지 않습니다.

```ini
[Options]
offsetHint="클릭 → 숫자 입력 → Enter\n양수: 노트/효과를 음악보다 늦게 실행"
saveError="Option.ini를 저장하지 못했습니다."
```

메인·옵션·곡 선택·플레이·일시정지·리절트·공통/Taiko 에디터의 고정 라벨/도움말과
판정명·단위·성능 표시도 같은 파일에 있습니다. 섹션과 키의 대소문자는 구분합니다.
곡명·아티스트·패턴 이름, 장치/물리 키 이름, 차트/엔진에서 전달한 진단 원문은 데이터이며
번역하지 않습니다. 진단 접두사/일반 UI 안내는 언어파일이 소유합니다.
게임 제품명은 아래 GameIdentity 계약을 따르고, PNG에 그려진 글자는 스킨 자산입니다.

누락/잘못된 항목은 **선택 언어 파일 → 외부 en.ini → 실행 파일의 영어 기본 문구** 순서로
찾습니다. 한국어 C++ 상수로 돌아가는 경로는 없습니다. 영어 기본 문구는 원본
`Client/Texts/Languages/en.ini`에서 빌드 시 생성해 EXE에 포함하므로 외부 파일이 없어도 유지됩니다.
빌드는 원본 en/ko/ja를 개발 폴더에 처음 한 번 복사하고 이미 존재하는 편집본은 덮어쓰지 않습니다.
새 번역 기본본을 배포할 때는 원하는 INI를 배포 폴더의 `Asset/Languages`에 직접 넣습니다.

INI는 UTF-8(BOM 선택), LF/CRLF를 지원합니다. 빈 줄과 `;`/`#`로 시작하는 주석을 허용하고,
값 안의 `;`/`#`는 주석으로 자르지 않습니다. 따옴표 없는 값은 양끝 공백을 제거합니다.
따옴표 값은 공백을 보존하며 `\n`, `\r`, `\t`, `\\`, `\"` 이스케이프를 지원합니다.
빈 값은 명시적으로 빈 문구를 뜻합니다. 중복 키는 처음 값을 보존하고 뒤의 중복을 무시합니다.
잘못된 UTF-8/NUL은 해당 파일을, 잘못된 구문/이스케이프는 해당 항목만 무시합니다.
알 수 없는 키와 형식 오류는 디버그 출력에 남기고 게임 시작을 막지 않습니다.

서식 문구는 영어 기본본의 인수 개수와 서식 지정자를 유지해야 합니다.
`{}`를 `{0}`, `{1}` 등으로 바꾸어 순서를 바꿀 수 있지만 자동/명시 인덱스는 섞지 않습니다.
`{:.1f}` 같은 정밀도/타입을 바꾸거나 인수를 누락/추가한 항목은 로딩 때 제외합니다.
이는 잘못된 번역으로 플레이 중 format_error가 발생하거나 수치 정밀도가 바뀌는 것을 막습니다.
정확도(`99.99%`)는 언어 파일의 서식을 쓰지 않고 `Presentation/AccuracyText.h`가 모든 화면에 같은 형식으로 만듭니다.
문자 자체의 중괄호는 `{{`, `}}`로 적습니다.

TextCatalog가 읽은 문자열은 실행 중 불변이며 화면은 해당 소유자의 참조를 받습니다.
화면별 표의 string_view와 에디터 콜백은 그 소유자보다 오래 살아서는 안 됩니다.
카탈로그의 복사/이동을 허용하지 않으며 View/Scene은 같은 게임 수명의 카탈로그를 공유합니다.

## 게임 이름 변경

`Client/Texts/GameIdentity.props`의 `GameDisplayName`이 제품 표시 이름의 유일한 원본입니다.
현재 이름은 `Y's Orchestral Unison: Melodic Ultimatum`입니다.
빌드는 `GenerateGameIdentity.ps1`로 `GameIdentity.h`의 전역 UTF-16 `GameName`을 생성하며,
게임 창·시작 오류창·에디터 확인창이 같은 값을 사용합니다. 생성 헤더는 직접 수정하지 않습니다.
EXE TargetName도 같은 속성에서 계산하며 Windows 파일명에 사용할 수 없는 콜론은
` -`로 바꿉니다. Debug/Release 결과는 `Y's Orchestral Unison - Melodic Ultimatum.exe`입니다.
코드/프로젝트/Scene ID·자산 캐시의 제품 식별자는 YOUMU이며 표시 이름 변경과 별도로 관리합니다.
에디터 확인창은 같은 이름에 언어별 editorTitleSuffix를 붙입니다.

## 언어와 글꼴 추가

`TextCatalog.cpp`의 `LanguageProfile`은 언어 이름과 `TextFont`를 한 쌍으로
관리합니다. 현재 세 언어는 Windows의 `Segoe UI`와 시스템 글꼴 fallback을 사용합니다. 시스템
글꼴은 `TextFontSource::System`, 배포 글꼴 파일은 `TextFontSource::File`로
지정할 수 있습니다. 파일 글꼴을 배포할 때는 글꼴 파일 옆에 라이선스를 함께 둡니다.
리절트는 Penpot 지정 글꼴인 내장 Noto Sans KR을 별도로 사용합니다.
경로는 `Client/App/AssetPaths.h`의 `NotoSansKR()`, 굵기·크기는 TaikoResultView의 Label/Button 호출에서
정하며 두 언어에 같은 글꼴을 적용합니다. 파일·라이선스는 [BuiltInAssets](Assets.md)에 있습니다.

언어를 추가할 때는 다음을 함께 변경합니다.

1. 현재 설명 언어는 한국어/영어/일본어입니다. 새 언어 지원 시 `Language`, 파일/프로필 목록과
   Option.ini의 언어 코드 매핑을 함께 추가합니다.
2. 해당 언어 INI를 작성합니다. 빠진 키는 영어를 사용합니다. 화면별 C++ 언어 표는 추가하지 않습니다.
3. `TextCatalog::SetLanguage` 뒤 revision을 보는 View가 표시 문구와 글꼴을
   다시 적용하는지 확인합니다.

런타임 진단은 종류와 원문을 상태에 보관하고 View에서 현재 언어의 접두사와
조합합니다. 따라서 언어를 바꾸면 이미 표시 중인 오류 제목도 함께 갱신됩니다.

## 렌더링 수명

TextCatalog는 문구와 글꼴 선택을 소유하고, 엔진 TextVisual/ComboBox는 공유
`TextContent` payload를 게시합니다. 문자열·글꼴·굵기·크기·정렬이 바뀔 때 payload를
교체하며 색상·위치·clip 변경에는 같은 payload를 유지합니다. D3D12 renderer가
글꼴과 배치 handle을 유지하므로 Client에 DirectWrite 객체나 아틀라스 UV를 저장하지 않습니다.
직접 DrawPacket을 만드는 에디터도 `packet.text`에 이 payload를 전달합니다.
자세한 배치·측정·아틀라스 수명은
[엔진 텍스트 계약](../../Dependencies/PhantomCore/Docs/TextRendering.md)에 있습니다.
긴 제목은 원본 Unicode와 같은 payload를 유지하고 실제 측정 폭이 영역을 넘을 때만
픽셀 단위로 순환합니다. 스크롤 단계마다 문자열이나 글리프 배치를 다시 만들지 않습니다.

## 옵션 패널

UI-02 리디자인([UI-02](../Design/Decisions.md#ui-02-ui-리디자인), [옵션 패널](../Design/UI.md#옵션-패널))이 현재 계약입니다.
`Client/Presentation/OptionsPanel.*`은 로고와 곡 선택 View가 조립하는 공통 Visual2D 서랍입니다.

- 로고의 `옵션` 버튼, 곡 선택 하단 띠의 톱니 버튼 또는 두 화면의 `Ctrl+O`로 열고 닫습니다.
  열린 서랍은 머리의 닫기(✕)나 `ESC`로도 닫습니다. 마우스가 밖에 있어도 처리하고 펼친 드롭다운·드래그 상태를
  정리합니다. 닫는 프레임의 ESC는 뒤 화면에 전달하지 않습니다. 선택은 모두 즉시 적용·저장하므로 확인 버튼이 없습니다.
  선택 칸은 공용 [드롭다운](#드롭다운)입니다.
- 1280×720 논리 화면에서 폭 432, 높이 720이며 왼쪽 밖에서 0.2초 동안 smoothstep으로 들어옵니다.
  왼쪽 폭 64는 남색 분류 막대(General·Display·Audio·Input 아이콘), 오른쪽 폭 368은 제목 `Options`와 본문입니다.
- 본문은 탭 전환 대신 네 섹션이 이어진 한 줄입니다. 분류를 누르면 그 섹션의 머리를 본문 맨 위로 스크롤하고,
  직접 스크롤하면 맨 위에 걸린 섹션(끝까지 내리면 마지막 섹션)의 분류가 켜집니다. 켜진 분류는 금빛 왼쪽 줄입니다.
  분류를 누른 뒤에는 손으로 스크롤할 때까지 그 분류가 켜져 있습니다. 서랍이 열려 있으면 `↑`/`↓`가 분류를 옮깁니다.
- 분류 막대에 마우스를 0.3초 올리거나 `↑`/`↓`로 옮기면 막대가 폭 184로 펼쳐져 분류 이름을 보이고 본문을 덮습니다.
  펼친 막대 밖으로 나가거나 키보드로 펼친 뒤 마우스를 움직이면 바로 접힙니다.
- 본문 안에서 휠, 공용 [스크롤바](#스크롤바), 가운데 버튼 드래그, 빈 영역의 왼쪽 버튼 드래그로 스크롤합니다.
  스크롤 위치와 켜진 분류는 같은 View에서 다시 열 때 유지하며 INI에는 저장하지 않습니다.
  분류를 옮기면 펼친 드롭다운과 입력 대기를 정리합니다.
- 섹션: General(설명 언어·Songs 폴더), Display(스킨·해상도·`Song text`·키빔 불투명도·배경 밝기), Audio(전체·음악·효과음 음량, 미들웨어·출력 방식·드라이버,
  글로벌 오프셋), Input(재시작 키, 모드별 키 설정 카드). 항목명은 칸 위의 작은 글자이고 입력칸은 흰 바탕과 아래 2px 줄입니다.
  설명 문단은 두지 않습니다.
- 오류·설정 복구 안내는 본문 밖 아래 칸에 왼쪽 색 띠·아이콘과 함께 두며 본문과 같은 clip을 쓰지 않습니다.
  저장·적용 실패는 빨강, 출력 방식 대체·드라이버 없음·Option.ini 읽기 경고는 금빛 갈색입니다. 안내가 없으면 칸도 없습니다.
- 모션 속도 설정은 사용자 지시로 폐기했습니다. 속도 필드·단계 선택·직접 입력을 추가하지 않습니다.
- 현재 설치된 미들웨어는 FMOD 하나이며 출력 방식은 일반(자동)·WASAPI·ASIO입니다.
  드라이버 목록은 현재 출력 방식이 제공한 실제 장치와 번호만 표시합니다.
- 출력 방식·드라이버는 같은 AudioSystem에서 즉시 바꾸고 목록을 갱신합니다.
  현재 제공하는 선택에는 게임 재시작이 필요하지 않습니다. 실패 시 기존 선택을
  유지하거나 복원하고 서랍 아래 칸에 안내를 표시합니다. 사용할 장치가 없으면
  드라이버 선택을 비활성화합니다.
- 언어 선택은 즉시 활성 화면의 문구를 다시 그리고, 스킨 선택은
  외부 자산 루트의 `Skins` 폴더 이름을 저장합니다. 스킨 자산의
  경로와 파일별 기본본 대체 규칙은 [BuiltInAssets](Assets.md)에 있습니다.
- Songs 폴더는 경로 상자와 `Browse…`(둘 다 OS 폴더 선택 창), 그 아래 `Use default folder` 글자 버튼입니다.

### 음량

Audio 섹션 맨 위의 `Master volume`·`Music volume`·`Effects volume`은 0–100% 막대입니다. 세 막대는 각각 한 줄(높이 36)에
항목명·막대·백분율을 나란히 두어 세로 공간을 줄입니다(사용자 결정). 다른 칸처럼 항목명이 위에 따로 놓이지 않습니다.
막대를 누르거나 끄는 동안 값이 바뀌어 보이고, 버튼을 놓을 때 한 번 저장합니다. 저장에 실패하면 저장된 값으로 돌아가고
아래 칸에 오류를 표시합니다. 배율은 백분율에 비례하며 전체 음량이 두 값을 함께 줄입니다(전체 50%·음악 50% → 음악 0.25배).

- 음악: 플레이 음원(`Music` bus), 곡 선택 미리듣기와 타이틀 음악 플레이어, 에디터의 곡.
  미리듣기·타이틀 플레이어는 저장 즉시 따라가고 페이드에도 같은 배율을 곱합니다.
- 효과음: 그 밖의 모든 bus(HitSound·TickSound·UserInputFeedback·UI)와 에디터의 히트사운드·메트로놈.
  YME `#Volume` 자동화는 이 배율 위에 곱합니다([Audio](Gameplay/Audio.md#실시간-오디오-효과)).
- 플레이·에디터·리트라이는 진입 당시 값을 실행 요청에 복사해 씁니다. 엔진에 전체 출력 음량이 없고 상주 bus는
  출력 방식 전환을 막으므로 각 재생 경로가 자기 음량에 배율을 곱합니다.

### 키 설정

모드별 키 설정 참고 구조는 osu!lazer의
[RulesetBindingsSection](https://github.com/ppy/osu/blob/master/osu.Game/Overlays/Settings/Sections/Input/RulesetBindingsSection.cs)과
[VariantBindingsSubsection](https://github.com/ppy/osu/blob/master/osu.Game/Overlays/Settings/Sections/Input/VariantBindingsSubsection.cs)입니다.
모드/variant 단위로 모드가 제공한 입력과 기본 binding을 씁니다.
키 편집 형태는 [모드 표현 등록부](../../Client/Presentation/ModePresentation.cpp)가 정합니다. 키 오버레이를
등록한 모드는 Input 섹션의 카드 하나(모드 이름 위, 안에 `Key settings`와 메인 키 · 첫 보조 키 요약)로 오버레이를 열고,
등록하지 않은 모드는 Input 섹션에 바인딩·칸마다 한 줄을 둡니다.

- 키 설정 창은 화면 가운데 폭 432이며 화면 전체를 남색 반투명 막으로 덮습니다. 막과 창은 옵션 서랍보다 앞에 그리고
  hit-test도 앞섭니다. 창이 열려 있는 동안에는 창 안의 노드만 동작을 받습니다.
- 열은 레이아웃의 바인딩 순서입니다. 열 머리는 등록부가 가리키는 Gameplay 입력 패널의 키 그림을 높이 24로 줄여
  입력 패널과 같은 위아래 차이로 둡니다(Taiko는 캇이 위, 동이 아래). Main/Sub 글자와 열 제목 문구는 없습니다.
- 각 열의 첫 칸은 큰 메인 키, 아래 세 칸은 각각 비울 수 있는 보조 키입니다. 빈 칸(미지정)은 흐린 `+`이고, 보조 키를 비우는 ×는
  그 칸에 마우스를 올렸을 때만 보입니다. 입력 대기 칸은 코발트 테두리와 `···`입니다.
- 안내는 입력 대기(`Press a new key · Esc to cancel`)와 거부된 키의 오류일 때만 창 아래에 붙여 둡니다.
- 초기 메인 키는 D/C/M/K, 첫 보조 키는 F/V/N/J입니다(열 순서: 왼쪽 캇·왼쪽 동·오른쪽 동·오른쪽 캇). 키 칸을 선택하고 새 키를 누르면 저장합니다.
  같은 모드의 다른 칸이 이미 쓰는 키를 지정하면 그 칸(메인 키 포함)은 미지정이 되고 새 칸에 키가 들어갑니다.
  미지정 칸은 입력을 받지 않으며, 모든 칸이 미지정인 열은 입력이 없습니다. 이 규칙은 키 편집의 공통 동작이라 모드별 처리가 없습니다.
  게임 제어 ESC/Space/F7은 예약하며, 재시작 키(기본 `` ` `` 백틱)도 연주 키로 쓸 수 없습니다. ESC는 키 지정 대기를
  취소하거나 키 설정 창을 닫습니다. 사용자 입력은 단일 Win32 Virtual-Key이며 키 조합/마우스 binding과
  런타임 DLL 모드 로더는 구현되어 있지 않습니다.

Input 섹션 맨 위의 재시작 키 칸은 플레이 중 0.5초 길게 누르면 시도를 처음부터 다시 하는 키입니다.
칸을 누르고 새 키를 누르면 바로 저장합니다. 설치된 모드의 연주 키(기본값·변경값)와 ESC/Space/F7은 거부하고
입력 대기를 유지하며, ESC는 대기를 취소합니다. 플레이는 진입 때의 재시작 키를 시작 요청에 복사해 씁니다.

`IPlayGameMode::InputLayout`은 stable mode/binding ID, 표시 이름, semantic action,
기본·보조 physical key 목록을 제공합니다. PlayGameModeFactory의 실제 지원 모드 목록으로
옵션 행을 구성하고 ResolveInputLayout이 기본값과 저장한 변경값을 검증합니다.
PlaySession이 해결된 목록을 소유하며 판정·held·키 불빛·입력 기록에 같은 매핑을 사용합니다.
빈 칸(메인 키 포함) 허용 같은 키 정책은 레이아웃의 `allowUnassignedKeys`로 모드가 선언합니다.
허용하지 않는 레이아웃에서는 키를 옮기면 옛 칸을 비울 수 없으므로 저장이 거부됩니다.
새 모드를 연결하는 전체 절차는 [게임 모드 추가](../Contributing/AddingGameMode.md)를 따릅니다.

### 해상도·오프셋과 책임

해상도 목록은 현재 모니터가 지원하는 실제 픽셀 크기와 현재 창 크기를 표시합니다.
선택 즉시 client 영역 크기를 변경하고 저장하며 다음 실행의 EngineConfig에도 사용합니다.
저장이 실패하면 이전 창 크기 복원을 시도합니다. 엔진의 비소유 WindowControl 서비스가 없는
offscreen context에서는 선택을 비활성화합니다. GPU 한도에 따라 각 치수는 1~16,384px입니다.

글로벌 오프셋은 짧은 숫자 상자와 `ms` 단위입니다. 클릭 → 정수 ms 입력 → Enter로 적용합니다. 숫자키/숫자패드,
음수 부호, Backspace/Delete를 사용할 수 있습니다. ESC는 저장하지 않고 서랍을 닫습니다.
+100ms는 음원에 비해 노트·틱·마디선·BPM·YME 지점/영역 끝점을 100ms 늦춥니다.
음원 시작은 여전히 차트 타이머 0ms이며 효과 보간의 구간 길이는 유지합니다.
설정은 다음 플레이/에디터 진입 Snapshot에서 사용합니다. MusicalTimeline의 실행용 정수 us
오프셋으로 컴파일하고 원본 YMP/YME·Pattern Offset은 수정하지 않습니다.
에디터 Copy/Replace/타이밍 수정/저장에도 이 분리를 유지합니다.
패턴마다 따로 두는 개별 오프셋(플레이 중 +/- 키)은 글로벌 오프셋에 더해 컴파일됩니다([개별 오프셋](Gameplay/Audio.md#개별-오프셋)).

OptionsPanel은 Canvas/스크롤/키보드 소유권과 서랍 틀·안내 칸을 맡고, Submodules의 OptionsRail(분류 막대·섹션 배치·스크롤),
OptionsVolume, OptionsDisplay, OptionsSongs, OptionsOffset, OptionsKeys(키 카드·키 설정 창)가 각 표시·적용 함수를 나눕니다.
OptionsPanelStyle은 서랍 치수·색과 글자 모양을 모읍니다. OptionSettings는 지속 값의
검증/원자적 저장을 맡으며 창·오디오 핸들은 소유하지 않습니다.
서랍 바탕·분류 막대·분류 버튼·키 카드·키 칸은 스킨 `[Options]` 그림이고 아이콘은 `[Common]`의 `Icons.*`입니다
([BuiltInAssets](Assets.md)).

## 툴팁

`Client/Presentation/UiTooltip.*`은 UI-02 공용 툴팁입니다([UI 리디자인](../Design/UI.md#공용-부품)). 화면(View)마다 하나를
Canvas 위 가장 높은 Z 순서로 두고, 컨트롤에 이름·옅은 보조 글자·단축키를 등록합니다.

- 진한 남색 면에 흰 글자(13px), 컨트롤 아래 8px에 놓고 아래 공간이 없으면 위로 엽니다. 화살표는 컨트롤 가운데를 가리킵니다.
  면의 폭은 최대 300이며, 단축키·보조 글자 없이 이름만 있는 긴 툴팁(긴 곡명 등)은 그 폭에서 여러 줄로 나눕니다.
- 단축키는 이름 오른쪽의 글자 칩입니다. `Ctrl+O`는 `+`로 이은 칩 두 개, `Esc / Enter`는 `/`로 나눈 대안, 키만 있으면 칩만 둡니다.
- 등록한 컨트롤(또는 그 안의 자식)에 포인터가 0.5초 머물면 나타나고, 사라진 지 0.3초 안에 다른 컨트롤로 옮기면 곧바로 바뀝니다.
  누르기·휠·키 입력에 사라지며 포인터가 다른 컨트롤로 옮길 때까지 다시 나타나지 않습니다. 화면 전환과 팝업·서랍·덧붙임 메뉴가
  덮은 동안에도 숨깁니다. 키보드 포커스 그림이 없어 키보드 포커스로는 나타나지 않습니다.
- 툴팁 이름은 항목명이라 영어이며 `[Tooltips]` 문구 키에서 읽습니다. 단축키 이름은 바꾸지 않습니다.
- 포인터를 받지 않는 컨트롤 안의 한 줄(곡 카드의 곡명·아티스트)도 줄 힌트로 등록할 수 있습니다. 포인터가 그 줄 위에 있고
  포인터 아래 컨트롤이 그 줄을 품고 있을 때만 나타나므로, 카드를 누르는 동작과 카드 위의 다른 컨트롤(난이도 행)은 그대로입니다.
- 지금 쓰는 곳: 곡 선택의 Back(`Esc`)·GO(`Enter`)·게임 모드·옵션 톱니(`Options`, `Ctrl+O`)·기록 필터·즐겨찾기 폴더 관리와
  곡명·아티스트·채보 제작자(등록한 모든 이름을 ` · `로 이음), 곡 목록 카드의 곡명·아티스트(이름이 여러 개이거나 줄에서 잘릴 때만,
  모든 이름 또는 잘린 전체 이름), 타이틀 음악 플레이어의 재생/일시정지(`Space`)·정지·다음 곡(`→`),
  옵션 서랍의 분류 버튼(접혀 있을 때)과 닫기(`Esc`), 결과 화면의 Back(`Esc / Enter`)·점수(`Score`)·옵션 칩(`Applied options`)·
  채보 제작자(`Chart by`). 결과 화면은 크기·문구가 바뀌어 내용을 다시 만들 때 힌트를 지우고 다시 등록합니다.
  검색칸은 Windows 편집기가 덮어 툴팁을 두지 않습니다.

## 드롭다운

`Client/Presentation/UiDropdown.*`은 UI-02 공용 드롭다운이며 게임 화면의 엔진 ComboBox를 모두 대신합니다
(옵션 서랍의 여섯 칸, 곡 선택의 기록 종류·정렬·게임 모드, 곡 필터의 모드, Play options의 HP gauge).

- 상자는 값과 오른쪽의 꺾쇠 화살표입니다. 바탕과 밑줄은 쓰는 화면이 정하고, 값 글자는 기본 14px 세미볼드 잉크이며
  화면마다 크기·굵기·색을 정할 수 있습니다. 항목이 없으면 흐린 `No items`이고 꺼진 상자는 열리지 않습니다.
- 상자를 누르면 펼친 목록이 Canvas 맨 위 층에 그려져 서랍 본문 같은 부모의 clip에 잘리지 않습니다. 흰 면에 위 3px 코발트 선,
  항목 34px(위아래 여백 4)이고 8개 반이 보인 뒤 휠이나 오른쪽의 공용 [스크롤바](#스크롤바)로 스크롤합니다(항목은 스크롤바 폭만큼 좁아집니다). 고른 항목은 체크와 굵은 코발트, 포인터가 가리키는 항목은
  옅은 코발트 면과 왼쪽 3px 선입니다. 아래 공간이 없으면 위로 열고 선도 아래로 옮깁니다. 목록 폭은 상자 이상, 360 이하입니다.
- 항목을 누르면 상자 노드의 `SelectionChanged` 동작이 나가 기존 엔진 ComboBox와 같은 경로로 처리됩니다.
- 목록 밖을 누르거나 휠을 굴리면 고르지 않고 닫히며, 그 누르기는 아래 컨트롤에 전달하지 않습니다.
  옵션 서랍은 드롭다운이 펼쳐진 동안 본문을 휠로 스크롤하지 않으므로, 목록 위의 휠은 목록만 움직입니다.
  목록이 열린 동안 키 입력은 뒤 화면으로 가지 않고 `Esc`·`Tab`이 목록만 닫습니다(곡 선택·타이틀이 먼저 확인합니다).
- 꺾쇠와 체크는 그림 없이 짧은 막대 두 개로 그려 스킨이 필요 없습니다. 시안의 `Common/Input` 드롭다운 PNG는 상자 폭이
  화면마다 달라 쓰지 않습니다.
- 게임에는 키보드 포커스가 없어 키보드로 상자를 열지 못하고, 열린 목록 안의 ↑↓·Home·End·PgUp·PgDn·글자 찾기·Enter 고르기도
  아직 없습니다(포커스 체계와 함께 구현).

## 스크롤바

`Client/Presentation/UiScrollbar.*`은 UI-02 공용 스크롤바입니다([UI 리디자인](../Design/UI.md#공용-부품)). 곡 목록,
옵션 서랍 본문, 즐겨찾기 폴더 탭(가로), 드롭다운의 펼친 목록이 같은 부품을 씁니다. 스크롤 위치는 쓰는 화면이 갖고,
스크롤바는 범위를 받아 그리고 끌기·레일 누르기가 요청한 위치를 돌려줍니다.

- 세로는 잡는 폭 12, 그 가운데 6의 막대와 같은 폭의 옅은 레일(코발트 7%)입니다. 막대는 평평한 코발트 42%이고
  포인터를 올리면 62%, 누르는 동안 100%입니다. 화살표와 둥근 끝은 없습니다. 가로는 높이 8에 막대 4입니다.
- 막대 길이는 보이는 비율만큼이며 최소 32(가로는 같은 비율로 줄임)입니다. 스크롤할 것이 없으면 레일과 막대를 모두 숨깁니다.
- 막대를 누르면 누른 자리를 유지한 채 끌고, 레일을 누르면 막대 가운데가 그 자리로 와서 계속 따라갑니다.
  끄는 동안 포인터가 스크롤바나 그 화면의 영역을 벗어나도 계속 따라가며, 버튼을 떼면 끝납니다.
- 매 프레임 포인터를 넘기는 화면(곡 목록·폴더 탭·옵션 서랍)과, 매 프레임 입력을 받지 않는 부품(드롭다운 목록)이
  스크롤바 자신의 포인터 이벤트로 끌기와 휠을 받는 방식 두 가지를 지원합니다.
- 그림 없이 색으로 그려 스킨이 필요 없습니다. 예전 곡 목록의 `ScrollbarTrack`·`ScrollbarHandle` 스킨 그림은 없앴습니다.
- Play options 등 아직 스크롤바를 두지 않은 팝업은 휠로만 스크롤합니다.

## 경고 대화상자

`Client/Presentation/UiAlert.*`은 UI-02 공용 경고·오류 대화상자입니다. 쓰는 화면의 Canvas 맨 위 층(펼친 드롭다운보다 위)에 그립니다.

- 폭 480의 흰 면을 화면 가운데, 남색 막(42%) 위에 둡니다. 위 4px 띠와 아이콘 색이 심각도입니다(오류 빨강, 주의 금빛이며
  아이콘은 대비를 위해 진한 금, 알림 코발트). 아이콘은 스킨의 `Icons.alert`(알림은 `Icons.info`)입니다.
- 제목(22px 굵게)과 버튼 이름은 영어, 설명(15px)은 선택 언어이며 폭 384에서 줄을 바꿉니다. 원문 진단(경로·오류)은
  Consolas 12px로 옅은 코발트 상자에 심각도 색 왼쪽 선과 함께 두고, 상자가 120px를 넘으면 그 안에서 휠로 스크롤합니다.
  엔진 글자는 고를 수 없으므로 `Ctrl+C`가 진단 전체(진단이 없으면 설명)를 클립보드에 복사합니다.
- 버튼은 높이 40으로 가는 선 아래에 놓입니다. 주 버튼은 오른쪽 끝의 코발트 평행사변형이고 Enter가 고릅니다.
  나머지는 흰 면에 아래 2px 선이며, 되돌릴 수 없는 동작(Discard 등)은 빨간 글자로 왼쪽 끝에 떨어뜨립니다.
  Esc는 취소 버튼(버튼이 하나면 그 버튼)을 고릅니다. 대화상자를 연 프레임의 키는 답으로 쓰지 않습니다.
- 막을 눌러도 닫히지 않고 아래 컨트롤에도 가지 않습니다. 열린 동안 화면은 자기 입력을 처리하지 않습니다
  (결과 화면은 애니메이션만 이어 갑니다). 곡 선택은 대화상자를 열 때 글 입력칸이 있는 창(필터·즐겨찾기·기록 필터·
  플레이 옵션)을 적용하지 않고 닫고, 열린 동안 Windows 검색 입력칸을 숨깁니다.
- 쓰는 곳: 결과 화면의 기록 저장 실패(Close·Retry, [Results](Gameplay/Results.md#화면-배치와-책임-경계)),
  에디터 곡 선택의 osu! 가져오기 실패(OK), 에디터의 미저장 확인(Discard·Cancel·Save)·저장/Create 실패·붙여넣기 실패(Close,
  [차트 에디터](ChartEditor.md#입력칸과-대화상자)). 에디터는 열린 동안 화면 위 입력칸을 그리기만 합니다. 입력칸 하나의 잘못은
  상태 문구로 알리고, osu! 가져오기 완료 안내는 없습니다. 시작 실패는 게임 창이 없으므로 Windows 메시지 상자로 남깁니다.
- 시안과 다른 점: 면 그림자와 주 버튼의 빗금 무늬가 없고, 진단 글은 마우스로 고를 수 없어 `Ctrl+C`로 복사합니다.

## 공통 UI 색상

`Client/Presentation/UiColors.h`는 로고·곡 선택·에디터·Result·일시정지·옵션의
공통 색상 값을 소유합니다. 각 화면의 Layout/Style은 그 색상을 자신의 표시 역할에
연결합니다. 공통 팔레트의 RGB/흰색/강조색은 한 곳에서 수정합니다.
Scene마다 필요한 색상군과 alpha 차이는 이름으로 구분하여 기존 디자인 값을 보존합니다.

옵션 서랍은 리디자인 팔레트(`theme`)를 씁니다. 바탕은 불투명한 `#F3F8FE`, 분류 막대는 `BrandDeep`,
입력칸은 흰색 0.74와 아래 `#B5CFF5` 줄, 글자는 `Ink`, 켜진 분류는 `Sun` 줄입니다. 서랍 고유 값은 OptionsPanelStyle에 둡니다.
노트 종류·판정 구간/키빔의 의미 색은 기존 게임플레이 표시 정책이 소유합니다.

## Option.ini

`YOUMUGame`이 `App/OptionSettings`를 소유하고 로고/곡 선택 패널에 빌려줍니다.
이 클래스는 파일 읽기·쓰기와 저장한 값만 담당합니다. `OptionsPanel`이 기존 엔진
API에 선택을 전달하며 별도 옵션 Controller나 새로운 오디오 미들웨어는 추가하지 않습니다.

EXE와 같은 폴더에 `Option.ini`가 없으면 처음 실행할 때 생성합니다. UTF-8 형식이며
`;`/`#`로 시작하는 주석과 UTF-8 BOM을 읽습니다. 다음은 키와 예시이며 Language의 첫 실행 값은 ko/ja/en입니다.

```ini
[General]
Language=ko
SkinSet=Default Skin
GlobalOffsetMs=0
SongsPath=

[Display]
Width=1280
Height=720
Notation=first
KeyBeamOpacity=100
BackgroundBrightness=100

[Keys.Taiko]
LeftKat=68,70
LeftDon=67,86
RightDon=77,78
RightKat=75,74

[Audio]
Middleware=FMOD
Output=Automatic
DriverIndex=-1
DriverName=
MasterVolume=100
MusicVolume=100
EffectsVolume=100

[Controls]
RestartKey=192
```

- `Language`: 설명 언어 `ko`, `en`, `ja`. 항목명·버튼은 영어를 사용합니다.
- `GlobalOffsetMs`: signed int32 정수 ms, 기본 0. 옵션의 오프셋 칸은 눌러서 키보드로 입력하거나, 누른 채 좌우로 끌어
  바꿉니다(4px 넘게 움직이면 끌기, Canvas 1px = 1ms, 놓을 때 저장하며 그 클릭은 키보드 입력을 시작하지 않음).
- `SongsPath`: UTF-8 곡 폴더 경로. 빈 값은 기존 개발/배포 자동 경로이며,
  상대경로는 EXE 폴더 기준입니다. 옵션 패널의 폴더 선택 버튼으로 변경하고 기본 폴더 버튼으로
  초기화합니다. 저장 성공 뒤 곡 목록을 비동기 갱신하고, 진행 중인 구 폴더 검색 결과는 버립니다.
  플레이·에디터·리트라이는 진입 당시의 곡 루트를 복사하여 사용합니다.
- `Display/Width,Height`: 게임 화면 픽셀 크기. 누락 시 1280×720.
- `Display/KeyBeamOpacity`: 모든 모드의 키빔 불투명도, 0~100 정수 %. 누락 시 100(기존 모습). 범위 밖은 오류입니다.
- `Display/BackgroundBrightness`: 플레이·로딩 화면 배경의 밝기, 0(검정)~100(그림 그대로) 정수 %. osu!의 background dim과 같은 기능입니다
  (사용자 지시). 누락 시 100(기존 모습). 범위 밖은 오류입니다.
  옵션의 슬라이더는 음량과 같은 모양이며 놓을 때 저장합니다.
- `Controls/RestartKey`: 0.5초 길게 눌러 재시작하는 키의 십진 Virtual-Key. 누락 시 192(백틱).
  설치된 모드의 연주 키나 ESC/Space/F7이면 오류입니다.
- `Keys.<mode ID>`: binding ID별 십진 Virtual-Key 목록. 첫 값은 기본 키, 이후는 보조 키입니다.
  목록을 저장하지 않은 입력은 모드의 기본값을 사용하며 변경한 행만 기록합니다.
  Taiko의 빈 칸(메인 키 포함)은 0으로 저장하며 기존 두 키 설정은 나머지 칸을 비운 채 읽습니다.
  현재 설치되지 않은 모드의 유효한 키 설정도 저장/읽기에서 보존합니다.
  설치된 모드의 알 수 없는 binding/개수·키 충돌·예약 키는 오류입니다.
  위 예시는 기본 Taiko 값이며 실제 최초 파일에는 Keys 섹션을 만들지 않습니다.
- `Middleware`: 현재는 `FMOD`만 사용 가능합니다.
- `Output`: `Automatic`, `WASAPI`, `ASIO`.
- `DriverIndex`: 엔진이 보고한 0부터 시작하는 장치 번호. `-1`은 기본 장치입니다.
  패널의 행 번호와 드라이버 번호가 같다고 가정하지 않습니다.
- `DriverName`: 선택 시 함께 저장합니다. 다음 실행에 장치 번호가 바뀌었으면 이름으로
  찾아 복원하며, 장치가 사라지면 기본 장치를 유지합니다. 다른 출력 방식으로 fallback한
  경우에는 이전 방식의 드라이버 번호/이름을 적용하지 않습니다.
  번호만 직접 지정하려면 `DriverName`을 비워둡니다.
- `MasterVolume`, `MusicVolume`, `EffectsVolume`: 0–100 정수 백분율, 기본 100. 범위를 벗어나면 읽기 오류로
  기본 설정과 경고를 씁니다. 적용 범위는 [음량](#음량)입니다.

선택이 성공하면 임시 파일을 기록한 뒤 기존 파일을 원자적으로 교체합니다.
쓰기 실패는 기존 저장 값과 언어를 보존하고 변경한 오디오 선택의 복구를 시도합니다.
장치 문제로 복구도 실패하면 그 오류를 함께 표시합니다.
잘못된 값/미설치 미들웨어, 읽기 오류 또는 최초 파일 생성 실패는 기본 설정으로
복구하여 실행을 계속합니다. 원본 INI는 임의로 덮어쓰지 않으며 옵션 패널에 원인과
기본값 사용 경고를 표시합니다. 이후 사용자의 설정 저장이 성공하면 경고를 지웁니다.
설정은 Option.ini만 사용하며 최초 생성에는 위 기본값을 사용합니다.
